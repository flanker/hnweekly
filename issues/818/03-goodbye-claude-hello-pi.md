## 文章摘要

Caleb 解释自己为什么不再把 Claude Code 作为主要编码代理界面，而转用 Pi。这里更换的是承载模型的开发工具和工作流，不等于宣布某个模型失去编码能力。文章最初发表于九月，本期抓取版本标注十一月更新；它记录了作者经历过的限制，不能保证每项抱怨仍适用于今天所有版本。

作者最在意的是审查代码时的摩擦：终端会话与编辑器选区的连接受到限制，图形扩展虽然支持多个标签页，却在命令、状态栏和并行代理输出的呈现上不符合他的习惯。他也不喜欢仓库指令文件格式分裂、频繁发布带来的行为变化，以及自己用不到的功能不断增加。对系统提示和工具说明长度的批评，重点是希望代理环境更可预测、更容易自行调整，而不是证明短提示必然产生更好结果。

转向 Pi 后，作者称自己喜欢其简约、稳定和扩展能力，并编写了适配个人需要的扩展。他承认早期产品面对的是新领域，后来者拥有观察前人经验的优势。这使文章更像一份需求清单：谁愿意维护扩展，谁需要完整的默认安全和审阅功能，谁重视图形界面，都可能得出不同选择。本期未安装或对比测试两种工具，也未逐项复现文章列出的缺陷；评论区同时存在成功迁移经验与压缩上下文、权限防护方面的担忧。
