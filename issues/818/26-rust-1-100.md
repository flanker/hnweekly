## 文章摘要

Rust 1.100 的发布把多个长期演进的能力带入稳定版。never 类型「!」可以出现在更多类型位置，例如表达不可能出现错误的结果；Infallible 也随之调整。值得升级者注意的是，旧版 edition 的 never 类型回退行为也有变化，过去依赖回退到单元类型的代码可能需要显式标注。发布说明中的兼容性提示，比单看版本号和新增 API 更值得纳入升级检查。

内存管理方面，Allocator trait 进入 core，Vec 和 Box 可使用自定义分配器，但不意味着所有标准集合都已经获得同等支持。DropGuard 用闭包表达离开作用域时的清理逻辑，并可在成功路径解除，适合组织回滚等操作；它仍受 Rust 析构与 panic 策略的正常边界约束。新增的零大小类型构造能力也并非天然安全，因为这类类型仍可能承载必须维持的逻辑不变量。

Cargo 的变化覆盖无用依赖提示、构建目录布局和可选的最短发布年龄限制。依赖冷静期可以降低刚发布的恶意包立即进入解析结果的机会，但已经锁定的版本不会因此自动替换，缺少发布时间信息的来源也有例外；发布说明明确指出 cargo install 不应用这项冷静期。它是供应链防护的一层，而不是安全保证。本文依据官方公告整理，未升级工具链或运行兼容性测试，依赖构建目录结构的脚本尤其值得人工复核。
