## 文章摘要

Seth Larson（Python 软件基金会的安全开发者常驻，也是长期写博客的开源人）在 2026 年 8 月 1 日发了这篇短文，记录他刚刚通关「**htmx 4: the game**」的全过程，并把整段游玩录像发到了 YouTube。

这件事本身就足够荒谬到值得写：htmx 团队把 htmx 4 这个版本**做成了一盒 Game Boy 卡带**——按 Larson 的说法，这是「第一个专门为 Game Boy 和 Game Boy Color 独家发行的 JavaScript 库」。他说自己看到公告的那一刻就知道这是为他量身定做的博客素材（Game Boy、开源软件、逆向工程，一次凑齐三样），当场就下单买了卡带。

**实物细节。** 卡带装在定制的纸盒和塑料壳里，包装紧到他得借助镊子才没把纸盒撕坏。卡带上有正式的标签，但标签上印的是「Game」而不是「Game Boy」——为的是避开任天堂的商标和授权问题。

**ROM 转储失败。** Larson 本想把 ROM dump 出来深挖，但他的 Epilogue GB Operator 读不出这盒卡带：卡带塞不进插槽，除非以一个奇怪的角度斜着插，而即便如此也无法给 GB Operator 提供稳定连接。他猜测这盒卡带的公差刚好落在 Epilogue 能容忍的范围之外。他只好转而用 Game Boy Player 配 HDMI 改装过的 GameCube 来采集画面——在这套组合上卡带插得很好，运行正常。

**游戏本体。** 他明确说这游戏**很难**，尤其是名为「The Slop Factory」（可以理解为对 AI 垃圾代码的调侃）的那一关，通关花了他一个多小时，而且每一关里散落的 4 个「HTMX」字母他都没能全部找到，这暗示还有更多内容待挖掘。游玩过程中有持续的卡顿（lag），而游戏的剧情把这个卡顿**归咎于 React**——Larson 加了个「一个多么可信的说法 ;)」的注脚。

**最妙的部分是源码分发机制。** 进游戏之前 Larson 最好奇的一点是：htmx 团队最终会怎么把 htmx 4 的源码交给你？如果只是弹出一个指向源码仓库的二维码，那就太让人失望了；还是说他们真的会让你**像抄 20 世纪杂志上的 BASIC 程序一样，一个字符一个字符地自己敲进去**？结果 htmx 团队真的走到了最远的那一端——你得从 Game Boy 屏幕上手抄源码。Larson 说正因如此，他现在更想挖这个 ROM 了。

他对这套「软件分发机制」的总结是全文的落点：算上下单、等快递、通关、然后从 Game Boy 屏幕上手抄源码这一整套流程，「可以说，它比 `npm install` 稍微不那么用户友好一点点 :)」——但这恰恰就是这类项目的乐趣所在。

补充两点从原文本身可以提炼、但正文篇幅有限没能展开的要点，用来替代评论区：

- htmx 团队在这次发布上做的其实是一次「分发渠道」的行为艺术。htmx 项目一贯的立场是反对前端生态的复杂度膨胀，而把一个 JavaScript 库的正式版本锁在实体 Game Boy 卡带里、只有通关之后才让你手抄源码，把这个立场推到了逻辑的荒谬终点：源码依然是完全开放的，只是获取成本被刻意抬回了 1980 年代的杂志时代。
