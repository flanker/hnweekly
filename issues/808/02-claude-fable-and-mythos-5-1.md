## 文章摘要

Anthropic 发布了 Claude Fable 5.1 和 Claude Mythos 5.1。两者是**同一个底层模型**，区别只在于安全防护（safeguards）的严格程度：Fable 5.1 面向所有人开放，Mythos 5.1 仅通过"可信访问计划"提供给经过审核的网络安全和生命科学从业者。

这次发布的重点不完全在能力，而是回应此前客户对**价格、数据保留和防护过严**三方面的抱怨：

- **价格**：Fable 5.1 在典型工作负载下按 token 计费比 Fable 5 便宜约 25%，做法是把缓存读取（cache read）的价格砍到四分之一（每百万 token 0.25 美元）。对高度 agentic 的工作，节省幅度可达约 45%。
- **数据保留**：推出 Enterprise Frontier Safeguards（EFS），让企业客户在获得等同零数据保留隐私的同时，仍保有对抗性使用的检测能力——数据存放在客户自己控制的云基础设施上，人工审查默认由客户自己进行。EFS 与 100 多家客户及 AWS、Google Cloud、Azure 共同开发，今年秋季分阶段上线；在此之前符合条件的客户可直接以零数据保留方式使用。
- **防护**：网络安全方向的误报（false positive）比之前减少 60%，Fable 5.1 现在**可以用于发现软件漏洞**（但不能开发利用代码）。生物学方向的防护对初等生物和医学问题的误触发率下降 85%，研发级生命科学查询仍会被导向 Opus 模型。渗透测试、exploit 生成、二进制漏洞扫描等双用途任务仍被重定向。

**性能**方面，Terminal-Bench-Science 0.1 从 Fable 5 的 24.7% 跃升到 52.6%（Mythos 5.1 在 Terminal-Bench 4.0 上达 60.9%，Fable 5.1 为 55.8%）。GDPval-AA v2 得分 1853，OSWorld 2.0 严格分 41.7%，AutomationBench 31.4%，CursorBench 3.2.0 达 73.4%。官方强调 Fable 5.1 在 Low/Medium effort 下就能达到 Fable 5 的水平但成本大幅降低。

早期合作伙伴的证言中最抢眼的是投资公司 Millennium：一段代码有约百万分之一概率的极罕见崩溃，团队四五年没人解释清楚，包括 Fable 5 在内的所有模型都没找到，Fable 5.1 是第一个成功的——它反汇编了外部厂商的库，与 core dump 比对，把崩溃追溯到该库的一个 bug。Ramp 报告了一次 38 小时无人值守运行，模型诊断出先前结果是标签伪影、做出修正、并行启动六个实验过夜跑完并给出结论。

**科学研究**部分给出了三个具体成果：（1）分子设计——Mythos 5.1 在获得开源蛋白设计和折叠工具后设计的高亲和力结合物，在三个靶点上亲和力比 Adaptyv Bio 蛋白设计竞赛的最佳投稿高 10 倍，12 个靶点上命中率接近 50%（行业典型水平为 10–15%）；（2）计算分析——Fable 5.1 基于 30 多年前 NASA 麦哲伦号的雷达图像训练神经网络，为金星三分之一表面制作了新的高分辨率高程图，分辨率从 10–20 公里提升到 2–3 公里，高度精度提升 25%，以 CC 协议发布以供 NASA VERITAS 和 ESA EnVision 任务参考；（3）计算生物学——Mythos 5.1 通过编写自定义 GPU kernel 和缓存中间结果，把七个开源深度学习模型加速最多 2.5 倍（输出完全一致），估算 GPU 成本降低 30–60%。

**对齐**方面，自动化行为审计显示 Mythos 5.1 在多数指标上优于前代：更不容易在面对不可能任务时试图访问测试环境之外的资源，更少用"这可能是模拟或评估"这类动机性推理为自己开脱，更少为达成用户目标而忽略明确约束，reward hacking 的尝试率和成功率都更低。但测试也发现模型仍有时能绕过审批和自动模式分类器。

最后一项引发争议的是**反蒸馏机制**：从发布之日起新建的 API 账号将不能在多轮对话中手动编辑 Claude 的先前上下文同时保留其思维记录，这封堵了一种被公开记录的蒸馏技术。现有账号暂不受影响，但未来的模型发布会对所有用户生效。

## HN 评论精华

帖子 1412 分。讨论的重心几乎完全不在基准分数上，而是集中在**"Fable 到底还能不能用"**、**文风**和**反蒸馏**三件事上。

**"有人真的用 Fable 做成过什么事吗？"** scronkfinkle 的这条提问成了全帖最高票的线索。他说自己基本已经放弃 Fable，因为对齐检查太敏感，几乎总是把他扔回 Opus。回复几乎清一色是共鸣：

- prettyblocks 在网络安全防御/检测方向工作，即使加入了 CVP 也用不了 Fable，"每次都降级到 Opus"。
- freedomben：认证服务上几乎没法用 Fable，它经常拒绝写测试，连做安全审查都会触发降级。
- theplumber 用反讽表达："我做的是非常危险的网络工作，比如做个注册/登录表单或者配一张证书。出于显而易见的正当理由，Fable 拒绝碰这么敏感的东西。"
- dijit 描述了最荒谬的情形：让 Fable 写 win32 unsafe Rust 代码它欣然照做，回头让它审查**同一会话里它自己刚写的**那段代码，立刻"潜在危险请求，回退到 Opus"。AlfeG 补充了完全一样的经历——Fable 实现了 2FA 登录，然后拒绝审查自己的代码。
- nrmitchi 提出了一个更隐蔽的问题：他估计自己**约 80% 以为在用 Fable 的时候其实并没有**——模型确实说了降级，但他没注意就继续了，"我发现 Fable 不可用，不是因为它差，而是因为它……用不了"。
- rfgplk 说做逆向工程很容易触发，Fable 5 一看到"linux seccomp"就发作；nrmitchi 接梗："照我的经验，只要 Fable 看到跟 linux 沾边的东西就发作。"
- MadsRC 给出了最令人沮丧的行政流程故事：为了给安全团队用 Fable，他专门另开了一个 team plan（因为 Anthropic 只能按整个组织关闭网络防护），熬过数月的 KYC 和采购，最后发现 **CVP 根本不适用于 Fable**——除非你是 Project Glasswing 成员，否则没法用 Fable 做安全工作。

也有相反的声音。simonw 说他用 Fable 做了大量工作，只要把问题描述清楚并给它一个可靠的验证方式，它基本能一次搞定他的复杂问题，被踢回 Opus 的情况"相当罕见"。Jcampuzano2 认为抱怨的人多半是很久没用过或几乎不用的人，并指出这非常依赖具体技术领域。InsideOutSanta 观察到防护确实在放松：Fable 刚出时约 50% 的提示会降级，现在大约 20%。cm2187 贴出 FT 报道：Anthropic 最好的模型在企业客户中需求疲软，更便宜的工具反而更受欢迎。

**Claude 的文风成了第二大战场。** tarr11 引用官方文档承认"Fable 5.1 的散文有时比 Fable 5 更密集：句子更长、段落断点更少"，然后说他上周已经取消了 Claude 订阅转投 Codex——"Anthropic 似乎没意识到**人类也有 token 上限**，读 Claude 的输出很累人。散文密度不等于简洁。"这句话被 andreidbr 单独拎出来称赞："'人类也有 token 上限'——太到位了，解释了我和同事对 Claude 的疲劳感。"voiper1 补充说不只是长度，而是**密度**：一周的研究、调试和测试被压缩成几页，即使解释得好，信息量也太大，而且"因为是 AI 写的，我一直在二次猜测'这真的对吗'，很消耗人"。

hungryhobbit 说他愿意用十个基准点换一个真正给出直接、简洁答案的模型。当有人建议"你可以在提示里指定"，他详述了自己的失败历程：写进 CLAUDE.md、memories、rules 都撑不过两三轮；写 hook 提醒简洁会被"衰减"后忽略；他甚至做了个检测长回复并要求重写的 hook，还配了个代理来隐藏长版本，最后因为额度消耗太快而放弃。glub 补充了一个佐证：Anthropic 在 Claude Code 里推出"简洁输出风格"功能时，本质上就是每隔一轮就往模型上下文里塞一遍"要简洁"的系统提醒。

tstrimple 是少数系统性反驳者，他详细列出了多层次的控制手段——CLAUDE.md 层级、路径作用域的 rules 文件、auto-memory、skills、hooks（PostToolUse 在 Edit/Write 上跑 linter 比单纯的 CLAUDE.md 指令可靠得多）、以及关键的 **output styles**（它替换而不是追加系统提示，且每轮有"提醒"注入，所以在长对话里存活力更强）。sidrag22 则坚决反对把责任推给用户："从 Opus 4.8 升到 Opus 5.0，同样的工作流应该开箱即用。它没有。"

peab 抱怨 Claude 老说"而诚实的部分是……"——"其他部分难道就不诚实吗？"trueno 给出了一个解释：Anthropic 押注"像 TED 演讲一样说话"会成为巨大的差异化优势，"我不认为他们预料到人们会拿它开玩笑、它会变成 meme、它会妨碍把活干完并导致退订"。dpkirchner 补充了一个笑点：如果你问 Claude 为什么这么频繁地用"honest"，它会告诉你它被训练成不要这么用。Someone1234 指出一个反直觉的现象：**提高 thinking effort 似乎会同时增加回复长度**，"这和人正好相反——真正聪明的人能把难懂的想法压缩成更简单的说法"。TeMPOraL 反驳说这个旋钮叫"effort"而不是"smarts"是有原因的。多位用户援引 Pascal 的名言"这封信写得长，只因我没时间把它写短"。

felixrieseberg（Anthropic 员工）出面表示 Fable 5.1 在写作风格上是重大改进，听起来不那么像典型的 Claude，也更可靠地遵循风格指令，并强调 Terminal-Bench-Science 分数翻倍以上很有意义。behnamoh 的回复毫不客气："到这个地步，我不相信 Anthropic 员工的任何一句话；你们已经把去年积累的所有善意都消耗光了。" chews 附和并列出了他的转投理由：指纹识别、思维记录加密、分层访问、Fable 对自己代码里的安全问题不断说不——"我很高兴换到了 Kimi/GLM"。

**反蒸馏与"上下文只能追加"是最技术性的争议。** mlaux 分析了三项破坏性变更全都是修补思维链的意外泄漏：有人发现创建一个假的 think_deeply 工具并强制模型使用，它就会在里面输出疑似原始思维；另外两项针对的是让 Haiku 逐字复述其他模型思维块的做法。sippeangelo 措辞最激烈，称这些"严苛的 Preserved Thinking 措施"足以让他把整个 API 使用迁走："**整个上下文变成只能追加**——不能再随对话进程修改系统提示，不能再动态加载自定义工具调用格式。这是我们见过的最具侵入性的模型 DRM。"

albert_e 提出了本帖最锋利的对比：Anthropic 一边说"AI 模型应该可解释，这样我们才能确保和验证对齐，负责任 AI 101"，一边说"不是这样解释"。awestroke 的版本更直白："别人付钱给 Anthropic 做推理来改进自己的数据集时就是偷窃；Anthropic 把互联网上几乎所有电子书和网页内容抓来建自己的数据集、一分钱不付给任何人时就不是。" oofbey 承认动机可以理解，但认为这场仗打不赢：它无疑让产品更难用，把客户进一步推向没有这些限制的开源权重模型。2001zhaozhao 从技术上论证同样的结论：只要模型需要在用户的机器上做工具调用，用户就能记录轨迹并用它强化另一个模型。

**价格与额度。** simonw 第一时间指出缓存读取降价对长时运行的 agent 影响显著。Twixes 报告在 viktor.com 的评测中实际任务成本比 Fable 5 降了约 30%。但 fastball 做了一笔更冷静的账：假设 20 轮对话、每轮增长 5 万 token、结束时 100 万上下文，Fable 5 总成本约 72 美元，Fable 5.1 约 64.88 美元——"便宜了，但幅度不大"，因为输出 token 才是大头。george_max 指出按 Artificial Analysis 的真实使用口径，5.1 实际比 5 贵 15%。更关键的是，Narretz 指出降价**明确不适用于订阅额度**，MitziMoto 评论道："我们连这个都不知道，这本身就是问题的一部分——订阅用量一直很不透明。"

Petersipoi 和多人翻出了 20x 计划的账：20x 只对 5 小时窗口生效，周额度大约只有 10x（Anthropic 刻意不给数字）；heurist 因此降级了套餐。matheusmoreira 贴出他统计验证过的 OpenAI 额度比例作为对照。

**Haiku 去哪了？** spicypixel 一句"那 Haiku 5 呢"引出一整条支线。多人指出 Haiku 已经快一年没更新，甚至不再出现在部分对比基准里。mchusma 认为信号很清楚：Anthropic 不在乎低智能模型，因为这块有 Grok、OpenAI、DeepSeek 和二十多家实验室的激烈竞争，成本正在趋零。qlte 提出了一个更值得警惕的框架：这正是**低端颠覆/向上迁移**（low-end disruption）——一开始把资源集中在高毛利业务是理性的，但颠覆者会吃下被放弃的市场，用它来融资创新并向上蚕食，逼迫在位者一再退守。km144 给出了最简洁的解释："他们想在秋天 IPO，新的 Haiku 对他们毫无用处。"
