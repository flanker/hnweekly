## 文章摘要

Movie Scene Map 是一个免费的交互式世界地图，把影视作品和它们真实的拍摄地点对应起来。作者在 HN 上的 ID 是 Flightmussy，人在挪威。站点提交到 HN 时标题写的是 13,312 部作品，页面上现在的数字已经涨到 15,716 个取景地、覆盖 166 个国家；作品侧的构成是 9,295 部电影与剧集、2,153 款电子游戏、407 部动画和 365 部漫画，另有 653 个系列。地点按类型也做了分类：134 个摄影棚与布景、599 座城堡与宫殿、4,153 处地标建筑、833 条街道与广场、2,176 处自然景观、7,623 个城镇、167 个国家与地区，以及 31 个虚构地点。按国家排，美国 5,178 处遥遥领先，其次是英国 2,068、法国 947、日本 671、加拿大 670、意大利 577、西班牙 537。

这个项目在方法论上的自我约束是它最值得说的地方，而且作者在页面上写得非常明确。数据主干来自 Wikidata 上的 filming location 声明，再关联到每个地点的坐标、照片和维基百科条目；另一部分来自作品自身维基百科条目里提到的地名，但这一类会永远被标注为「per Wikipedia」，因为"一个句子比一条结构化声明是更弱的证据"，而且两类数据从不混在一起。页面上直接写了一句「Nothing is generated」——没有任何内容是生成的。电子游戏是唯一的例外，而且作者强调这个区别很重要：游戏不在任何地方拍摄，所以它的位置来自 narrative location，也就是故事被设定在哪里；动画和漫画同理，因为"画出来的世界里什么都没被拍摄过"。地图本身需要 JavaScript，但下面所有的列表页都是纯 HTML，包括分国家的取景地页面和"史上最著名的 150 个实景拍摄场景"这样的专题页，每个地点都有自己的页面、照片，以及在那里拍过的作品列表。技术栈方面，评论区里 Askiir 从源码判断是 Tailwind + React + MapLibre。

站点还提供了一个 FilmGuessr 的猜地点小游戏，以及一个 /missing/ 页面用来提交地图上缺失的条目。作者本人说这是他一系列交互式地图项目中的一个——几周前上过 HN 的 Castle Map 也是他做的，他刻意维持一套标准化的 UI，觉得某个地图上的功能好用就复制到其他地图上去。他形容自己的做法是"用维基百科的信息在交互式地图上讲一个有趣的故事，有点像电子游戏，因为我自己就是玩家"。

## HN 评论精华

这条 Show HN 拿到 339 分，作者 Flightmussy 几乎回复了每一条实质性反馈，讨论的主线是数据精度与数据来源。

**最集中的批评是"地点粒度不够细"。** hberg 说他查具体的取景地点（而不是城市级别的列表）时找不到什么内容，并承认建立一个精确的取景地数据库是难一个数量级的问题。作者坦率承认这正是他知道的问题——有些条目甚至只精确到国家级别，尽管那个场景的具体位置是已知的，原因是他"没能把维基百科解析得足够好"。这句"解析得不够好"在整个帖子里被他反复用来解释各种错误。yorwba 立刻贴了个具体案例：《1942》的页面只列了 5 个地点，但 Wikidata 上的 narrative location 里至少还有塞班岛和中途岛。steinwinde 说苏丹境内唯一那个点在喀土穆，点开却显示的是埃及的尼罗河、对应一部只发生在埃及的电影。tamimio 指出《Source Code》被标成渥太华火车站，但查下来那次拍摄因为费用问题取消了、根本没去成——ChickeNES 在这里给了一条很好的建议：**别直接删掉，把它变成一条负面记录**，"错误信息就是这样一直流传下去的"，而且取消的取景地本身就很有意思（比如《蜘蛛侠》里的世贸中心）。DrZoidberg 举了《三颗榛子的灰姑娘》把摩里茨堡同时列在哈勒和德累斯顿的例子，问是不是只用了英文维基。sbassi 报告 X-Men 里的比亚赫塞尔条目是错的。reaperducer 说地图明显偏向 2000 年之后的作品，他知道的那些七十年代的地点一个都没有。

**关于"这是不是又一个 AI 项目"，作者的态度很明确。** ynac 建议他和别的数据库合作、或者用带验证机制的众包来扩充数据量，作者回答说他主要依赖维基百科，正是因为"不想让这个项目被当成又一个 AI 项目"；他愿意考虑其他数据库，但需要先弄清授权条款。Brajeshwar 问数据源怎么找的时候，他又强调了一遍：维基百科对所有人开放使用，这个项目才成为可能，"没有维基百科，我就只能依赖 AI 生成的结果，那不理想"。有意思的是 laidoffamazon 说自己几周前做过同样概念的东西，用的是 Wikidata 加 LLM 做数据来源和反向地理编码，但"这里的数据集干净得多"；作者的回应相当谦逊：找电影取景地的地图已经有不少竞品，谁都不独特，他只是按自己的原则做事、再靠社区反馈反复做质量检验。

**最打动人的一条来自 jimnotgym**：他说这类"把互联网上的某个专题整合成一种专门格式"的站点，是非公司化的互联网还能繁荣的领域之一。作者的回复难得地流露了情绪——"这条评论让我很开心。我喜欢有创造性，但我也喜欢人们真的想用我做的东西。在我开始做交互式地图之前，这种事从来没发生过。"他补了一句真实的困难：缺的条目还很多，难点在于怎么把地图填满而不至于让它变成一团点的垃圾场。binarysneaker 顺势给了个技术建议：高空视角先用热力图，放大后再转成具体的点。

**功能请求方面**，呼声最高的是"把实景照片和银幕画面并排对比"。xnx 说界面很好但光标和图钉很跳，而且看不到实景与片中画面的对照就不太满足；作者说他一直在想怎么把这个功能放进地图但还没想清楚，"很想加，因为那会非常酷"。1e1a 接着提议：如果加了这个，FilmGuessr 里就该用每部电影的真实画面，让人在完全不知道是哪部片的情况下猜地点。zamadatix 希望能有一个"直接跳到作品页面"的入口——他在夏延看到一部叫《Jericho》的剧，页面上有到数据来源、拍摄地列表、地点维基页的链接，却得手动搜索才能知道 Jericho 是什么。PetitPrince 想要筛选器：按类型（巴黎是不是爱情片更多？冰岛是不是奇幻片更多？）、票房（大片是不是都在好莱坞和温哥华？）和评分。

**几条比较可爱的**：jedbrooke 说他很惊讶 Null Island（经纬度 0,0）上什么都没有，"数据清洗做得不错"。larrymcp 认真地指出弹窗里那句"2 more places under this dot, click to see them"是典型的逗号拼接错误，应该用分号。radiorental 讲了他把星战粉丝送去爱尔兰阿基尔岛的经历，也吐槽了小岛上多部影片图钉互相遮挡的 z-order 问题，但同时发现了自己家附近居然也有取景地；作者说他自己也是这样才知道坐火车经过的芬瑟（Finse）是星战取景地，"我住在挪威，通常这里什么都不会发生"。autoexec 说他曾经按《狩魔猎人：圣父之罪》里的地点规划过一次新奥尔良之旅，游戏在这个地图上有条目但没有具体地点。Ldorigo 说自己做过一个非常相似但针对叙事设定地的项目，"看来你先到了"；作者回答他一开始做的是取景地，后来觉得自己也很想看游戏和动画的地点。dewey 补充推荐了 imcdb.org（影视中的汽车数据库）。
