## 文章摘要

这是一篇发表于 2026 年 9 月 27 日、篇幅不长、语气很冲的个人博客，作者是一名大学生（博客名 godObject）。起因是他学校的 App 最近推送了一次"小幅 UI 改进"，结果成了他见过"最 slop 的界面"。旧版虽然笨拙，他宁愿要旧版，也不想要 AI 代理喷出来的这堆东西。他对 slop UI 的定义是：AI 做出来的、看着别扭、放错位置、没有用处或者过于千篇一律的界面，常见于"没有愿景的氛围编程"。他强调氛围编程做得好也能很好看，只是大多数做得不好，让应用显得廉价、没人想用。他还点名 Cloudflare 最近就上线了一个这样的网站。随后他列出十个特征：

1. **渐变，到处都是渐变。** 最显眼的标志，按钮上、背景里，凡是能塞的地方都塞。而且这类"slop 大炮"不知为何特别爱紫色。
2. **彩虹呕吐。** AI 喜欢用一堆毫无意义、只是"不一样"的颜色，彼此并不搭配，只因为做 UI 时字段之间有某种区分，完全不遵循配色比例原则（作者写的是"70-30-10 法则"，设计界更常见的说法是 60-30-10）。
3. **会闪的徽章。** 他的学校 App 里有个"数字学生证"，只显示二维码和照片，旁边却挂着一个闪烁的"已激活"徽章。问题是它永远不会是未激活状态，一旦失效 App 直接把你登出。个人资料页还有个"在读学生"徽章，他大写质问："谁能告诉我不在读的学生长什么样？？"校徽旁边还加了个"已验证"标记，可它根本没有调用什么接口去验证，就算验证了也毫无意义，难道伪造学生证的人会特意加个"未验证"吗？
4. **指甲卡片。** 指的是卡片一侧带一条彩色竖边的样式。几乎每个氛围编程的界面里都有，"倒也不是说它难看，只是被每个 LLM 在每个地方用滥了，现在看着就难看"。他不相信有人曾经认真坐下来想过："你知道什么能改进这个设计吗？一片指甲。"
5. **满屏 emoji。** AI 对 emoji 的爱，"比 Sam Altman 爱假装自己在引领前沿还多"。
6. **对不齐的东西。** 不在方框里的 SVG、ASCII 图形之类的元素几乎总是偏的，比如他学校 App 课表里的一个列表。
7. **字体选择。** 几乎总是 Inter，只要网站跟编程沾一点边就是 JetBrains Mono；而且凡是提到技术相关的东西，就要加上 `//` 这样的装饰符号。
8. **聊天上下文泄漏导致的多余文字。** 他做上一个博客时对 AI 说"我不想写 HTML，我要在舒服的 Neovim 里写作"，结果网站上出现了一行"Built with Hugo. Written from Neovim"。没人在乎你在哪里写的。README 里也一样，"采用现代 C++20 特性构建"，谁在乎？学校 App 的启动屏写着"一个校园，一个应用"，"你几乎能闻到触发它的那句提示词"，多半是某个管理者说了句"我们三个校区有三个 App，合并成一个吧"。
9. **玻璃拟态。** AI 酷爱毛玻璃效果，除此之外只会粗野主义（brutalism），而 AI 做出来的粗野主义风格全都长得一模一样。不过他承认粗野主义还算可以接受，直到被用滥为止。
10. **空洞的口号和无谓的煽动。** AI 痴迷于 Elevate、Seamless、Next-Generation、Supercharge、Unleash、Empower 这些词，每个 H1 下面都跟着一行灰色副标题，比如"以我们前沿而直观的界面体验任务管理的强大力量"，还爱写"欢迎来到你的仪表盘，[名字] ✨"或"革新你的工作流"，把每个页面都当成落地页，而不是一个实用工具。

结尾他坦言这只是一堆让他看着烦的东西，自己并不反对氛围编程，"这个网站本身就是氛围编程做的，挺可爱的吧"，他只是受不了那些人连让界面稍微好看一点的努力都不肯花。

## HN 评论精华

帖子 386 分、约 240 条评论，讨论非常活跃。主要分歧在于：这些特征究竟是 AI 的问题，还是人类设计早已有之、只是被 AI 用滥的潮流；以及 slop 到底是模型能力问题，还是使用者懒得给方向、懒得把关。不少人顺手吐槽了作者博客本身的字体，也有很多人补充了自己观察到的"AI 特征"。

**这些都是人类先用的。** ronbenton 的评论排在最前：很多模式真正的人类设计师早就在用了（emoji 满天飞除外），这和有人认定破折号就意味着 AI 写的一样。hnlmorg 说那种安抚用户"应用还在干活"的加载屏 Discord 用了好多年，玻璃效果是苹果开创、早就进了 CSS 的，用颜色区分紧急程度也是好的 UX；podgietaru 提醒他作者批评的是加载屏上那句泄露上下文的文案，hnlmorg 又回应说合并应用时这本来就是常见的营销话术。api、qoez、vallerie 都说丑陋界面早于 AI：之前是 React 垃圾，再之前是 Bootstrap 垃圾，再之前是 jQuery UI 垃圾，vallerie 还说 jQuery 的手风琴组件是"网页蟑螂，可能会比我们所有人活得都久"。几位读者也解答了作者的反问：tptacek、epihelix、cosmotic、atoav 都指出"非在读学生"确有其事，指的是在系统中但当前未注册课程的学生，跟学生折扣等资格有关；atoav 说他从零写过校园身份管理系统，区分两者很重要，只是没必要展示给用户看。

**被用滥才是问题。** dreambuffer 区分了两种"坏"：有些风格永远糟糕，有些只是因为被用滥才显得糟糕，后者恰恰因为原本是好设计才被滥用，问题在于人们天生厌恶重复。socializer 说得更透：大家用的是同样的 LLM，随口说一句"帮我做个网站"，得到的产品就非常相似，久而久之人们学会识别并厌恶这种美学；写作也一样，"不是 X，而是 Y"本身没错，但他现在尽量避免，因为已经被 AI 污染了。pornel 惋惜道：我们已经失去了破折号和项目符号列表，接下来还要失去卡片、胶囊标签和小型大写字母的副标题。jd7h 说自己最爱的粗野主义网页风格成了 AI 的气味，"他们已经拿走了我的破折号！"。ungovernableCat 预计这会像时尚一样循环，过几年现在被用滥的风格也许又会显得新鲜。

**是提示的问题，还是能力的问题？** NitpickLawyer 认为很多问题都是糟糕提示的结果：渐变和 emoji 在提示词或 agents.md 里加一行就能去掉，颜色乱用可以先指定调色板，没有就先让模型按最佳实践给一套；对不齐则是使用者的锅，这种问题检查起来又快又便宜。minimaxir 说人们没意识到可以对 LLM 说"不"：现实中质疑同事的设计是职场失礼，但 LLM 不是同事。pointillism 分享了自己 agents.md 里的一句狠话："如果我在你的代码里看到 indigo-500，我就宰了你。"gpm 则认为对齐问题是视觉能力不足导致的，等模型真正能"看"就会解决；minimaxir 回应说现在的多模态模型做网页设计已经够用，只是对负空间和内边距不敏感，主要问题还是提示过于简略。mrweasel 指出关键在于把关的人：机器做了 UI，但总得有人看了一眼说"好，上线"；做好 UI/UX 本来就非常难，不擅长的人又怎么认得出好 UI？

**提示中的"负面例子"反而招来问题。** weakfish 说他终于明白"三个校区，一个应用"这类文字是怎么来的：模型过度在意提示的某一部分，他要求优先用 TestContainers 写集成测试，模型就在每个测试里加注释"真实服务，没有 mock"。JoshTriplett 说 LLM 特别爱"可疑的具体否认"：你让它别做某事，它就特意声明自己没做。WorldMaker 把这比作"别去想粉红色的大象"，他曾在多个项目里删掉别人精心写的"不要 X""绝不 Y"段落，换成更短、只有正面示例的提示，效果反而更好。jesse_ash 讲了个笑话：他在提示里加了一条"紫色大象规则"来劝阻这种行为，结果注释和文案里开始冒出紫色大象。slopinthebag 也说他让模型"不要口号、不要多余文案"，它就加上一句"只有你的 UI，没有文案"。charles_f 做了一个只给自己用的德语练习应用，登录页上 AI 塞了七句口号。demibabs 补充了一个常见泄漏："你的文件从不离开你的浏览器"，凡是在客户端处理文件的氛围编程网站都忍不住要说这句。unholiness 认为很多 AI 痕迹都是"AI 与写作者之间的关系"泄漏到了给读者的文本里，部分源于 RLHF（"看我做到了！选我！"），部分像是思考过程混进了正文。

**大家补充的其他特征。** vmg12、msdz、efilife 提到滥用全大写，尤其是加字距的等宽全大写；WorldMaker 补充说无障碍专家好不容易让大公司不再这么做，LLM 又让它成了默认。zeroonetwothree 提到随处可见的小型大写标签，bbg2401 和 atoav 提到中点（·）分隔符，nfw2 提到"卡片套卡片套卡片"、羊皮纸背景和毫无意义的仪表盘，xavdid 提到滚动时淡入的内容，jd7h 提到"Claude 米色"和"Claude 炭灰色"，65 提到"没有这个，没有那个"式文案，arshxyz 发现 slop 界面的标签总用第二人称，比如"需要你"而非"需要处理"，pmkary 和 nswizzle31 则认为最明显的特征是"标题加描述"和满屏的文字。

**Cloudflare 被群嘲，也有人辩护。** docheinestages 无法理解一家数百亿美元的公司怎么能放弃设计标准；jasonvorhe 把那个页面批得一无是处：对比度糟糕、没有视觉引导、两侧留白不一致、编号永远停在 01、终端窗口不像任何真实终端。ctrlkctrls 认为 Cloudflare 这么有名的公司落地页不需要多少设计，"别再搞 AI 末日论了"；dragonwriter 反驳说，对低投入的 AI 作品表示不满不等于末日论，何况作者本人显然是热衷用 AI 的人。Mawr 的观点颇为务实：他正好需要 Cloudflare 那个 Quick Tunnel 产品，网站长什么样他一点也不在乎，真正的替代方案往往不是一个更好的网站，而是根本没有网站。

**作者自己的网站也没逃过。** wigster、dpark、falsemyrmidon、bryanrasmussen 都吐槽博客标题用的哥特体（UnifrakturCook）难以阅读；xz18r 说作者的个人作品集网站也有点"slop 味"。wongarsu 替作者解释：他本来就坦然使用 AI，只是希望人们别把通用提示的第一个结果直接发出去。dpark 则说最近不少"slop 设计"批评似乎都不是来自有扎实设计功底的人。

**普通用户在乎吗？** ookblah 和 uxcolumbo 认为大多数公众根本不关心界面是不是 AI 做的，只要能用、文案不太烂就行；_rwo 说他用 AI 重做了一个老旧门户站点（原来是手写的 Bootstrap 2），收到的全是好评。elaus 反驳说毫无意义的徽章、没有含义的颜色本身就会降低可用性，对齐也不只是为了取悦设计师，它帮助用户理解哪些元素是一组。zinoc 和 Ancapistani 把现状比作 2013 年前后 Bootstrap 带来的同质化，当时也有人抱怨，但那是可用性和无障碍的巨大进步。voidhorse 和 WorldMaker 不同意这个类比：Bootstrap 是一套有意设计、对用户有益的合理默认值，满足 WCAG 标准，而 slop 范式只是 LLM 的偶然倾向被无限复制，留白糟糕、字体难读、对比度不足，"对无障碍嗤之以鼻"。

**一些更深的感想。** mjr00 用学音乐的经历打比方：从"糟糕的音乐人"变成"过得去的音乐人"，靠的是一百个细小技巧的积累，需要经验才能知道它们是什么，UI 也一样。tlahtinen 说今年早些时候他用 Claude 为自己做的 Unreal 游戏设计了一个界面，当时觉得是改变游戏规则的布局，不到一年就为它那么"Claude"而尴尬：角落里的闪烁圆点、标题里的双斜杠、那些字体，现在到处都能看到。anothermathbozo 和 blindflag 则认为，每当有人精确总结出 AI 垃圾的特征，前沿实验室就多了一个清晰的强化学习目标，这些特征注定只是暂时的。andrewdb 当场把这篇文章做成了一个检测 slop UI 的 Claude 技能，diwank 预言"看着吧，这会变成一个技能，然后在 X 上爆火"。
