## 文章摘要

这是苹果开发者网站上 Pass Designer 的产品介绍页。Pass Designer 是一款 macOS 应用，用来为 Apple Wallet（钱包）设计和预览各种「卡券」（pass），比如活动门票、登机牌、会员卡、商店卡。苹果的说法是，不管是本地健身房、小型音乐场馆，还是跨国航空公司、全国连锁咖啡品牌，都能用它做出符合自家品牌风格的卡券。

**主要功能。** 可以从苹果提供的模板或自己的模板起步；logo、背景图、条幅图这些素材用自己习惯的设计工具做好，再导入 Pass Designer 拼成完整的卡券。编辑时预览会实时显示卡券在 iPhone 和 Apple Watch 上的样子，而且用的是和 iOS、watchOS 相同的渲染方式，苹果称「所见即用户所见」。其他功能包括：

- **颜色与外观**：调整卡券的背景色、前景色和标签颜色。
- **自适应布局**：既能用上 Apple Wallet 最新的设计能力，也能生成兼容旧系统的卡券。
- **标准字段**：每种卡券类型都有一组用来显示信息的标准字段，可以直接在应用里编辑内容。
- **校验**：编辑过程中实时检查，发现缺少必填键值或出现意外定义时会提醒。
- **语义标签**：针对登机牌和活动门票，可以添加活动日期、场馆位置、航班信息等结构化数据，系统据此提供 Siri 建议、日历集成、地图导航等功能。语义标签可以直接在界面里编辑，带语义和不带语义的版本可以并排对比；应用还能根据语义数据自动生成一份不依赖语义标签、兼容旧系统的卡券结构。

**获取方式。** 目前是 beta 版，需要 macOS 27 或更高版本，用 Apple 账户登录开发者网站下载，可能需要完成免费注册并同意开发者协议。从评论看，iOS 27 的钱包应用本身也新增了让普通用户自建卡券的功能，Pass Designer 则面向需要更精细品牌设计的商家和开发者。

## HN 评论精华

评论有 300 多条，很多讨论都跑题了：除了 Wallet 卡券本身，还谈到电子票务的种种不便、苹果「垄断」之争、HN 社区风气、苹果软件质量和 Siri。

**电子票务的痛点**

- **frabert** 觉得这个工具特别像只有旧金山人才用得上的东西，和他的乡下生活没什么关系。**boplicity** 说现在很多活动没有智能手机根本进不去，手机电子票不但普遍，而且常常是强制的。**corytheboyd** 说至少 Apple Wallet 能离线用，比那些要先跟几千个数据收集服务握手、在人挤人信号差的场馆门口才能打开「我的票」页面的专有应用强多了。
- **freedomben** 提到演唱会门票只能在官方应用里显示，二维码上有动画，没法截图或导出 PDF。这引出了关于「动态二维码」的讨论：**hackingonempty** 说滚动码是为了防止有人用截图入场、绕开官方系统转让门票；**well_ackshually** 解释说检票员是人，动画就是一种「活体证明」，很多检票系统不联网，没法确认票是否已用过，动态码的原理类似 2FA 验证码，按设备密钥每分钟轮换。**mrweasel** 举了丹麦的例子：新冠通行证最初只是一个二维码，结果有人在 Facebook 上卖截图。
- **subpixel** 吐槽 Ticketmaster 的门票绑定账户，几乎没法转给别人，他发誓再也不给这家公司一分钱。**radicality** 则说自己多次用应用内转让功能把票转给伴侣，没遇到问题。

**它到底有什么意义**

- **pastel8739** 问大家觉得这东西有什么意思。**tonymet** 回答说，很多 iPhone 用户一直抱怨 Wallet 发展了快 18 年还是没多少商家支持，原因之一是接入需要 Xcode 开发经验，这个应用有望消除这个障碍。**iAMkenough** 不太乐观：商家想要 iPhone 和 Android 通用的方案，这个工具解决不了这一点，所以采用率可能还是老样子。
- **MBCook** 认为它主要面向小商家和小活动方，健身房这类小机构不会有懂行的员工去做卡券。他还提到，在 Whole Foods 或亚马逊退货点，经常能看到店员帮顾客在应用里翻找条码，所以「发邮件就够了」并不是普通人的真实体验。**jkubicek** 补充说，Wallet 卡券可以绑定地理位置，到了地方会自动出现在锁屏上。
- **mahboi** 持反对意见：直接发一张条码图片的做法一直都挺好用，现在搞出一个更不稳定的方案，大概是为了加强 iPhone 锁定。他说西南航空的登机牌在他妻子的 iPhone 上用不了，他只好截图发给她。
- **msephton** 说自己十几年前在苹果工作时就极力推动做这个工具，当时内部用的是临时凑合的方案，「迟到总比不到好」。**multiplegeorges** 说自己当年照着苹果那份很不完善的文档做卡券，最后因为太痛苦而放弃了。**eddieroger** 回忆说，Passbook 刚推出时苹果有过一个 Sinatra 写的工具，需要大量手写 JSON。

**平台限制和「垄断」争论**

- 有人问为什么要 macOS 27 才能用。**briandw** 认为主要是测试成本，新功能不去兼容旧系统要省事得多；**ladberg** 解释说苹果习惯把应用之间的共享代码抽进系统库，内部开发者又一直跑最新的 nightly 系统，所以新代码几乎不可避免地依赖最新系统。**user_7832** 不满它只能在 Mac 上用，认为这会把没有 Mac 的图书馆、咖啡馆等小机构挡在门外。**coldtea** 说苹果本来就不做其他平台的软件，**andrewshadura** 则说完全可以做成网页应用。
- **GodelNumbering** 说很难支持一个只会加固垄断的东西。**gumby** 反驳说苹果在哪个领域都谈不上垄断。**GodelNumbering** 认为苹果虽然不控制整个市场，但牢牢控制着自己的生态系统并从中收租；**ChrisMarshallNY** 认为苹果用户喜欢苹果，恰恰是因为它的围墙花园。双方就此争论了很久。
- **frabcus** 认为苹果应该和谷歌、票务公司一起制定统一标准，让商家只做一次卡券，**dewey** 回了一句「于是现在有三个标准了」（引用 xkcd 927）。**apocalyptic0n3** 解释说，Apple Wallet 和 Google Wallet、三星钱包各有各的实现，大多基于 .pkpass 格式，Pass Designer 只是苹果这一侧的设计工具。

**功能愿望和替代工具**

- **mortenjorck** 希望 Wallet 显示条码时只把条码那一块区域提到 HDR 高亮，而不是把整个屏幕调到刺眼的亮度。**kenferry** 说条码区域其实早就有语义定义，因为条码是苹果根据文本数据自己绘制的。**SirMaster** 贴了一个用 HDR 视频技巧实现局部高亮二维码的演示页。**database64128** 发现应用临时把亮度调到最大，会被 iOS 当成用户手动调节，久而久之自动亮度就失灵了。
- **ACCount39** 希望卡券支持 TOTP 动态码。**saxenaabhi** 抱怨 NFC 读卡器读不了 Wallet 卡券，**CamJN**、**jyounker** 等人反驳说他们当地的巧克力店、健身房、咖啡店都在用 NFC 卡券。
- **gruez** 指出，用这个工具签发卡券仍然需要苹果开发者计划的签名证书（年费 99 美元），没法随手做临时卡券；多位用户回复说 iOS 27 的钱包应用已经能直接创建自定义卡券，不过 **Lalabadie** 说这个功能不支持条码，所以大部分会员卡还是用不了。评论里还推荐了不少第三方工具：walletwallet.alen.ro、Pass4Wallet、Anycode Wallet、kitty.cards 等。**cube00** 提醒说，有人贴的 passdesigner.app 看起来像苹果官方，其实是评论者自己没有声明的 vibe coding 项目。
- **danpalmer** 认为这正是那种 LLM 出现前很难排上优先级、现在却很容易做出来的软件：schema 清晰，不需要什么巧妙的交互，用标准组件就能拼出来。**latexr** 反驳说，苹果市值数万亿，缺的不是 LLM，而是专注把产品做好。
