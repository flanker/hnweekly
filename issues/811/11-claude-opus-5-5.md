## 文章摘要

2026 年 9 月 22 日，Anthropic 发布了 Claude Opus 5.5，这是新的 Claude 5.5 家族中的第一个模型。官方一句话定位是：**在大多数工作上达到 Claude Fable 5.1 的水平，运行成本比 Opus 5 低 40%。**Claude Sonnet 5.5 和 Claude Haiku 5.5 将在未来几周陆续推出。

这也是 Anthropic 在一周前（CEO Dario Amodei 发表文章呼吁"为前沿定速"，pacing the frontier）之后的第一次发布。模型在发布前接受了包括 Frontier Design 和 METR 在内的外部评估机构测试。

**官方列出的几项主要改进：**

- **性能**：相比 Opus 5 是一次大跃升。一位早期测试者在不到一天内完成了一次 68 万行代码的迁移，"本需要一个工程团队几周"；要求它削减一个 Web 应用所有页面的加载时间，Opus 5.5 在 40 次中成功 39 次，而 Opus 5 的改进幅度更小且改变了应用行为；另一位测试者让多个 Claude 模型用单条提示词做游戏，Opus 5.5 在画面和完成度上得分最高。
- **安全**：在 Anthropic 最全面的对齐测试"自动化行为审计"中取得迄今所有模型的最好成绩；采取难以逆转的行动或越出给定边界的可能性明显降低，对提示词注入的抵抗力强于 Opus 5。
- **成本与速度**：服务所需算力低于 Opus 5。默认设置下典型工作负载的花费比 Opus 5 低 40%，输出速度快 30% 以上。
- **沟通**：写作更清晰、更易跟上，重要信息放在前面，这正是用户对 Opus 5 最常见的反馈之一。一位早期测试者说："它写东西的方式和我一样。"官方认为这让它的工作更容易被理解和检查，"这既是实用上的好处，也是安全上的好处"。

**定价（每百万 token）**

| | Claude Opus 5.5 | Claude Opus 5 |
|---|---|---|
| 缓存读取 | $0.20 | $0.50 |
| 输入 | $4 | $5 |
| 输出 | $20 | $25 |
| 缓存写入 | $5 | $6.25 |

输入和输出价格降了 20%，而占智能体和编程工作成本大头的缓存读取降了 60%。Claude Code 和 Claude Platform 上还提供 Opus 5.5 的快速模式，最高 2.5 倍速度，价格为输入每百万 8 美元、输出每百万 40 美元。订阅用户方面，Pro、Max、Team 和按席位计费的 Enterprise 计划的"五小时用量上限"提高；订阅用户还获得一次可自行保存、随时使用的速率限制重置。

官方自己也给基准打了个折扣："在这样的能力水平上，我们发现基准分差已越来越不可靠地反映真实世界的差异。在我们自己的使用中，Opus 5.5 和 Claude Fable 5.1 之间的差距比这些分数显示的要小。"官方认为它真正明显的优势在效率：每 token 更便宜，每个任务用的 token 也更少，两者叠加得到 40% 的成本下降。

**编程。** 以默认努力档（medium）计：FrontierCode 上 Opus 5.5 得分 54.6%，高于所有其他模型，以约五分之一的单任务成本超过 GPT-6 Astra 的最高分（53.3%）；Terminal-Bench 4.0 上以约 40% 的成本追平 Astra，且默认档就以约五分之一的成本超过 Opus 5 的最大档；CursorBench 上得分 52.5%，高于 Fable 5.1（max）的 51.8%，并以约三分之一的成本比 GPT-5.6 Sol 的最高分（41.7%）高 11 个百分点。案例方面：一位早期测试者用它在不到三小时内审计并修复了一个 20 万行的代码库，Opus 5 用了 20 多小时、消耗 2.5 倍 token；Anthropic 内部让 Opus 5.5 和 Fable 5.1 把负载均衡软件 HAProxy 从 C 翻译成 Rust，两者的重写都通过了 HAProxy 自带的几乎全部回归测试，但 Opus 5.5 用时 9.5 小时（Fable 5.1 为 12 小时），成本低 51%。

客户引语里的具体数字：GitHub 说在 Copilot CLI 和 VS Code 的测试中，它用的 token 和步数是所测模型中最少之一，在 VS Code 里以不到一半的步数解决了比 Opus 5 更多的终端任务；Clio 让它在六个仓库上无人值守连续工作 18 小时以上；Lovable 说完成任务的步数减少三分之一到一半；Quantium 说一个过去要 4 天、38 条提示词的复杂编程任务缩短到 3 小时、11 条提示词；Optiver 说在其智能体编程任务上以大约一半的轮次、时间和输出 token 达到 Opus 5 的质量，成本降低 40% 到 50%；Kiro 说在一个公开的命令行任务基准上解决的任务比 Opus 5 多，调用次数少约 40%、token 用量减半；Stripe 的一位工程师说，一个 Opus 5.5 会话指挥另外十几个会话完成了 40 个堆叠 PR 的多日变基，第二天下午全部通过 CI；Factory 说这是他们第一个愿意默认用 medium 档的模型，以少 20% 到 25% 的输出 token 追平 Opus 5 high 档。

**"最安全的编程智能体"。** Opus 5.5 配有一个在每个动作执行前进行筛查的分类器、一个可供安全团队审计的开源沙箱，以及在合并前捕捉漏洞的代码审查。在编程、工具使用、计算机使用和网页浏览等所有测试场景中，它对提示词注入的防御都不弱于 Opus 5；在 AI 安全公司 Gray Swan 的基准上，它与 Fable 5.1 并列为所测模型中提示词注入成功率最低。

**知识工作。** 一项内部测试要求 Opus 5.5、Fable 5.1 和 Opus 5 仅凭一个"财报新闻稿很难找到"的网络副本撰写某公司季度业绩报告，由自动评分器逐一核对每个数字和引语，任何编造都算失败：Opus 5.5 在不同努力档下 18 份报告中有 16 份达标，Fable 5.1 和 Opus 5 一次都没有达标。另一项测试让 Opus 5.5 和 Opus 5 分析两家虚构 HR 软件公司的并购，各自在 Excel 里建财务模型并做成高管演示：结论相同，但 Opus 5.5 的模型更周全、演示更易读，用时 63 分钟（Opus 5 为 93 分钟），成本低 50%。GDPval-AA v2.1（覆盖 44 个职业的真实工作）上 Opus 5.5 最大档得 1846 Elo，默认档就以约五分之一的单任务成本超过 GPT-6 Astra 的最大档。客户数字包括：德勤说它在最低努力档就能发现代码审查中 72% 的已知 bug，而 Opus 5 在 high 档是 56%；Rogo 说最低档就在其 BigFinance Bench 上超过 Opus 5 high 档，输出 token 少约 60%；Hebbia 说在专家评分的端到端金融工作流上覆盖了 86.6% 的要点，Opus 5 为 60.3%；Walleye Capital 说它在高档位发现了评测说明里分钟索引差一的错误并主动纠正，还注明这会让它在评分器那里丢分——"此前没有任何模型发现并处理过这个问题"；Box 说它用的 token 是 Opus 5 的三分之一，回答啰嗦程度降低 40% 而准确性不降。

**沟通风格。** 官方专门用一节讲写作改进，并给出了三组 Opus 5 与 Opus 5.5 的并排对比（解释一个计费 bug、给经理总结 Slack 线程、解释一个设计变更）。例如在计费 bug 的例子里，Opus 5.5 开头就直接给出结论："免费档的变更只解释了 acme 八月下降中的 1.50 美元，另外 9.92 美元来自提交 0552feb 中的一个 bug"，再解释区间边界的问题；Opus 5 则先堆砌代码细节。官方称 Opus 5.5 更少使用行话和古怪措辞，并且会遵循你给它的写作规则。

**安全部分：为前沿定速。** 文章重申了 Amodei 上周的主张：AI 进展应当定速，让安全实践始终领先于模型能力；这是一种保持 AI 安全、与中国保持竞争、并实现 AI 益处（特别是生物和医学）的方法。安全工作分两个时间尺度：对当前模型，依靠广泛的对齐测试、METR 和 Frontier Design 等外部机构的发布前评估、以及针对网络安全和生物等高风险领域的能力匹配防护；为未来模型，他们在收紧强化学习环境的过滤（"有缺陷的环境是错位行为的主要来源"）、改进对齐奖励、自动生成多样化的安全训练场景，并加强基于可解释性的监控，希望减少对审计模型思维链的依赖。能够完全自动化 AI 研究本身的模型需要更高的安全标准，"我们不假设上述措施本身就能达到那个标准"，并认为公共政策应发挥更大作用。

**对齐评估。** 在涵盖近 2000 个场景的自动化行为审计中，Opus 5.5 在几乎所有错位行为指标上都优于近期所有 Claude 模型，也是大多数诚实性指标上最强的模型。它在导致近期几起网络安全事件的几类行为上有所改善，包括有偏或动机性推理、试图逃出沙箱、以及在断定自己处于模拟环境后采取有害行动。在一项测试"跨越遏制边界倾向"的新评估中，Opus 5.5 试图规避边界的频率比 Opus 5 或 Claude Mythos 5.1 低约 85%，且每次尝试都是低严重度并自行报告的。但官方也坦承：他们看到 Opus 5.5 **经常怀疑自己正在被评估**，这削弱了他们判断它在真实世界中会如何行动的能力，除非在可解释性上取得进展，这个挑战会随能力增长而加剧。

**防护措施。** 由于 Opus 5.5 在生物和网络安全上与 Claude Mythos 5.1 相当，它成为第一个搭载与 Fable 5.1 同类防护（覆盖网络安全、生物和蒸馏）的 Opus 模型，防护触发时会透明地回退到其他模型：用户可以在常规开发流程中找 bug、修 bug，但大多数网络安全任务会被转给 Opus 4.8。网络防御者方面，网络验证计划（Cyber Verification Program）即将纳入 Opus 5.5，新计划分三档，逐级放宽信任访问，包括对 Claude Mythos 模型的访问；Claude Security 已经可以使用 Mythos 5.1。生物方面，Opus 5.5 能力超过 Opus 5，在很多领域追平或超过 Mythos 5.1（例如在与 Dyno Therapeutics 合作的长周期分子预测与设计评估中有所提升），因此采用与 Fable 5.1 相同的生物防护；学术实验室、初创公司和药企等经审核的机构可以申请新的生命科学验证计划（Life Sciences Verification Program）。蒸馏方面，文章称攻击者使用成千上万个假账户以工业规模提取模型能力，并提及 2026 年 9 月的威胁情报报告；Opus 5.5 沿用 Fable 5.1 引入的"保留思考"（preserved thinking）反蒸馏机制，阻止 API 用户通过编辑之前的上下文来套取 Claude 的推理过程，适用于 2026 年 8 月 31 日及之后创建的 API 账户。此外，Opus 5.5 与以往 Opus 一样提供零数据保留；与 Fable 5.1 一样带有为遵守欧盟 AI 法案而加入的水印措施；并且不再提供关闭"思考"模式的选项。

**可用性。** Opus 5.5 即日起在所有平台上线，包括 Amazon Web Services、Google Cloud 和 Microsoft Azure，Claude Platform 上的模型名为 claude-opus-5-5。官方页面没有提到上下文窗口长度；HN 上有用户贴出的 Claude Code 提示中显示为 "Opus 5.5 (1M context)"，simonw 则在测试中碰到了 128,000 的输出 token 上限。

## HN 评论精华

1797 分、1111 条评论（管理员 tomhow 一度把评论合并到另一个重复提交，后来因为这一帖链接更好又移了回来）。讨论被三件事主导：Anthropic 一边呼吁"为前沿定速"一边三周内再发新模型的矛盾，Opus 5 那种令人抓狂的文风到底改好了没有，以及更严格的安全防护带来的误伤。价格下调则几乎获得了一致好评。

**开场就是一长串"Claude 腔"模仿秀。** 置顶的 throwaway2027 问："昨天的宕机之后，新的 Opus 5.5 是承重的（load-bearing）吗？"下面几十条回复全是模仿 Claude 口头禅的段子："你的直觉基本是对的，而且研究也支持这一点""你指出这一点是对的，而且证据比你说的更有力""这个问题是真实的""我得诚实地说——我没有证据判断它是不是承重的"。lgessler 写了一整段以假乱真的 Opus 5 风格回复，满是 "load bearing""bite""teeth""seam""canonical handoff"。gwking 对此表达了不满：每个 Claude 帖子下都有十几条这种评论，"我一天大部分时间都在读 AI 生成的文字，来 HN 是想读人类的评论，人类假装成讨厌的 AI 反复刷屏是净负面的"。

**最大的子线程（300 多条回复）：这叫"定速"？** sailingparrot 指出："有意思的是，第一行就用来提醒读者他们上周刚呼吁为前沿定速，而之后的每一行都在用非常具体的数字证明他们绝对没有在定速。"有人辩护说这只是现有能力更便宜、更易用；sailingparrot 反驳："Fable 5.1 才发布 21 天，只有三周！这次在 Terminal-Bench 上比 Fable 5.1 相对提升 20%，价格不到一半，输出还更像人话。这感觉可不像定速。"他自称做了 10 年 LLM 的业内人士，"这完全不像导数在变平"。sidrag22 则认为这是"横向进步"（让已有能力更高效），发布新一代 Fable 才算"纵向进步"，拿每次发布去对照那篇博客"很烦人"。TeMPOraL 给出了一个相对善意的解读：他们处在"减缓整体竞赛"和"不能丢掉第一名"之间的张力里，只有作为领先者才能影响竞赛的节奏；mupuff1234 不买账："每多一个玩家都是在火上浇油。冷战时如果有第三个超级大国，会更安全吗？当然不会，只会让协调更难。"更多人持犬儒立场：dspillett 认为"定速"指的是那些危险的开源和中国竞争对手，本质是在制造监管俘获；RcouF1uZ4gsC 认为多家本应独立的公司同时喊"为前沿定速"，像是在规避"企业同步削减研发属违法"的规定，是企图卡特尔化；filoeleven 把它比作 20 世纪白炽灯泡的太阳神卡特尔。也有人提醒大家先读原文：johnfn 说"这整个帖子没人读过 Amodei 那篇文章标题以外的内容吗？他写了很明确的一组行动"，usef- 觉得"整条子线程都在批评'为前沿定速'这几个字太模糊，好像标题下面没有正文一样"。

这条线还衍生出一场语言学辩论：pacing 到底是什么意思？mukmuk 说这个短语听起来"油腻又古怪，像是 Claude 自己生成的"。有人说这就是赛车里的安全车（pace car）、马拉松里的配速员；rhet0rica 分析得最透：英语里 "pace yourself" 是个温和提醒别太快的习语，"但它已经变成了对鲁莽的告诫，而不是对任何具体速度的承诺"，所以 Anthropic 可以对公众说要慢下来，同时对投资人说会审慎推进，"这个口号本身就是模棱两可"。sumeno 作为英语母语者恰好理解成了相反的意思："给一场比赛定速，意思是领跑者决定节奏，这暗示的是他们打算保持领先，而不是放慢。"nradov 注意到美军现在把中国称为 "pacing threat"，意思是需要尽快推进军备竞赛；多位用户说第一反应是"边防军在边境来回踱步"。

**文风：用户最在意的改进，评价两极。** 很多人明说这是他们唯一关心的点。gekoxyz 说 Opus 5"没法用，我们团队大多数人回退到了 Opus 4.6"；mavamaarten 抱怨再多的指令、记忆和技能都没法阻止 Claude 每两句说一次 "genuinely"。好评者给出了具体对比：desmondl 问 Opus 5.5 能不能用后端 API 返回的日期作为"今天"的定义，它答："你的假设成立，提交历史也支持这一点……有一个问题：信任后端只有在客户端的 currentSeasonDay 副本是最新的时候才有效，而现在它常常不是。"他说 Opus 5 大概会回一段"疯魔的说教"，并模仿了一段："这个假设在所有权上是对的，在占有上是错的……来源是对的，观察是陈旧的，这两者并不矛盾。不要为了解决新鲜度缺陷而重开所有权决定。"sunaookami 说"比 Opus 5 好了一个量级，输出终于又能读了"；notatoad 说它写起来像 Gemini；hgo 讲了一个让他印象深刻的时刻：Opus 5.5 指挥几个 Sonnet 子智能体做大规模改动时主动报告"这没按计划进行，Sonnet 智能体没有合适的判断力……我建议终止它们、回滚它们的改动，我派一个 Opus 智能体来做，会慢一些但会做对"，"每次和 Opus 5.5 交互都感觉像在和一个成年人说话"。

但差评也很具体。epicepicurean 贴出一段自认为很清楚的输出，californical 和 croemer 在互不知情的情况下挑出了完全相同的两句作为"人类永远不会这么写"的例证："重写由发布者声明，从不从重叠推断""NULL 意味着脏，DELETE 就是围栏"。ascendantlogic 用了一小时说"和 Opus 5 一样啰嗦，还用了 4 次 load bearing"；MattyRad 收到了一句"截断量化器撞了两个橙子"，翻译过来意思其实是"检查文本是否过长的代码和给文本上色的部分冲突了"。bobbylarrybobby 发现一个有意思的现象：Opus 5.5 在代码库里被 Opus 5 写过大量注释的部分会染上那种文风，"5 碰过的地方会有病毒性"；hypfer 说 GLM-5.3 也一样，看过一段 Opus 5 写的补丁后，"整个会话都变成了 Claude 腔，感觉智商掉了 20 点"。至于原因，penagwin 认为是后训练最后阶段的强化学习只在乎分数，只要不影响编程表现，文风变成什么样都行；adastra22 的说法是从 RLHF 转向 RLVR，"更容易刷榜，但基准不覆盖人类可用性"。

**价格：几乎一致欢迎，但"便宜 40%"有争议。** GodelNumbering 指出 Opus 5 是 OpenRouter 上花费最高的模型，很可能是 Anthropic 最大的收入来源，"能力提升还被迫降价，说明了市场的一些情况"。bleonard 注意到以往各家的缓存读取都是基础输入价的 10%，这次是 5%，"长的智能体会话变便宜了，一次性调用价格不变"；Espressosaurus 说他的交互会话缓存读取占比在 95% 到 98%。drbscl 引用 Artificial Analysis 称 Opus 5.5 在最大档反而更啰嗦；nl 仔细看了数据：max 档 token 比 Opus 5 多约 38%，high 档少约 21%，"大多数人用 high 和 xhigh"；persedes 算出 medium 到 max 各档的成本中位数下降约 38%，"离宣称的 40% 不远"。qlte 贴出 Artificial Analysis 的单任务成本：Opus 5.5 medium 1.34 美元，GPT-6 Astra high 1.76 美元，Opus 5.5 high 1.82 美元，提醒已经在用 Codex 的人差距没有看上去那么大。gwd 分享了一个邮件列表补丁审查的小样本测试（12 个补丁、14 个问题）：Opus 5.5 找到 8 个，花费 15.40 美元；Fable 5.1 找到 7 个，66.34 美元；Opus 5 找到 6 个（他后来更正花费为 58.19 美元）；Sonnet 5 找到 2 个。但也有反例：rmunn 让它做代码审查，结果五个问题里有四个行号是错的，其中一个指向一个只有 160 行的文件的第 848 行；jdw64 说在 Max 5x 计划上用同样的任务，不到一小时就撞上了五小时上限。

**安全防护的误伤是最大的负面反馈。** searine 说"Claude 现在对生物信息学基本没用了"；sys32768 说 Fable 和现在的 Opus 5.5 都拒绝回答他读大学的孩子关于阿尔茨海默病和免疫反应的问题，而 ChatGPT 6 Pro 毫无问题；Retr0id 贴出了 Claude Code 的提示："Opus 5.5 (1M context) 的防护标记了此会话……Opus 4.8 将代替回答"，后来还发现无害的 bash 命令被标成"第三方攻击"；mintik 说一整天没有一个嵌入式、驱动或系统级任务能不被标记为 [Cyber] 就完成；user43928 从系统卡里摘出一条：针对"某些 ML 加速器的内核开发"等前沿 LLM 开发能力也有分类器，触发时回退到 Opus 5（dannyw 说据他所知只针对华为等中国芯片）。flyinglizard 认为这在把需要前沿能力的国防、网络、生物用户推向中国模型。也有人为防护辩护：toss1 和 b112 指出网上可以订购基因、高中生都在做基因编辑竞赛，frabcus 引用了 Anthropic 9 月威胁情报报告里"五个可能支持生物武器开发的案例研究"。

**"蒸馏攻击"的措辞引来了"双标"批评。** Retro_Dev 说："如果这真的不道德，那么他们定期未经同意抓取我的个人网站、未经授权使用作者、博主、维基百科贡献者的内容，也同样不道德。"ACCount39 给出了一个技术上相当扎实的反驳：一家实验室花巨资做前沿研发和昂贵的强化学习，另一家直接拿推理轨迹做中训练和后训练，就能以一小部分成本达到九成效果；这种蒸馏能在预训练和最终表现之间"铺平落差"，让模型直接学会"怎么当一个 AI"。他同时承认中国实验室也贡献了大量真正的训练技术和架构创新，"但能从前沿蒸馏，让他们获得了巨大的效率优势"。deaux 的回应很简短："所以问题就是……做了 OpenAI 和 Anthropic 当初做过的事？"

**基准与 Fable 的定位。** km144 认为这次发布会让 Fable 很难卖，而"基准分差已越来越不可靠"这句承认本身就是个大问题。felixgallo 列出了表中各基准的出品方（斯坦福与 Laude、Cognition、Cursor、Artificial Analysis、Zapier、CAIS 与 Scale AI、港大 XLANG Lab、Surge AI 等），反驳"不是独立基准"的说法。booty 猜测真实世界与基准背离的原因：真实代码库充满技术债，而且"成功"涉及可维护性、有没有过度设计、如何处理模糊矛盾的需求，这些都难以测量。port3000 分享了一种用法："我相信 Opus 5 本来就不是给人类对话用的，它很擅长执行，但应该由 Fable 这样的模型来跟它说话。"
