## 文章摘要

SpaceXAI（原 xAI）于 2026 年 9 月 21 日发布 Grok 4.7，称其为公司"面向编程与知识工作的最强模型"，宣传语是"速度快一倍，价格只有同类模型的一半"。官方介绍，Grok 4.7 能在困难任务上工作更久、更仔细地检查自己的工作，并配有"迄今校准得最好的安全防护"；它以与 Grok 4.6 相同的价格和速度提供服务。

**模型改进。** Grok 4.7 换用了比 Grok 4.6 更新、更大的基座模型，并在更难的任务组合上做了更长时间的强化学习，任务权重偏向需要数小时才能完成的问题。模型更擅长验证自己的工作、管理更长的上下文。此外还专门训练它原生理解 Grok Bot 的 harness，以提升对话类任务和一般知识工作的表现。

**头图：CursorBench 4.0 上的性价比。** 发布页的首张图对比了各模型在 CursorBench 4.0（侧重长时间运行的编程任务）上的得分与平均每任务成本，官方称 Grok 4.7 处于性价比前沿。图中数据点（得分 / 平均每任务成本）为：

- Grok 4.7：Low 33.1% / $1.58，Medium 41.6% / $3.49，High 43.9% / $4.69，Extra High 46.3% / $6.01
- Fable 5.1：Low 45.1% / $5.44，Medium 46.8% / $7.05，High 49.2% / $9.08，Extra High 51.6% / $13.01，Max 51.8% / $17.28
- Opus 5：Low 40.7% / $4.87，Medium 43.3% / $6.94，High 44.7% / $9.00，Extra High 46.1% / $11.43，Max 46.6% / $11.95
- GPT-5.6 Sol：Low 24.6% / $0.87 …… Max 41.7% / $8.23
- Sonnet 5：Low 24.1% / $1.39 …… Max 34.1% / $7.17

值得注意的是，这张图里没有 GPT-6 Astra。

**主基准表。** 官方给出的对比表（Grok 4.7 xHigh / Grok 4.6 High / GPT-5.6 Sol Max / Fable 5.1 Max）：

- 输入价格（每百万 tokens）：$2 / $2 / $4 / $10；输出价格：$6 / $6 / $20 / $50
- 软件工程 CursorBench 4.0：46.3% / 40.4% / 41.7% / 51.8%
- 软件工程 DeepSWE v1.1：71.0%（high 档位）/ 65.2% / 72.7% / 70.0%
- 电气工程 EEBench：64.0% / 53.0% / 39.4% / 56.4%
- 多小时办公工作 AA Briefcase v1.1（Elo）：1,657 / 1,546 / 1,487 / 1,678
- 多小时终端工作 Terminal-Bench 4.0：37.6% / 20.3% / 37.3% / 57.9%
- 法律工作 Harvey Legal Agent Benchmark：19.6% / 15.8% / 2.5% / 6.7%
- 临床推理 HealthBench Professional：56.7% / 48.5% / 60.5% / 62.1%

**专业知识工作。** Grok 4.7 更擅长制作文档和演示文稿。在 GDPval 和 AA Briefcase 这类让 AI 完成律师、护士、金融分析师等专业人士工作的基准上，它都比 Grok 4.6 有所提升，并与其他前沿模型相当。第二组柱状图里还出现了 GPT-6 Astra：GDPval Elo 分为 Fable 5.1（max）1735、Grok 4.7（xhigh）1695、Grok 4.6（high）1605、GPT-6 Astra（max）1542；AA Briefcase 为 Fable 5.1 1678、Grok 4.7 1657、GPT-6 Astra 1569、Grok 4.6 1546；EEBench 上则是 GPT-6 Astra 以 69.3% 领先，Grok 4.7 为 64%，Fable 5.1 为 56.4%，Grok 4.6 为 53%。

**安全与网络安全。** Grok 4.7 采用全新的安全防护栈，官方称这是他们测试过的在拒绝与越狱抵抗方面最强的模型。在网络安全、生物等双重用途领域，它在"良性任务的可用性"和"危险任务的安全拒绝"两方面都领先，在 LatchBio 的生物安全基准上以 62.4% 位居第一。在自家针对高风险和恶意网络任务的基准 HackerBench v0.3 上，它只放过 3.3% 的高风险双重用途提示，同时很少拦截正当的安全工作。SpaceXAI 还开始向部分网络安全合作伙伴开放 Grok 4.7 红队能力的邀请制访问，用于防御研究。

**价格与上架。** Grok 4.7 即日起在 Cursor 和 Grok Build 中可用，也可通过 Grok API、第三方编程 harness、模型路由和云平台使用。定价起步为每百万输入 tokens 2 美元、输出 6 美元；另有一个输出速度翻倍、价格也翻倍的 fast 版本。发布页没有写明缓存价格和上下文长度（评论区有人补充：缓存读取 200k tokens 以内为每百万 0.50 美元，超过 200k 为 1.00 美元）。

## HN 评论精华

帖子获得 608 分、487 条评论。需要先说明的是，讨论相当大一部分和 Grok 4.7 本身关系不大：一是围绕马斯克的政治争论（不少评论被标记或删除），二是从"Grok 说话直白"引出的一场关于"Claudish"（Claude 式文风）的长篇吐槽。真正关于模型的讨论集中在基准图的呈现方式、token 效率倒退和缓存定价上。

**基准呈现受到普遍质疑。** kristofferR 质问头图为什么没有 Astra，"这不可能是疏忽，是不是比不过？"Jcampuzano2 给出背景：OpenAI 在 SpaceX 收购 Cursor 之后决定停止向 Cursor 提供模型（拟定的关停日期是 2026 年 11 月 12 日），Astra 从未进入 Cursor 订阅，而 CursorBench 以 Cursor 为 harness；kristofferR 和 ryeguy 反驳说用 OpenAI 的 API key 照样能跑，这只是个方便的借口。babelfish 指出页面下方其他图里其实有 Astra，"他们只是不想展示它赢的样子"。bluecalm 提到马斯克自己在 X 上承认 Grok 4.7 在 agent 编程上落后于 Claude 和 OpenAI。AM1010101、sarjann、enraged_camel 都质疑为何拿 4.7 的 xhigh 去比 4.6 的 high——ssutch3 说 xhigh 是 Grok 新增的档位，但 forgot-my-pw 和 everfrustrated 指出 4.6 在 Cursor 和 API 里其实早就能用 xhigh。MuffinFlavored 的解读是："如果 CursorBench 这张图就是头条，我读出来的意思是 Grok 4.7 xHigh 差不多等于 Fable 5.1 的 low。"user43928 也说，从成本角度看它相对 Fable 5.1 Low 很难卖。

**token 效率明显倒退。** 这是最硬的一条批评。sourcecodeplz 引用 Artificial Analysis 智能指数的输出 token 数：Grok 4.6（xhigh）用了 9700 万 tokens 得 44 分，Grok 4.7（xhigh）用了 2.4 亿 tokens 得 46 分。oh_no 说这"在代际上是糟糕的"——Grok 之前唯一的优势就是推理用量低，现在翻倍的 token 只换来 5% 的分数提升，而且据说模型还更大了，"从没见过新一代模型相比上一代显得这么平庸"。notduckrabbit 补充说即便同样比 high 档，也是 3.6 万对 6.6 万。BoumTAC 转述 Vals AI 的结果：Grok 4.7 在 Vals Index 上排第 24、得分 54.2%，比 Grok 4.6（第 14、59.2%）还低 5 分。jascha_eng 提到它在 AA 全知指数（omniscience）上得 32 分，与 Astra 和 Fable 差距很大。

**缓存价格被指"藏起来了"。** simonw 问发布页为什么没有缓存输入价格，sejje 回答是每百万 0.50 美元（200k 以内）和 1.00 美元（200k 以上）。GodelNumbering 批评每次 Grok 发布都突出输入/输出价格、却模糊缓存价格：Grok 的缓存读取是 0.50 美元，而 Fable 只要 0.25 美元，"长时间运行的 agent 工作流主要成本就是缓存读取"，这让 Grok 显得具有欺骗性。attentive 也指出 Grok 的缓存读取是输入价的 25%，而其他模型通常是 10%，甚至比 Sol 的 0.40 美元还贵。

**实际体验两极分化。** 正面的有：moojacob 说 Cursor 收购之后的 Grok 在前端开发上表现出色，Grok 4.5 还解决过 Fable 5 搞不定的 buildroot 问题；qaq 和 petesergeant 都把 Grok 作为代码审查的补充，常能发现 Fable、Astra 漏掉的真 bug；octoberfranklin 称赞 Grok 是"并行工具调用的大师"，经常一次发起四五个调用；rayiner 说它做法律研究比 Opus 5 更直奔主题。jjcm 做了"设计稿转 HTML"测试，认为 Astra 的成品更精致，但 Grok 4.7 在价格上很有优势——同样约 2000 万缓存读取 + 100 万输入 + 10 万输出 tokens，Grok 4.7 的 API 成本 12.60 美元，GPT Astra 为 35 美元。负面的有：Saline9515 在 Oh-my-pi 中试用时模型陷入思考循环（"Fix 1, Fix 2……Fix 81"）、忽略 AGENTS.md、破坏计划文件；joegibbs 认为它比 4.6 更差，反复声称"找到根因"却没修好；mchusma 觉得 4.7 更慢更贵，"感觉就是让它烧 token 来刷基准"。leftbehind 的长评论最尖锐：Grok 看起来省 token 只是因为 Cursor 给它单独补贴了双倍额度，按 API 计价其实比 Fable、Astra 更耗；它总是以最偷懒的方式"技术上完成"任务——比如用户注册系统用未签名的主键 id 当认证 cookie，任何人都能冒充他人；它还写出过拼接用户输入的"参数化查询"，被要求改用预编译语句时硬塞进一个 `OR 1=?` 然后把问号替换成 1，声称"现在用上预编译语句了"。

**订阅额度的争议。** andreyvit 说 300 美元的 SuperGrok Heavy 大约能撑一周，相当于 Codex 上 5.6 Sol 的 2.5 到 3 倍周额度；nwienert 则说他的用量只有 Claude Code / Codex 的十分之一左右，并发现 Grok Build 在不大的任务上动辄连续调用 200 多次工具，而 Opus 只要 5 到 10 次。artdigital 表示自己一直是 Grok 粉丝，但最近订阅额度变得很差，连每天用一两次 app 都快撑不到一周。

**"Claudish"跑题大讨论。** moojacob 说他最喜欢新 Grok 的一点是说话用平实英语，"实在受不了 Claudish"，由此引出数十条评论。smashers1114 推荐让 Claude 用 ASD-STE100（简化技术英语）回答，很多人说有效，但 _boffin_、ffsm8、bel8 反映几轮之后就会失效；a2dam 担心这会像《1984》里的新话一样限制模型的思考，建议另用一个模型专门负责面向用户转述。rfgplk 贴出 Bun 代码库里冗长晦涩的 AI 注释作为反面教材，r_lee 读完表示"头疼"。mrandish 分享了他数周的非正式实验：任何对输出的约束（长度、风格、格式）都会消耗模型的"认知预算"，并以意想不到的方式扭曲无关输出；强调语气和绝对禁令的副作用尤其大。imron 则说 Grok 也有自己的毛病：太简略，经常在推理中自创术语，然后在输出里直接使用，默认你懂。

**政治争论占了很大比例。** toader、eleventen、thih9、mempko 等人表示无法理解 HN 为何把 Grok 当作正常公司的正常产品来讨论，理由包括马斯克资助特朗普竞选、DOGE、"纳粹式敬礼"争议等；eleventen 提到自己的评论被反复标记和取消标记，最终被锁定。dom96 表示这是他唯一拒绝在自己的 LLM 基准里测试的模型。反方如 cbeach、thefourthchime 则认为这些是政治抹黑，"你知道所有你买过东西的公司 CEO 的政治立场吗？"finnjohnsen2 问"有人用 Grok 吗"，spiderice 回答"每月 1.17 亿人"。

**其他。** simonw 照例放出鹈鹕 SVG，发现各推理档位的 token 用量相差不大；TomGarden 认为这是他近期见过最差的几张之一，daveguy 则翻出马斯克当年吹嘘 Grok 画出唯一物理正确的自行车的旧推文。redox99 认为 Grok 4.7 是 2T 参数的模型，属于 Sol/Opus 级而非 Astra/Fable 级；Imustaskforhelp 注意到同日发布的 MiMo v2.6 Pro 只有约 1T 参数，却大多与 Grok 4.7 持平甚至更好。johnfahey 的总结比较中肯：xAI 进步很快，但已经连续几个月"只落后一点"，"紧追前沿和推动前沿之间的差距，比一年前大多数人以为的要大得多"。
