## 文章摘要

这是一条由 **genekrapivin** 发起的 Ask HN，29 分、39 条评论。原帖只有三句话：

> HN 是一个极好的创业者社区。
>
> 我们这群人喜欢透明度、数字，喜欢拆解自举（bootstrapped）的商业模式。
>
> 你现在在做什么项目？分享你的胜利、失败和技术栈。如果你愿意，也分享一下月度经常性收入（MRR）。

**这次讨论的实际走向**：需要说明的是，这条帖子没有变成一场关于自举商业模式的深度讨论。它基本上是一份**产品清单**——绝大多数回复是一段自我介绍加一个链接，真正响应「分享数字」号召的只有少数几位，而且金额都很小（几百到一千美元量级）。评论区里还出现了一场关于减肥 App 效果宣称是否可信的激烈对撕，以及一个小插曲：大量评论被 HN 自动折成了 dead 状态，连提问者本人都表示不解。

即便如此，这份清单本身有观察价值——它相当直白地反映了 2026 年秋天一个独立开发者会去做什么、用什么技术栈、以及最常在哪里卡住。

**本次清单反映出的几个模式**：

1. **AI 相关的工具占了显著比例**，但大多不是「AI 产品」，而是「AI 时代的配套工具」：给各家 agent 做共享记忆层的笔记本、把文档转成结构化输出的 RAG 提取器、检测「AI 引擎对你的品牌了解什么」的 GEO 工具、用 agent 三件套来起草/审查/红队合同的平台、在终端里可视化 codex 在干什么的按钮 CLI。
2. **浏览器内本地处理成为一个明确卖点**。有两个视频剪辑工具（一个面向「多次重录的口播内容」的预剪辑器，一个基于转录文本的视频编辑器）都强调整条流水线包括语音识别全部在浏览器标签页内运行、不需要账号、数据留在本机。
3. **「反订阅、反数据外流」的定位反复出现**：一个明确承诺「不含任何 AI、没有东西会泄露你的日记条目」的日记应用；一个自托管的容器镜像漏洞持续监控；一个明确说「目标是让价格未来几十年保持稳定，同时让切换到自托管方案变得容易」的网页归档服务。
4. **传统的、无聊的、垂直的 B2B 工具仍然健在**：工时填报、HTML 转 PDF 的 API、员工合同与劳动法问答、草坪养护建议、家庭物品清单（面向保险理赔）、量化选股回测、内部人交易追踪。
5. **技术栈相当分散**，没有明显的统一答案：Flutter + Rust、Go + Vue + Postgres、Elixir/Phoenix、Ruby on Rails、Next.js + ASP.NET Core + SQLite、Python(Sanic) + Pyppeteer、Cloudflare + Hetzner + React、Java + Cython + Numba、手写的 three.js 引擎。选择更多取决于作者的个人偏好而非产品需求。

## HN 评论精华

由于这条帖子的性质，「评论精华」这里主要挑出**真正有讨论价值的交互**，而不是罗列链接。

### 一、最有价值的三条建议：都来自同一个人

**miguelfrreg** 是评论区里唯一系统性地给别人提商业建议的人，而且每条都切中要害。

对一个报告 700 美元 MRR 的作者（**ahmgeek**，voklit.com），他问：

> 恭喜做到 700。真诚地问：你是怎么定到现在这个价格的？有没有试过往上调？我的经验是，自举创业者第一次定的价格，通常是他们自己愿意付的那个价——而那几乎总是太低了。

对做网页归档、坦承「$0 MRR、太小众、竞品都是老牌玩家、现在还不太能变现」的 **flippant**（memoryhole.app），他给了本帖最锋利的一条反馈：

> 「还不太能变现」通常是定位问题，不是产品问题。「给所有人用的网页归档」很难收费。「给某个有合规或法律理由必须留存页面的群体用的网页归档」——代理机构、记者、追踪竞品价格的电商团队——就非常好收费。今天在用它的都是些什么人？

对做免费职位聚合、明确表示不打算变现的 **gr1m**（atsradar.com，扫描 3 万个招聘网站、已积累 30 万条职位、300 多用户、自己贴钱运营），他的建议是：

> 喜欢这个想法。我的坦率意见，姑妄听之：网站文字过于饱和，缺少留白（空气）和视觉元素。为什么不变现？不是向求职者收费，而是从雇主侧。你可以看看大厂的报价是什么样的。另外你不是已经给 API 定了价吗？那块怎么打算的？

另一位 **wakaru44** 给网页归档项目的反馈同样直接：「我从没想过会有人为这个付费。我本地就有一套，不需要 SaaS，而且它能接进我的卡片盒笔记法。就算我认识的那些确实有这个需求的人，也不愿意付钱，他们宁可忍受复制粘贴。在我看来这更像是一个功能而不是一项服务，所以那些集成才是有意思的部分。祝好运！」

### 二、一场关于「保证效果」的对撕

评论区第一条回复（**faangguyindia**）为一个宣称「2-3 周内保证减重或增重，在减重上击败 GLP-1 类药物」的 App 打广告（声称 17000+ 用户，技术栈 Flutter + Rust）。

**OpenMac** 立刻要求出示证据：「我看到了这些主张，但没看到支持它们的证据。能分享一下你的『保证』基于什么吗？有没有公开可得的数据显示你的 App 能保证效果并且优于 GLP-1？我搜了但什么都找不到。」

作者的回应没有正面提供数据，而是转向攻击提问者的动机和竞品的透明度——指责对方为竞品 MacroFactor 工作，并反过来质疑后者公开的算法精度数据「依赖未披露、不可独立验证的内部数据」，打了个比方：「就像一个学生说『我考了 99 分』，但不给任何人看试卷和答卷。你无法独立验证这个分数是否真的反映了他的水平。」他给出的己方证据是「17000+ 用户的自有数据」和「2000+ 人的用户群里的独立用户报告」。

这场交锋本身没有结论，但 **mattbrewsbytes** 把它拉回了一个有意思的技术问题上：

> 这类 App 的底层逻辑很简单：你必须根据变化调整卡路里目标，必须边走边重算。
>
> 我发现的是，通过「消耗卡路里」来追踪活动量极其没有生产力——不同 App、不同设备、不同活动给出的「消耗」差异巨大。有没有关于如何计算任何活动的卡路里消耗的科学研究？有没有在受控环境下研究一些简单的东西，比如一个成年人以每小时 3 英里的速度在平地走 1 英里？感觉这件事比「一个苹果的平均卡路里」要难钉死得多。个人经验：我一停止追踪活动量，体重秤就开始动了。

### 三、被广泛观察到的一个共同困境：用户来了但不用

**davedx**（octoloops.com，面向独立开发者/vibe coder 的外联工具）交出了本帖最坦诚的一份失败报告：

> 不幸的是进展不顺利：人们注册了，然后就不用这个 App。坦白说我已经想不出还能试什么了。

**radio879**（buttons CLI）的处境类似但更有具体数字：「大家确实买了 v1，而且还在用，但大部分是免费用户。很难让人付任何钱……不过我从 v1 确实赚了大约 1000 美元。人们每天还在用它，尽管随着 agent 变强它已经没以前那么有用了，但偶尔还是派得上用场。至于新的 buttons cli，我连让人免费试都做不到，哈哈。我自己在用，用来看 codex 在各个终端里都干了什么（而且我喜欢点按钮，也喜欢能比 Google 更快地生成命令）。」

**gr1m** 的情况则是另一个极端：产品有人用（300+ 用户，30 万条职位），但他明确选择不收费，自己承担运营成本。

### 四、一个说得最清楚的技术栈自述

**abejora**（工时填报软件）是少数详细谈了技术选择的：

> 我们用 Elixir 和 Phoenix 做应用，体验相当惊艳。这和你在很多地方看到的「React/JS 店面 + 传统后端语言 REST API」是非常不同的路子，而且它是函数式语言。这绝对是新东西，也是我们推荐你去体验的东西。
>
> 托管方面我们也从一台简单的 Debian 服务器加标准 CI/CD 流水线，换到了一套更奇特的配置：现在跑在 Talos Linux 上的完整 Kubernetes 集群，用 Flux 做 GitOps CI/CD。这对我们也是新东西，跑通有点挑战，但现在看它运转起来很棒。

他们的三点差异化也值得记下来：尽可能快且好用（因为没人喜欢填工时），「民主化定价」（很多竞品把好功能锁在贵套餐后面，按人头计价很快就变贵），以及产品源于自身需求。他还开了个有意思的口子：给产品提意见的人可以免费用 6 个月。

**cx42net**（pdfshift.io，HTML 转 PDF/图片的 API）的定位则是本帖最「Unix」的一条：「我试着遵循 Linux 的理念：只做一件事，但做好。我只能希望我做到了。」技术栈是 Python（Sanic 框架）配 Pyppeteer。

### 五、关于被大量折叠的评论

**cx42net** 注意到一个现象并提了出来：「这里有很多 dead 评论。我很好奇发生了什么（我测过那些链接都是通的，所以不是这个原因。那些帖子看起来也符合 HN 指南，至少没有辱骂或恶意内容）。」

提问者 **genekrapivin** 回应：「我也不理解，也很好奇。肯定是某种没有文档记录的启发式规则。」

这大概是这条帖子最真实的注脚：一个鼓励大家贴自己产品链接的帖子，在一个厌恶自我推广的社区里，本身就处在一种微妙的紧张关系中。
