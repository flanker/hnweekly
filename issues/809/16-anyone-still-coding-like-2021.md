## 文章摘要

68 分、93 条评论的一条 Ask HN，提问者是 HN 老用户 **sph**。原帖很短，但情绪很重：

> 用 LLM 只做调研这件事我可以睁一只眼闭一只眼。
>
> 这些天我感觉自己是唯一一个写软件方式完全没变的人。比起去管理 agent，我宁愿转行。但我现在正好待业（合同结束了），想知道到底还有没有一个正常的地方可以工作，还是说真的到了该转行的时候。

**背景**：这条帖子发布在 2026 年 9 月——距离编码 Agent 大规模进入企业已经过去两三年。提问者的困境有两层：一层是个人偏好（不想把工作变成审阅 AI 输出、当「经理」），另一层是很现实的求职压力（合同结束、市场上似乎每个岗位都默认你用 agent）。

这条帖子的回答基本可以归为四类：**「有，去这些行业」**的实用情报；**「我在硬扛」**的现场汇报；**「你错了，赶紧改」**的现实主义劝诫；以及**「怎么在 AI 时代保持脑力」**的方法论。值得注意的是，讨论后半程完全跑题到了「为什么 C 级高管这么急着推 AI」和「因为拒绝用 LLM 被解雇算不算政治性理由」上，火药味相当足。

## HN 评论精华

### 一、「还有，去这些地方」——实用情报

这是提问者最想要的答案，而且确实有人给了具体方向。

**lopsotronic** 的回答最具体也最有画面感：

> 兄弟，去防务行业看看就行了。
>
> 不光前沿模型在大楼里任何地方都是禁用的\[1\]，任何在你笔记本上跑的开放权重模型也得过一个相当严格的审批流程。我们现场没有 GPU 能跑任何能跟 Claude 竞争的东西，所以你本地那些傻乎乎的 7B 小模型不可能接管比如一套复杂的 3D 视觉跟踪算法的编码。
>
> 所以如果你想像 1998 年那样写代码，跳进你的 DeLorean，来死亡商人这边吧。
>
> \[1\] 往里面放任何跟产品沾边的东西都是当场开除的罪名。在答复回来之前保安就会拿着箱子来帮你收拾东西。

**bthallplz**（加州州政府）：「公共部门/政府是稳妥的赌注。政府对没有经过 5 年以上验证的技术和工具有强烈的抵触。我怀疑大多数政府程序员的实践水平还没达到 2021 年的最佳实践。」

**guywithahat** 提供了一个有趣的反视角——他在同样的防务/涉密领域，但是站在相反的立场：「讽刺的是，我不高兴的是自己还在像 2016 年那样写代码。我一直在推 AI 工具，也说服了管理层这是个好主意，但他们现在在玩『选最喜欢的供应商』的游戏，工具迟迟不到位。写代码确实更有意思，但这不是有意思不有意思的问题，而是交付高质量产品的问题——现在没有 AI 工具谁都做不到这一点。明知自己在练一门过时的技能，挺让人沮丧的。」（**sph** 本人回了句「Citation needed」。）

**alexjplant** 泼了一盆冷水，指出防务行业的「慢」是有代价的：「防务承包不是对 LLM 有抵触，而是对任何威胁现状的事情有抵触。很多地方稳稳地落后行业中位数 5-10 年，或者因为莫名其妙的理由被困在专有技术栈上。比起 Claude 不听指令，我更不愿意被迫用一个已经被供应商实质上停止支持的专有框架写软件，然后用 Citrix 把软件部署到 Windows 机器上、还要经过一个月的手工测试。前者只是有点烦人，后者是对你职业流动性和尊严的严重威胁。」

其他提到的领域：**cowanon77** 在受严格监管的美国医疗器械公司（但明确说这是暂时的，C 级已经下了推广 AI 的指令）；**mysterydip** 做微控制器和需要手写 bit-banging 驱动的硬件（「LLM 不太可能有足够数据自己写出这些东西」）；**gottagocode** 在网络安全做 lead，目前只把 copilot review 接进 pipeline；**yurish** 提到能源行业「非常保守，不用 AI」；**voakbasda** 在一个**合同明文禁止 AI 编码**的嵌入式项目上，原因是 AI 版权问题尚未解决而客户是在意这件事的政府部门。

**dd8601fn** 的处境很说明问题：「这样的地方多得是，你只是在这里听不到而已。我这儿有些杂活，Claude 订阅几分钟就能干完，而我们要干几个月。但我没有权限跑那种东西，所以我不跑。奇怪的是我们的外包商可以——他们把这条写进了合同里。这真的不公平。」有人问他是不是意味着管理层想用外包商替换他，他答：「当初雇他们的那些人肯定是这么想的。结果没走到那一步，他们现在也不在了。不过中间还是折进去不少人。」

### 二、现场汇报：在 AI 化的团队里当人

**squalvj** 的描述可能是全帖最惨的：

> 我们公司给每个人发了 Claude Code。赢下一场争论的方式变成了「Claude 说……」，每天面对这种破事真的很烦人。代码库变成了一个只有上帝和 AI 知道是什么样子的黑盒，每个函数上面挂着四行段落，历史性地描述从过去到未来的所有改动。
>
> 我在考虑辞职因为我受不了了，但别的地方看起来也没好到哪去。……我受够了当我经理和 AI 之间的中间人。

**localhoster** 提供了更具体的技术后果：「我工作场所大多数代码今天是 AI 写的，情况不太好。所有实现决策这些天基本由 Claude 决定。我们有那么多没用的测试、那么多重复代码，任何改动哪怕只有几行都会触发额外 25-50 个文件的变更，因为一切都写得太糟了。我听说 AI 之前也有这种情况，但现在糟糕得多。最后我认为归结为三件事：**在意**——AI 之前你至少得有一点在意；**强有力的领导**——AI 精神病在我们 C 级像疾病一样传播；**所有权**——现在完全没有，每次关于某件事的对话都以『但 Claude 觉得/说』开头。真希望能回到过去。」

**timbaboon** 的遭遇则是纯粹的组织混乱：「我们被要求使用 AI，但能不能用 ChatGPT 或 Codex 反复横跳，搞得大家完全没有方向。今天允许，明天 IT 安全把它封了。本地模型也不允许。我还是自己写所有代码，因为 IT 每隔一天改一次主意，我不可能跟着改工作流。尽管如此，CIO 的指令是明年 70-80% 的代码必须由 AI 生成。而我上次查的时候，公司只有 2% 的人真的拿到了 codex 授权。所以我也不知道该说什么。」（**sph** 回：「听起来像地狱。」）

**icedchai** 和 **eudamoniac** 给出了同一个策略：假装喝下了这杯 Kool-Aid。前者：「我在假装喝下 kool-aid，装作对 agentic coding 有兴趣，同时想别的出路。个人项目上还行，但在职业上，我真心讨厌审阅 slop、被人发来十几页没人读过的垃圾文档。」后者更实用主义：「作为同样的逆行者，我为你的决心鼓掌。但既然本来就没人质疑你的产出，你更应该假装在用。这样你很快会成为最（唯一）懂行的开发者，可以拿这个换晋升或新工作。我知道假装相信自己不相信的东西很恶心，但这件事可能严重到值得这么做。我最近面试时按每家公司的态度说他们想听的话；我拿到了新工作；我在新工作假装在用 AI。要么我们是对的、AI 强制令被撤回，我们处境很好；要么我们错了，那我们得死死抓住饭碗。」

### 三、被解雇之后：最激烈的一场争论

**vermilingua** 的自述引爆了本帖最长的子线索：

> 我在任何场合都不碰 LLM（只要我能避免的话，它们经常被硬塞到你面前）；直到不久前一切都还好好的。我因为这个立场被解雇了，不是因为绩效原因（官方声明说对我的产出没有任何顾虑），纯粹是政治原因（不服从管理，拒绝用 LLM 替我干活）。
>
> 过去几个月我看到要求/需要 LLM 使用的招聘广告越来越少，所以我觉得潮水可能正在转向我们这边；但我开始感到压力了。这是我第一次考虑自己采取绝对主义反 LLM 立场可能是「错的」，尽管我觉得这只是失业在消磨我。

**nater5000** 的回应措辞最重：「即便抛开语境，你不做雇主让你做的事，本来就该被解雇。因为不服从被开除不能算『政治性』，它就是绩效原因的极致——你字面意义上拒绝做你的工作。……未来面试时一定要好好想想怎么包装这件事，因为知道你在有意违抗直接指令，对我以及任何有常识的面试官来说都是当场 pass。……如果你有道德上的问题，那你可能真该考虑转行。但如果你只是卡在某种对『手艺』的奇怪自尊上，那你需要退一步认真体会一下，你的职业对愿意付你钱的人到底意味着什么。」

反驳来自四面八方：

- **em-bee**：「有点苛刻了。工作是解决问题、实现方案。作为开发者我应该对如何完成有一定的自由度，能选择我认为最适合这个任务的工具。可以有约束，但把『用 LLM』当成约束说不通，因为 LLM 影响的是过程而不是结果。」
- **archagon** 引用了已故喜剧演员 Mitch Hedberg 的段子作类比——好莱坞总让脱口秀演员去写剧本，「这就像我努力成为一个好厨子，他们说『行，你是厨子，你能种地吗？』」他补充：「LLM 辅助编程基本上是和软件工程完全不同的职业，不是每个人都想干那个。」在另一条回复里他说得更直白：「工作是造小部件，不是用特定工具造小部件。这什么时候成过规矩？我的老板从来没在意过我用什么编辑器。……放轻松，别给这个行业当门卫。也许听起来很奇怪，但我认为总会有不依赖 LLM 的细分领域存在。」
- **chaosharmonic** 拆解了「绩效 vs 政治」这个二分法：「996 是办公室政治。强制回办公室是办公室政治。薪资保密是办公室政治。其中一些会变成绩效指标或对你『态度』的评价。『绩效』可以指你工作的质量，也可以指表演——比如当你用 token 用量、代码行数、出勤率来衡量绩效的时候。」
- **eudamoniac**：「它们不需要『消失』，管理者只需要停止强制使用。理智的企业关心产出而不是 token。……你的论断只有在 AI 进步到没有任何开发者能不用它跟上进度时才成立。那不是今天，可能也不是明天。」
- **dspillett** 从英国劳动法角度指出：至少在英国，雇主不能强行改变你的职务实质，也不能因你拒绝而解雇你（可以裁员，对新人来说效果相同）。他还给出了一个完整的个人立场：「我的『连贯理由』是他们会拿走这份工作里我还喜欢的那一点点。远程办公对我的心理健康有不好的影响，而这个我没得选；我不会在此之上再用一个我在原则上反对的工具；我多年来一直避免做管理，所以人们常挂在嘴边的『就像有了自己的团队』对我恰恰是最没吸引力的。真到了那一步，我宁愿彻底离开这个行业。」

**ropetin** 给出了一个夹在中间的实用立场，也附带了一个有价值的数据点：「我们 CEO 在 OpenClaw 刚出来的时候陷入了彻底的 AI 精神病。最高层的指令是『所有事都用 AI』，完全不管它是否提升了生产力、服务交付或产出质量。**这个指令在他们看到账单之后很快就被收回了——多人一周烧掉几万美元的 token，却拿不出任何可证明的价值。**……我内心跟你一样：他们雇我来做一份工作，如果我以期望的速度和质量完成了，他们凭什么在乎我用的是 LLM、我的大脑、还是随机往键盘上扔泥巴？但现实的那一半说『我喜欢头上有屋顶』，所以如果他们强制我用 LLM，我会用——只要他们为这个决定带来的任何负面影响负责。」

### 四、「为什么 C 级这么着急？」

**xgbi** 提了一个没人能回答的问题：

> 我在试图理解为什么 C 级这么迫切地抓住 AI。是什么驱使他们如此强推？
>
> 是害怕业务被别人复制？是缩减劳动力的金钱激励？还是就是富人俱乐部在互相洗同一个想法——AI 会解决他们的问题——然后 Cxx 们从静修会回来把「全公司都得用 AI」当成立场，因为高尔夫球场上的哥们这么说？还是十倍生产力的许诺？
>
> 我们公司冻结加薪好几年了，但 AI 使用是开放吧台。我在 review 里也感觉到了：有些 review 连人都没过一遍就加急通过了。它也暴露了那些完全不在意结果的人，他们提交自己都看不懂的东西。C 级会说「每个提交 MR 的开发者都应该能解释为什么和怎么做」，同一周又在推动 Spec → 实现 → MR → Review 全流程的完全自动化。我完全看不懂这个终局是什么。

**localhoster** 的回答：「我也不懂。而且我们连他们急切想要的 10 倍都没到，差不多 3 倍，还是假设每个新 MR 都有价值的前提下。我觉得这是精神病、与代码库脱节、和薄弱的批判性思维的组合。」

### 五、怎么在 AI 时代保持脑力

**andreybaskov** 的做法引发了一场小辩论：「我发现自己需要写代码来保持大脑的状态，就像去健身房保持健康一样。虽然我所有代码现在都是 agent 在写，但我每天早上从一道 LeetCode 题开始。没有实际用途，但它让我一整天感觉良好、思维敏锐。」

**jplusequalt** 反驳：「照你的比喻，这相当于去健身房只做一组卧推。你的大脑仍然在萎缩。」**sph** 补充了更实质的批评：「软件工程不只是解代码谜题。调试、写干净的代码、写有效的测试、架构、优化、性能分析呢？LeetCode 一个都练不到。」**eska** 说得更准：「LeetCode 是学算法和数据结构。编程远不止这些。知道 minimax 和环形缓冲区，对判断你的 LLM 做的事有没有道理帮助不大。要判断那个，你需要做更开放的问题。」

**cyberpunk** 的实战经验支持了原方案：「你确定吗？一道 LeetCode medium 或 hard 需要投入的努力通常远超我在工作中做的大部分事情——而且现实点说，我一天最多只有两小时能承受那种强度的工作，其余是自动驾驶式的代码、review、会议、文档。我发现 AoC/LeetCode 基本上逆转了我那种无意识的萎缩。」

**arw0n** 给出了本帖最有价值的一份自我观察清单——他注意到自己在 agentic coding 中出现的几种不良行为转变：

> - 同时做太多事，极度疲劳，变得紧张和焦虑
> - 谄媚（sycophancy）让我高估自己
> - 当我的压力遇上外部压力，质量就下降。那个「AI 肯定做对了吧」的小声音会导致缺陷和代码质量下滑
>
> 除了手写一些代码，我开始做几件不管用不用 AI 都很健康的事：
> - 每天至少半小时什么都不做。读人写的东西，最好是小说。
> - 做一件让你觉得自己很蠢的事，而且不要用 AI 帮忙。（可以是 LeetCode，对我是学统计。）
> - 当你感觉事情推进得太快时，慢下来。这是目前为止最难的一件事，但一旦我意识到自己在为某个 deadline 赶，我就出门散步。现实点说，我现在比以前快 3-8 倍，这点延迟什么都不是，却能让我保持理智和质量在线。

**thefz** 用一个小故事完美地总结了 **andreybaskov** 的做法：「我以前是个面包师，各种复杂的面包和甜点都做。现在机器替我做了。为了保持状态，我每天早上烤一个面包。」

### 尾声

帖子里还有几条值得记下来的：

**jolt42** 描述了新的工作形态：「现在像是用苏格拉底方法编程。知道该问什么问题成了最难的部分，而你需要懂上下文才能问对问题。是的，我没在敲那么多代码，也没在直接读那么多代码，但我仍然在琢磨如何产出一个好方案。」

**QuadmasterXLII** 提供了一个诚实的企业实验记录：「我们每四个月左右会花一周试着为 agent 兴奋一次。到目前为止答案一直是很坚定的『不行，这玩意烂透了，回去手写』。这些试验期间 agent 写出的那部分代码库，明显比其余部分更让人恼火。不过这一轮比之前几轮都顺利（Fable 5.1 确实惊人）。但每一轮都有蜜月期，所以还不好说。」他随后补了一句意外的收获：「其实挺不错的一点是，现在我们能用一条命令行调用就启动整个系统的隔离副本——这是让 agent 放开手脚乱试的必要条件，但现在它主要让手工开发和新人上手更容易了。」

**tgv** 的结尾很冷：「如梗所说，现在开始健康饮食吧，因为你未来的医生会是 vibe 着读完医学院的。」

而 **patterner** 的回复是全帖最短也最沉重的：「我写了几十年代码，我热爱编程和学新东西。不幸的是没人愿意为此付我钱了，所以我放弃了。而我又不会别的，所以我无路可走。」
