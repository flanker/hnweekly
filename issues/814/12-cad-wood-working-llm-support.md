## 文章摘要

提问者 reacharavindh 是一名业余木工爱好者，本职是计算机工程师。帖子正文很短：他做东西时会在 Shapr3D 里手动设计一些简单的作品，需要极大的耐心。他想知道，在大模型时代，有没有什么有效的办法能借助 AI 加速 3D 模型设计？有没有人试过用 AI 给木工项目建模？有什么工具推荐？

问题本身虽然简单，却触到了一个当下很多人在摸索的领域：大模型如何参与到空间设计和实体制作中。从他在评论区的补充来看，他的需求并不局限于书架、柜子这类标准化的板式家具，而是想要一套更通用的工作流，能做任何自己想做的东西：给孩子的玩具、棚屋里的自行车架、工具墙、儿童床等等。他希望 AI 能帮助完成设计的第一步，把脑中的想法从多个视角可视化，方便调整和改进；他也承认业余木工是艺术、科学和工程按个人兴趣不同比例的混合，项目做着做着细节、榫卯、设计甚至尺寸（因为犯错）都会变，但在开始铣木料之前，必须先想清楚自己想要什么。他现在会从不同角度画大量草图来缩小范围。

讨论结束时，他在评论里整理了自己的结论：短期打算试用 sawdust.diy 和 FluidCAD；长期来看，FreeCAD 加 Blender 再加一个 AI 模型，是控制力更强的通用工作流（“大概也会让我迷失在细节里”）；另外记下了从图片生成 CAD 模型的 silhouette-modeling 方法及其配套技能、FreeCAD MCP 服务器，以及专门面向木工的 FreeCAD 资源库 dprojects/Woodworking。

## HN 评论精华

本帖 125 分、约 125 条评论。讨论大致分成三类：几位开发者推荐自己正在做的工具；更多人分享“通用大模型 + 代码化 CAD”的工作流；还有一部分木工从业者和爱好者讨论 CAD 到底在木工中有多大用处。

**作者们的自荐。** maouida 是开发者兼业余木工，做了 FluidCAD，自带可以接入任何大模型的 MCP 服务，在本地运行，暂时还不支持把模型拆分成零件；他说两年前在没有 AI 的情况下做了概念验证，成形后开始用 AI，现在所有代码都是 AI 写的，但整体架构仍由他把控。variodot 做的 ShopSpec 是一个木工领域引擎加参数化家具生成器，专注书架、橱柜、车间家具，自动算出零件、榫卯和下料单，有测试版 MCP 让代理探索设计而由引擎负责计算，可导出 DXF 或能在 SketchUp Pro 中重建模型的 Ruby 脚本。它获得不少好评，职业家具匠人 mauvehaus 称赞它融入了很多实用的木工知识；也有人提出意见：非美国用户需要默认公制、超过 4 层书架会出错、找不到让台面倒角显示的办法，harmoni-pet 吐槽页面上到处是全大写的小字，建议“告诉你的大模型别这么干”。taylorfinley 推荐自己的 sawdust.diy，说是当初建棚屋时为了让脑中的画面更贴近现实而做的；ninju 发现它的界面风格和 ShopSpec 很像，benhurmarcel 调侃“可能用的是同一个大模型”，作者说两人从没合作，只是做相似项目的人用了相似的视觉语言。此外还有人推荐 claydash、builder.auxx.ai、RapidCAM、partforge.ai 等，kleiba2 批评 partforge 首页让人以为能直接试用、提交后却弹窗要求注册，是他最讨厌的暗黑模式。

**通用大模型 + 代码化 CAD 才是主流。** 更多人推荐直接让通用模型写代码驱动 CAD。Sevii、dboreham、bobd123 推荐 Claude Code 加 OpenSCAD，bobd123 还建议再用 cutlistevo.com 优化下料排版；dghlsakjg 说用 Opus 5.5 加 OpenSCAD 设计了一个模型帆船船体，“完全做对了”，还考虑到了可打印性。kentlyons 说 Claude Code 现在对 FreeCAD Python API 的掌握好了太多，新一代模型能对他的陶瓷相关产品中的定制建模做大幅修改且基本正确。TrueDuality 用 FreeCAD MCP 设计了一个带下料单、组装和五金说明的工作台，还有一个 3D 打印用的全向差速机器人轮模块，后者已到能力边缘，需要换成 Fable 才搞定。他提醒几个坑：模型实际操控视口并截图时理解问题非常好，但它很抗拒这样做，更喜欢编一堆方程来自证正确，而那些几乎都不对；它还经常把坐标轴方向搞反，导致碰撞检测查错了方向。edg5000 认为本地使用根本不需要 MCP，直接让模型在命令行里跑无头 FreeCAD 就行，并称 Codex CLI 里的 Astra 很擅长用 FreeCAD Python 运行时纯靠自然语言设计和修改。asteroidburger 已经打印了第三四个完全由 Claude 生成的定制外壳，用的是 CadQuery 脚本导出 STL；zdp7 也说 CadQuery 相当于 Python 版的 OpenSCAD，优势是 B-rep 建模。s1mon 推荐 Onshape：和 Shapr3D 一样基于 Parasolid 内核，几个月前加入了 MCP 支持，FeatureScript 语言催生了很多木工自定义功能库，非商业用途免费。meetingthrower、freak42 则说 Fusion 360 配 Claude 的 MCP 连接器效果很不错，但 tonyarkles 觉得 Fusion 内置的聊天助手不太行。

**方法论：先建领域模型。** tcdent 的做法是用 Python 写一个 DSL，描述所有部件以及它们之间的关系，最重要的是能用确定性的方式测试装配，然后再从参数化关系导出三维视图或下料单，而不是把三维软件当作唯一的真实来源；jmtulloss 说他的创业公司在建筑领域用 TypeScript 做同样的事，证明这对空间装配很有效。mvcalder 讲了一个故事：他想画一些装饰性金属角撑板的 DXF 文件，让 Claude 当 CAD 导师失败了，让它根据描述写 Python 也失败了（理解不准、缺乏审美），最后让 Claude 实现一个捕捉他几何直觉的小 DSL，得到一种类似 Logo 的专属语言，终于做出了想要的东西。cladopa 说他以前手写 OpenSCAD 太痛苦，每个细节都要理性推敲，于是转用 FreeCAD；有了大模型后又回到 OpenSCAD，既有代码的完全控制，又不必耗费心力，时间只要以前的二十分之一；filcuk 则说自己用大模型写 OpenSCAD 效果很差，渲染还慢。bob1029 给出一个实用判断标准：如果模型能用一段简短的 Python 程序描述，大模型基本能一次做对；如果是人脸或鸟这种东西，它充其量是个笨拙的学徒，柯氏复杂度高的东西就是大模型的难点。

**木工需要 CAD 吗？** 讨论中关于“画图”本身的争论同样精彩。seemaze 讲了一个故事：他是建筑师出身，看到一位知名琴匠和朋友对着一张废纸皱眉推敲榫头公差，就打趣说你们迟早得提前画正规图纸，琴匠回答：“图纸永远是问题所在，你最好让木头告诉你它该怎么组合。”他无言以对。WillAdams 也讲了当地一位木雕名家的故事。pjc50 则说他家浴室装修时所有工种都不画图全凭目测，结果出了严重的测量错误。mattbrewsbytes 认为业余爱好不赶时间，用纸笔画图本身就是放松，软件里的精度一碰到有纹理、有节疤、尺寸不一的真实木头就失去意义；提问者回应说他不排斥电脑，而是用电脑加速人类规划中容易出错的部分，把想法可视化后能发现比例问题，mattbrewsbytes 坦言自己的问题是总想做到像素级完美，于是投入太多时间，提问者说“这太扎心了”。itissid 说他做家装内嵌储物，发现大多数业余项目里 CAD 工具都是次要的，前几轮 3D 设计总要因为反复测量、间隙和墙骨位置而推翻，他唯一依赖的是 cutlistoptimizer.com。CubsFan1060 问：AI 做设计和建模，机器人负责切割，这还算是木工吗？提问者答道：界线一直很模糊，为什么用电刨而不用手刨、用电锯而不用手锯？关键在于你享受哪部分、愿意把哪部分交给工具，“有些人干脆把整个过程抽象掉，直接去宜家”。

**职业匠人的经验。** mauvehaus 是职业家具匠人，从软件行业转行而来，三十多岁才回学校学做家具。他与远程客户交流时用 SketchUp 或 FreeCAD 出粗略渲染图，真正动手时则画铅笔三视图车间图纸，标出隐藏线和榫卯，稍复杂一点（比如带抽屉的边桌）就一定画图。他还解答了胶合板建模的问题：3/4 英寸胶合板实际常是 23/32 英寸，CNC 切割要拼合的零件时，必须用数显卡尺精确测量板材和刀具，Freud 的 1/4 英寸螺旋铣刀常常只有 0.245 英寸，差这点就装不上；嵌入壁龛的柜子应做小一些，就位后再按墙面刻画修整面框；抽屉盒要按实际开口尺寸做，而不是图纸上理想化的尺寸。有人问如何训练拆装顺序的空间思维，他说小时候玩了很多乐高，修车时宁可一次只拆一边，留另一边做参照。
