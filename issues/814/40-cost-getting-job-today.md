## 文章摘要

作者 Weli（Gerard）是柏林一家 AI 创业公司的工程负责人，这篇博文很短，他开头就说："这篇不长，但这件事困扰我有一段时间了。"

**招聘是最难的部分。** 几个月前他升任工程负责人，随之而来的是他一直觉得最难的工作：招人。他说自己很幸运，身边已经是一群很棒的同事，但创业公司总有一种持续而安静的压力，要不停地物色人才，因为等真正缺人时，你等不起三个月去找完美人选。

**技能不是全部。** 他坦承自己过去对"唯才是举"抱有宏大的想法，认为招人应该只看技能，后来发现大错特错。一个人的行为方式、与人相处的方式、解决问题的思路和给团队带来的能量，和技术能力同样重要，常常更重要。在他有限的观察里，越过基本能力门槛之后，愿意把事情做完的态度比多懂一点知识走得远得多。这在创业公司里说得通：小团队正是靠这一点，才能对抗那些有几千名员工、在每个工程师身上都能出价更高的巨头。

**与候选人本身无关的障碍。** 所以，当真正稀缺的好工程师因为与工程能力无关的原因无法加入时，他会很心痛：拿不到签证，住在另一个城市，合同条款不合适。而最近他又想到了另一个问题。他认为使用 LLM 如今已经是软件工程的必备部分，所以在面试和技术挑战中，他们期望候选人使用 AI。

**换位思考。** 想象你在找工作：你没有收入，求职基本是数字游戏，一周可能同时面五家公司，而每家都给你一道要求用 AI 完成的挑战题。AI 不是免费的，真正擅长写代码的工具需要月度订阅或 API 额度。于是你要在人生中可能最拮据的时候为它们掏钱。常见的回应是："一直都是这样，找工作本来就要花钱。"确实，你需要住处、衣服和食物才能去应聘，但这些东西都不只是为了被录用而存在。LLM 的花费不同，它是一次性的，唯一目的就是拿到这份工作。

**没有完美答案。** 这让他很为难：要么接受现状，明知会因为有人负担不起一个像样的模型而失去一些好工程师；要么尝试别的办法。他想了很久，没有令人满意的方案。给候选人开公司账号不行，这是一种责任风险，他无法保证账号会被怎么使用；报销候选人的花费也不行，很难作为业务支出说清楚，很快就会滑进财务灰色地带。

**他能改变的是流程。** 既然消除不了成本，目标就变成让候选人尽量少花钱，并且只在真正重要的时候花：

- **把挑战题挪到后面。** 公司还没和你好好聊过，就不应该让你为它烧 token。走到挑战题这一步，说明公司已经认真感兴趣，你花的钱更可能变成 offer。
- **把题目缩小。** 一道需要顶级模型跑几个小时的题，考的不是候选人，而是候选人的钱包。他宁愿出一道边界清晰、用免费档或基础套餐就能完成的题，然后把剩下的时间用来讨论你是怎么做的，反正他从这种对话里了解得最多。
- **一起做。** 这是他最喜欢的方案：不再布置带回家的作业，而是现场会话，候选人主导，AI 跑在公司这边，用公司的机器和账号。没有责任风险，没有报销，没有灰色地带。他还能看到自己真正在意的东西：你怎么思考、怎么沟通，以及模型自信满满地给你一个错误答案时你怎么反应。
- **降低代码的权重。** 他说最大的变化其实是挑战题本身占多少比重。如今他更看重关于架构和你喜欢怎样构建软件的深入讨论：怎么组织系统、在哪里划边界、怎么看待测试、代码评审和发布。当 LLM 能写出大部分代码，代码能告诉他的关于你的信息就少了；你如何权衡取舍能告诉他的多得多，而这样的对话不花你一分钱。

这些方案都不完美：现场会话会让一些人紧张，小题目能展示的东西也更少。但他宁愿有意识地选择一种取舍，也不愿假装问题不存在。文章最后呼吁同样在招人的读者问问自己：你的招聘流程会让一个眼下没有收入的人花多少钱？你可能在不知不觉中失去了多少好人？文末附了一个小广告：如果你在柏林、愿意去 Rosenthaler Platz 的办公室、喜欢创业环境，欢迎发邮件聊聊你对 RAG 的看法。

## HN 评论精华

本帖 47 分、60 多条评论，作者本人（weli）也在评论区回复。讨论主要集中在一点：作者否决"给候选人提供 API 额度"的理由站不站得住。

**"给个有额度的 key 有什么难的？"** 这是最集中的质疑。63stack 问：给候选人一个充了 5 美元的 DeepSeek API key 有什么风险？5 美元够连续用一周。coffeebeqn 也说完全可以单独开一个与公司主账号隔离的沙盒账号。jetemple 建议在模型前面放一个代理，给每个候选人发一个有硬性预算的 key，用完就撤销，"如果你要求面试用 AI，就该由你来付钱"；frangonf 补充说这样还能顺便观察候选人的用量模式和结果的关系，甚至做出不错的评估数据。embedding-shape 给了类似的方案：在鉴权后面架一个 HTTP 代理，候选人用这个端点，你还能复用公司已有的订阅，只要事先告知请求会经过公司基础设施。petesergeant 说得更尖锐："如果你连给通过筛选的候选人一个充了 50 美元的 OpenRouter key 都做不到，你怎么付得起工资？你又有多不珍惜现有工程师花在面试和看简历上的时间？"arcza 讽刺作者风险厌恶得离谱："那也别让人来现场面试了，万一他们猜出办公室 Wi-Fi 密码下载坏东西呢。"

作者 weli 回应说，他考虑过，但这既是责任风险又会给他带来太多负担：额度设多少完全是拍脑袋，5 美元还是 10 美元？他无法保证候选人只用来做题，可能用来生成有害内容；还要手动创建、撤销 key，候选人可能要更多额度，key 也可能泄露。bonoboTP 替他解释说，风险大概是候选人用额度做违法的事，导致公司账号被封或惹上官司；但他也说，那就直接付现金，有些招聘流程本来就会为较大的带回家作业付报酬。CharlieDigital 说他面试过一家公司，直接给了一张 500 美元的虚拟卡用于 token，"非常慷慨也很合理"；另一家（AI 之前）则按市场价付了一个 8 小时项目的合同费，这种公司存在，只是很少。sokoloff 建议对走到特定环节的候选人发一张 20 到 50 美元的礼品卡，比给每人开虚拟卡更容易过财务那一关。

**"20 美元都出不起？"** luckylion 嘲讽说"软件工程师穷到付不起每月 20 美元"是 LinkedIn 式的废话。rhdunn 回应说，没有稳定收入时每一笔开支都很重要，额外支出会缩短你靠积蓄撑下去的时间；methou 说他失业第二天早上就取消了每月 20 美元的 Emby 订阅。weli 说他当过背着贷款的穷学生，经历过在"加油去面试"和"今天吃饭"之间二选一，问题不在 20 美元，而在于要求人们为了一个被录用的机会花自己的钱，在道德上是否说得过去。sokoloff 认为 LLM 订阅很快就会像手机话费一样成为"人人都有的东西"，已经不算专为面试付出的成本；littlecranky67 说他 90 年代、2000 年代在 O'Reilly 编程书上花的钱远不止这些，"作为资深工程师拿不出 20 欧元订阅 Claude，不是因为穷，而是优先级不同"。npodbielski 反驳说，价格不会永远是 20 美元，而且成年人有房贷、保险和孩子，"为了一场面试而不是一份工作付 AI 的钱，这很糟糕"。imtringued 推演了一个极端情境：如果每个公司都设计一套会烧光一个月 20 美元订阅额度的自动化面试，找工作期间你就得买 200 美元的套餐。

**面试到底该不该让人用 LLM。** pjc50 说自己可能已经脱节，但看不出 LLM 在面试中应该扮演什么角色，"你面试的又不是 LLM"，带回家的编程题在 LLM 时代更没用了。EliRivers 说他见过有人对 LLM 言听计从、不加思考地复制粘贴、在病态的循环里打转几个小时，所以确实想知道候选人能否被信任使用 LLM；em-bee 建议可以让候选人评估预先生成好的 LLM 输出。mceleri 也认为可以"纸上谈兵"，直接问候选人会怎样、为什么使用 LLM。inatreecrown2 和 ungovernableCat 都觉得文中"一起做"的方案最好，与其让人在家烧 token，不如当面观察对方怎么思考。

**其他话题。** 在招聘行业做了 15 年以上的 Peroni 非常认同"越过能力门槛后态度更重要"的观点，并支持"没好好聊过之前不该让候选人做任何任务"。solatic 则认为，文章开头强调行为和品格，与后面关于考察 LLM 使用的内容并不连贯，因为面试和推荐信都测不出一个人是否正派。methou 由文中签证和地域限制的话题，分享说自己在日本，近年明显感到很多岗位只招美国或特定城市的人，"全球化没那么强了"；soneca 也说在 HN 每月招聘帖里，美国公司的远程岗位约 90% 都是"仅限美国远程"。
