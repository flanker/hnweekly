## 文章摘要

Tiny Little Office 是一个在浏览器里运行的免费迷你办公套件，核心理念只有一句话：**链接就是文档**。一封信、一张表格、一份幻灯片或一个日历，全部内容都编码在页面网址里；复制链接就等于复制了文档，谁拿到链接谁就拥有这份文档，不需要注册账号。它由纽约的软件公司 Aboard 出品，以 MIT 许可证开源，代码托管在 GitHub 上。站点首页本身只是十个应用的入口，以下内容综合自首页、项目 README、面向 AI 的说明文件 llms.txt，以及 Aboard 联合创始人 Paul Ford 10 月 14 日在公司通讯上发表的介绍文章。

**十个小应用。** 套件包括文字处理器、大纲工具、演示文稿制作、电子表格、计算器、绘图工具（可画像素画）、图表制作（思维导图、组织架构图等）、动画制作、日历和行程规划。官方示例很有生活气：给街坊的一封信、"房租四人平摊"表格、"史密斯街那家店的晚餐"计算器（含税、小费、六人平分）、"跳蚤市场那一周"日历、面包店的分工组织图等。任何一个应用的文档都能以代码块的形式嵌入文字处理页面、幻灯片或大纲条目中，由对应的应用就地绘制和编辑；Ford 说文档嵌套文档是整个 1990 年代办公软件的梦想，如今终于实现了。

**它是怎么工作的。** 文档内容用一种加了少量扩展的 Markdown（官方称 TLO 格式）书写，经过编码或压缩后放在网址的 # 号之后。浏览器默认不会把 # 号后面的部分发给服务器，所以文档不会存到任何服务器上，你的网络服务商也只能看到你访问了这个网站。想"保存"文档有几种方式：把网址贴进聊天，群里每个人都得到一份可编辑的副本；导出为 PDF、PowerPoint、Markdown，或者生成二维码，一两页的文档可以整个塞进二维码里；文档较大时可以用自带的短链接服务，浏览器先加密文档再上传，密钥留在链接的 # 号之后，服务器永远看不到内容，短链接最长一个月后失效。也可以选择保存在自己设备的浏览器存储里。README 提醒，浏览器历史记录当然会留下链接，介意的话用无痕模式。

**面向 AI 智能体设计。** 首页顶部就有一行专门写给智能体的话，指向 llms.txt。这份说明详细描述了如何手写一个文档链接，给出了每个应用的最小示例，还列出了"智能体最容易犯的三条错误"：每个空格和换行都会被保留，列表靠两个空格缩进来分层，掉一个空格整棵树就扁平了；一张幻灯片只放一样东西，有图表的幻灯片上的要点不会显示；列表里的逗号会把条目切开，所以"2,000 例"要写成 2000。项目还提供 JavaScript API、npm 命令行工具，以及可以一键安装到 Claude Code 的技能文件。链接建议控制在 2000 个字符以内。

**来龙去脉与取舍。** Ford 在介绍文章里讲了缘起：六年前他们还在经营另一家公司时，搭档 Rich Ziade 想出了 TinySheet，一个把数据全存在网址里的十行小表格，大家主要拿它在 Slack 里分享简单算式，后来又做了 TinyCalendar。他们转去做别的事后，这些网站下线了，旧链接全部失效。到了 2026 年，"软件已经大不一样"，他决定把 TinySheet 的想法做大，于是有了这个套件。他坦言有很多取舍：这完全不是 Web 应用应有的工作方式，贴进聊天的链接会很长，不能上传视频或图片，也不像 Google Docs 那样能协作，"它的协作方式更像在街头集市上发小册子"。他给出几种理解它的角度：这是用完即弃的软件；如果 Signal 是一个操作系统，这也许有朝一日能成为它的办公套件；把完整链接发到 X 或 Bluesky 上，就等于把文件公开"存"了一份；它也是为智能体设计的，你可以让大模型用它做小巧、可分享的东西。他还说，如今科技行业里一切都很庞大，所有系统都跑在别人的机器上、到处追踪你，你创作的内容也被大模型吞噬，而大多数普通人整天待在聊天软件里躲避这一切，他很享受为这些人做点东西。他最喜欢的是大纲工具，需要保存时就在 Slack 上发给自己。文章结尾引用 Ziade 当年的观点："小而私密的东西也许不赚钱，但可以有价值。"

## HN 评论精华

本帖 692 分、近 200 条评论。帖子发出后网站一度因为流量过大触发了托管服务的套餐限额（christophilus 贴出了"站长已达套餐上限"的提示），一些人转而去 GitHub 本地运行。讨论主要围绕三点：这类"AI 辅助开发的小工具"带来的软件生态变化、类似产品的比较，以及链接存文档这种设计的实际局限。

**不要登录、不收费、可自托管。** 最受关注的评论来自 poisonborz：他喜欢这类"氛围编程"小工具的一点是，它们似乎很清楚自己随处可见，所以不想圈用户、也不卖付费服务，一切免登录、用一个网址就能分享、默认支持自托管；AI 虽然削弱了创作者的影响力和认可，但总体上是软件领域一股伟大的民主化力量。maelito 回应："这也意味着你别指望这工具下个月还在。"muyuu 说能在自己电脑上运行就可以指望，throwaway2037 指出主页底部有 GitHub 链接，README 里有本地运行和自托管说明。不过 4ndrewl 和 ktzar 发现自托管主要依赖 Cloudflare 的云服务，没有文档说明如何用 Docker Compose 加 SQLite 或 Postgres 在本地部署；beklein 则说他在本机克隆、安装、启动开发服务器都没问题。thatsabadlook 的说法更尖刻：不收费是因为作者根本无法为这些代码担保，收钱"可能真的构成犯罪"；llm_nerd 反驳说从来没有哪个程序员能为自己的作品"担保"，所有软件都有 bug。latexr 不满"民主化"一词被滥用，"本地蛋糕店接单做蛋糕并没有让烘焙民主化"；oidar 和 Kiln6125 则引用词源和印刷术的例子反驳，认为民主化恰恰体现在规模上。danhite 贴出了 Aboard 联合创始人的介绍文章，指出这个想法六年前就有了。mogoh 认为这是三天内用 AI 写出来的，"现在能用、一年后还在的概率都很小，但我希望一年后被证明是错的"。

**同类产品。** oijkuij 推荐了之前在 HN 上看到的 bento.page，功能更多但目前专注于演示文稿，而且编辑器和内容都嵌在一个 HTML 文件里，不依赖托管网站存活；redbell 指出那个项目三个月前在 HN 上拿到过一千多分。monk_grilla 说他可能是"2026 年的卢德分子"，但实在没法去读一个落地页满是千篇一律 AI 设计风格的产品；NewsaHackO 觉得好笑的是，三年前这样的网站光凭设计就能上首页，现在却给人一种 Wix 模板站的感觉；mtford 说"无聊的幻灯片已死，一个文件杀死了它"这类文案让他几乎过敏。altern8 则认为 bento 太复杂，Tiny Little Office 好就好在极简直观。rezaprima 说它让人想起能把自己保存为单个文件的 TiddlyWiki，spankibalt 也希望它能像 TiddlyWiki 那样做成一个可下载的单文件。

**让 AI 来生成文档。** simonw（Simon Willison）建议让 Claude 等模型读一下 llms.txt，它就能生成渲染文档的网址，他还让模型生成了一份讲解网址格式的幻灯片。monk_grilla 反问为什么不直接让智能体写 LaTeX 的 beamer 模板，更专业、可定制、能进 git；gf000 和 groestl 推荐 Typst；simonw 受此启发，顺手做了一个把 LaTeX 放进网址就能渲染的小工具。albert_e 对最后一页能装下整份文档的二维码很感兴趣，也好奇文件大小的实际上限。

**链接存文档的局限。** eviks 问：几兆字节的内容编进链接，怎么能叫"方便分享"？ninju 提醒，"迷你"二字是实打实的约束，文字文档大概两千字符就到头了。oidar、pseudosavant、ArekDymalski 都发现没有办法打开已保存的文件，不能导入 csv、txt、ics，甚至没法重新加载保存在浏览器存储里的文档，ArekDymalski 认为对电子表格来说缺少导入功能是硬伤，因为表格很少从零开始。datas 问是否考虑实时协作，随即意识到数据存在网址里，离实时协作其实很远；nine_k 补充说浏览器里可以不刷新页面更新网址，分享则需要一个随文档更新而更新目标的短链接服务。ent101 主动提出要用自己的开源项目 Puter 的 WebRTC 能力给它提交一个实时协作的 PR。yellowapple 发现 OpenStreetMap 对该站返回了 403，可能是行程规划应用拉取地图瓦片过多；Gigachad 说 OSM 的瓦片服务器本来就主要用于编辑地图，jdranczewski 补充说只要遵守使用政策，第三方应用其实也可以用。plasticeagle 随手挑了一段界面文案："在此加密：服务只持有密文，且仅持有到那时。每个地址每天最多一百个链接。"他问这到底是什么意思。也有人报告了文字处理器光标错位、深色模式下幻灯片预览文字看不清等小 bug。

**怀旧与需求。** alexpotato 回忆 80 年代末父亲给他买了一台 Olivetti 的 IBM 兼容机，那时表格用 Lotus 1-2-3、图表用 Harvard Graphics、文字处理用 ChiWriter，各是独立软件，如今一个网站就有一套免费的办公套件。mikepurvis 对行程规划被列为顶级应用很感兴趣，他最近组织两次多人出游，最后都变成了表格、谷歌地图收藏和零散 ChatGPT 对话拼起来的一团乱麻，他觉得这里有未被满足的需求。mattoxic 说他想过类似的东西，因为不排除某届美国政府会对一些国家停用 Google Workspace 和 Office 365，catlikesshrimp 贴出了荷兰在国际刑事法院遭美国制裁后推出替代软件生态的新闻。也有不以为然的声音：self_awareness 不明白有 LibreOffice 这种免费又强大得多的软件，为什么还有人做、有人用这个；syngrog66 认为这是"提供这些功能的最差方式"，而这些功能几十年前就已经解决了。
