## 文章摘要

微软在 Ignite 公告中介绍一组面向不同企业任务的模型，包括安全防御、日常编码、图像编辑、实时语音、转录和模型路由。其主张是把不同工作交给更合适的专用模型，而非所有请求都使用同一个昂贵通用模型。编码系列尤其强调解释、定向修改、常规修复和快速迭代，并明确表示尚未针对基础科学或很长时间跨度的代理工作进行优化。

公告中的性能价格比来自指定基准、产品设置或厂商评估。例如编码模型的比较是多个日常编程基准的平均表现，不表示真实工程里任何任务都能保留同样比例的能力；Decision 1.1 的路由用途，也不应与通用模型的全部能力混为一谈。不同模型的推出渠道不一致，有的进入 GitHub Copilot，有的在 Foundry 提供有限预览，实时语音则提供试用和兴趣登记，不能一概描述为所有开发者已能自由调用。

微软同时推出 Licensed Weights，让企业在约定方式下定制模型并在自己的 Azure 环境运行。授权获取权重、限定环境内控制模型与自由分发的开源权重并非同一个概念，具体权利仍须查看适用条款。最初网页正文抽取误取了页尾相关文章，本次已补读完整 HTML 中的正式公告。本文未测试模型、复算费用或独立核验排行榜，所有规模和优势描述均保留为厂商披露，不把营销比较当成跨任务的普遍结论。
