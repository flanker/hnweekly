## 文章摘要

Foolscap 把 AI 定位成阅读与反馈工具，而不是代笔者。产品页面称它会在写作过程中识别人物、想法、叙事线索和未解决的问题，并把发现指回作者自己的文字。作者在发布帖进一步说明，旁侧助手可以回答关于书稿的问题并触发操作，但不向作品正文写入内容。这里强调的是保留创作过程，而非承诺模型对全书的理解必然正确。

长篇写作的困难常常不在单句润色，而在跨章节的一致性和结构。讨论中有人希望检查技术文档里的矛盾数字、概念重叠和固定设定，作者表示这与产品方向一致。不过，这些具体请求不能全部当成已经成熟交付的功能。作者提到系统能够关注定理与证明之间的依赖，但尚未重点开发，也没有 Lean 支持，更不能将其描述成数学证明验证器。

隐私说明同样需要精确阅读：官网称书稿不用于训练 AI，并允许将一本书设为私密，使其不发送给 AI；这不等于默认所有分析都在本机完成。作者还说明每本书有 Git 历史及克隆、推送或镜像能力，相关工作区设计仍在调整。本文依据简短主页和作者讨论整理，未上传书稿、验证数据流或测试版本恢复。对作家而言，反馈是否贴近文本、资料是否可导出，以及是否能保留习惯的编辑器，仍是值得实际试用的重点。

## HN 评论精华

- [FinnLobsien](https://news.ycombinator.com/item?id=50560817)：强调写作阶段不同，所需反馈也不同：早期可以重构角度，后期再提出同类建议可能打乱工作。

- [ramses0](https://news.ycombinator.com/item?id=50570786)：分享有限试用反馈，认为建议有潜力，但复制粘贴、编辑器和批注呈现方式仍妨碍日常使用。

- [atugard](https://news.ycombinator.com/item?id=50572571)：作者回应每本书已有可克隆和推送的 Git 仓库，同时承认产品组织方式仍在变化，未把未来整工作区方案说成已完成。
