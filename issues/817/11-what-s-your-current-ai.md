## 文章摘要

eggbrain 发起一份开放式工作流调查，想记录与一年前相比，人们实际在用哪些订阅、模型和代理工具。问题分成几个层面：个人购买的套餐与档位，订阅之外的 API 或本地模型，编码 CLI 和 IDE 界面，多代理编排，以及处理编码以外任务的平台。提问者没有要求每人全部作答，目的是获得当下的使用快照，而非做严格抽样或给产品排市场份额。

回答呈现出两种不同方向。一些人随着模型变强，反而删除复杂配置，只使用一个主要界面，把精力放在清楚描述完成条件；另一些人保留多家订阅、按任务调用不同模型，或者自建监督代理的工具。成本、使用限制、开放权重偏好和界面习惯，常与能力差异同样重要。还有用户把代理组织为事件驱动流程：发生某种变化就触发对应处理，但也承认连接渠道、记忆和运行逻辑的基础工作相当繁琐。

这份讨论适合用来比较工作方式，而不适合机械抄一张工具清单。模型名称和套餐价格都来自评论者当时的自述，没有逐一核实可用性或官方定价；个别人的高并行度也不证明所有任务适合同时开展。更值得留意的是如何定义验收、何时把有效流程改成确定性程序，以及工具链复杂度是否真的减少了自己的维护负担。

## HN 评论精华

- **减少配置，明确终点。** [thefourthchime](https://news.ycombinator.com/item?id=50367037) 说自己转向主要使用 Claude IDE，删除不少技能配置，最重要的技巧是准确说明完成后应交回什么；这是个人体验。

- **界面与模型可以分开选择。** [simlevesque](https://news.ycombinator.com/item?id=50367215) 分享 Claude 订阅、DeepSeek API 以及在 OpenShell 内使用 Claude Code CLI 的组合，强调界面习惯与自定义脚本。

- **有用后再逐步确定化。** [ctolsen](https://news.ycombinator.com/item?id=50367326) 描述以 Pi 为主要界面、用 Paseo 编排的做法；若某个由技能启动的流程确实有价值，就尽可能把它变成确定性的实现。
