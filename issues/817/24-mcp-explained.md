## 文章摘要

MCP Explained 是 Runlayer 制作的交互式协议教材，通过网络图、时序图和逐步消息流解释 AI 应用怎样连接工具与数据。开头先区分三种角色：宿主应用管理交互，服务器描述并提供能力，模型选择使用什么，但不会绕过宿主直接与服务器通信。JSON-RPC 是消息封装，MCP 还规定方法、能力协商、传输和认证，因此既不能简单等同 REST，也不只是换个名称的 JSON-RPC。

页面把工具、资源与提示模板分别放到模型、应用和用户的控制关系中解释，并展示请求、响应、通知、初始化握手、stdio 与 HTTP 传输等概念。课程还涉及采样、用户输入、工作区边界、长任务和安全问题。尤其需要区分：客户端提供的 roots 是范围提示，不等于操作系统强制沙箱；工具发现和代码执行优化也可能只是宿主实现方式，而非协议的新增消息。

页面含规范版本比较与安全演示，也介绍 Runlayer 自身的网关方案，因此阅读时应辨别规范要求、某个版本的设计和厂商产品功能。初次静态正文抽取只能看到首页，本摘要补读了同一公开 HTML 中的课程文字数据，没有执行嵌入脚本；交互效果及所有版本差异尚未逐项验证，具体实现仍应回查所选版本规范。

## HN 评论精华

- **视觉丰富不一定适合初学者。** nater5000 认为信息过密；jrmg 指出教材可能默认读者已经理解系统的整体形状，导致新手找不到入口。
- **简化不能抹掉协议差异。** dingaling911 和 Aurornis 反对把 MCP 直接称为 REST，后者指出页面开头本就明确解释了这一区别。
- **入门指南与参考手册各有职责。** dspillett [建议](https://news.ycombinator.com/item?id=50390767)将概念入门、实例和参考材料分层组织，避免对高手过于啰嗦、对新手又仍然不透明。
