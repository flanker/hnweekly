## 文章摘要

OmniDiff 是用 Rust 编写的差异查看工具，尝试摆脱所有文件都按文本行比较的限制。代码使用 tree-sitter 解析语法结构，图像按像素、动画按帧、字体按字形、压缩包按内部文件、PDF 按页面比较；不认识的文本仍可退回普通逐行比较。它既提供终端交互界面，也支持批处理及 JSON 输出，并能接入 Git difftool 与 Jujutsu。

项目将速度、处理成功率和人类可读性分开衡量。README 报告在一台 ThinkPad 上，2,302 个代码测试用例的中位耗时为 4.2 毫秒；更大语料中的代码变化处理成功率为 99.95%。这些是作者的特定设备、样本和资源上限下的测量，不表示任何文件都能瞬间完成。生成代码、巨大文件以及复杂压缩包仍可能触及时间或内存限制。

准确性则与人工标注比较，README 坦承预设的完美匹配目标尚未达成。当前文档与 HN 早期回复使用的测试集及指标不同，不能把不同百分比直接拼成排行榜。项目采用 AGPLv3，另提供商业许可；作者公开披露大量使用 AI 辅助，同时强调关键算法和质量判断由人负责。此次仅审阅文档，未运行工具或复现基准。

## HN 评论精华

- **移动后又修改的代码是重点。** 作者 FabCH [解释](https://news.ycombinator.com/item?id=50350312)，Git 的行级移动高亮不等同于 AST 节点匹配，复制、抽取函数和移动后编辑是结构比较希望改善的场景。
- **许可证是主动选择。** anilgulecha 担心 AGPL 妨碍普及；FabCH 回应 copyleft 是其价值选择，即使最终启发别人做出更好工具也可以接受。
- **终端宽度影响展示。** arkenflame 希望宽屏自动并排显示；FabCH 说明当时阈值为 200 列，也可手动切换。这属于当时版本的交互讨论，使用时仍应核对当前文档。
