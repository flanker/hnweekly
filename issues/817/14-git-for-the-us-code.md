## 文章摘要

Lexifina 希望让查阅法律的人像程序员查看代码历史一样，追溯某段文字来自哪部法律、何时生效，以及过去某一天适用什么版本。困难在于，法典发布日、修法通过日和实际生效日并不总相同；后来的法律还可能追溯改变先前案件适用的规则。文章以小企业破产债务上限的临时提高、到期和追溯恢复为例，说明只保存历次文本快照仍可能给出错误答案。

团队称，它对九个编章自 2017 年以来相邻发布版本之间的修法逐项重放，365 处变化中有 361 处能精确重建下一版本，其余明确标记核实程度。界面提供按日期查看文字、按来源法律着色、追踪定义变更影响和订阅条款变化等能力。这些是项目方报告，并非本次独立法律审计。

作者也明确承认，系统尚不能在旧日期视图中充分提示后来法律的追溯效力；生效日期以模式匹配解析，特殊措辞可能回退到颁布日期。读者必须回看所链接的原始法律，不能把可视化历史当成具体案件的法律结论。文章提醒：让模型看到正确时间版本，比要求它凭记忆复原旧法更可靠，但仍需要可检查的证据链。

## HN 评论精华

- **从文本历史到法律效力仍有距离。** tpmoney 指出商业法律数据库长期投入大量人工处理修订、编号迁移和判决影响；法院可能使条文不可执行，却不删除其文字，单纯 diff 无法回答所有法律问题。
- **也要记录记录本身的修正。** edflsafoiewq 区分法律变化与整理者纠正法律记录的「元变化」，说明版本控制模型本身也需设计。
- **项目后来提供了仓库。** octoberfranklin 起初质疑标题称 Git 却不能克隆；作者 alansaber [随后回复](https://news.ycombinator.com/item?id=50283354)，链接到公开的 [global-law 仓库](https://github.com/lexifina/global-law)。应按更新后的状态理解这段争论。
