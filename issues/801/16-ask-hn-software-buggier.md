## 文章摘要

这是一条引发广泛共鸣的 Ask HN 帖子。发帖人说自己感觉「快要疯了」——过去六个月里，他在所有设备上都撞见各种奇奇怪怪的 bug，于是发问：是不是别人也有同样的感受？帖子本身极其简短，但它像一根引线，点燃了社区对「软件质量是否在系统性下滑」这一话题的集体吐槽与理性反思。

讨论大致分为三派。第一派「确认党」旗帜鲜明地表示「显然如此」「你没疯，这是长期趋势」，并列举了大量具体证据：iOS（尤其是 Safari）在过去一年明显变卡、变糙；微软全家桶（Windows 11 每次更新都像要搞砸点什么、O365 网页版、PowerPoint 缩放都要「搏斗」、Azure ML 分页随机崩坏一个月才修）；Atlassian 的 Confluence 和 Jira 十年来每次 UI 更新都更令人困惑；Adobe 创意云在 Win11 上也问题频出。第二派「泼冷水党」则提醒这可能是确认偏误（confirmation bias）——软件一直都很有 bug，当年整个操作系统动不动就崩溃，只是如今换成了更小、更蠢的 UX 问题；由于大家最近特别关注「AI 编程」带来的变化，看到任何 bug 都容易归咎于它。第三派则试图给出结构性解释。

多位评论者把矛头指向了行业机制而非单纯的 AI：「先发布最小可行产品、再用补丁修」的模式盛行；苹果曾经的 Gold Master 高质量发布标准和向后兼容传统正在消失；以及最被点名的「房间里的大象」——QA 团队被裁撤或干脆从未组建，测试职责被甩给开发、支持乃至用户。也有人给出了更 nuanced 的看法：核心底层库（如 ffmpeg、virsh）其实从未如此好用，问题几乎都集中在面向消费者的、带 UI 的应用上——「特性速度远远压过了特性稳定性」。AI 编程被普遍认为放大了问题，但多数人认为它只是加速器，而非唯一元凶。

## HN 评论精华

- **lkbm**：代表了「泼冷水」的理性派。他认为软件一直都很有 bug——当年动不动整个操作系统就崩溃，如今只是变成了更小、更蠢的 UX 问题，而这种状况已持续数年，他在过去六个月里「没看出任何区别」。这条评论提醒大家警惕把长期现象误读为近期突变。

- **trio8453**：明确点出「确认偏误」的可能性。正因为你熟悉过去六个月软件开发方式的变化、并且很可能不喜欢它，所以每当看到 bug，你就会下意识地把它归因于此。这是对发帖人问题最冷静的方法论回应。

- **jofzar**：说出了那句被反复点赞的「房间里的大象」——QA 团队被裁掉或压根没组建，测试的活儿被甩给了开发、支持和客户自己。管理层想要的是「做功能、搞销售」，而非「可爱度和打磨」，整个行业正处在一个「拼命做、做、做」的历史高点。这被许多人视为质量下滑的根本制度原因。

- **Hasz**：提供了重要的细分视角，反驳了「一刀切变差」的说法。他指出核心库和软件「从未如此好用」，例如 ffmpeg 和 virsh 的体验比以往任何时候都好；但只要是「带 UI、面向消费者」的东西，那就是「bug 之城」。一句「feature velocity >> feature stability」（特性速度远远压过特性稳定性）精辟概括了症结。

- **lordofgibbons**：给出了一个反直觉但值得深思的辩护，类比 Electron 桌面应用。他说 AI 编程虽让软件更多 bug，但也催生了「一大堆本来根本不会存在的软件和功能」——正如 Electron 虽耗资源，但很多应用若非它带来的开发提速，压根不会被创造出来。这是一种「有 bug 的存在也胜过不存在」的成本收益视角。

- **waynecochran**：从历史纵深佐证了下滑趋势。他回忆苹果曾有 Gold Master 发布机制，达到很高的质量门槛才发版；如今「反正这周晚点还能再发个新版本」的心态盛行。他还哀叹「向后兼容」这件事也已消亡——现在没人会为在旧平台上跑不了代码而多想一秒。

- **karmakurtisaani**：用亲身经历给出了对未来的警示。他去年遇到一个明显是「vibe coded」（AI 随手糊出来）的网站，「看上去很棒，但什么都用不了」，最后只能靠邮件跟公司周旋。他认为这是对未来图景的一次清晰预警。
