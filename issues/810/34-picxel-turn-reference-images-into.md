## 文章摘要

Picxel 是一个面向独立游戏开发者的开源工具（GPL-3.0），目标是把参考图重绘成可辨识的像素风游戏素材。它的定位很明确：不是又一个「AI 生成像素画」的端到端模型，而是把大模型的视觉判断和本地图像算法拆开来各司其职——GPT 负责理解画面主体、制定重绘方案并指挥重绘，本地算法负责把结果转换成精确的像素网格。项目声明主要是在 Codex 环境中用 GPT 开发和测试的。

功能上，它可以导出 32×32、64×64、128×128 的透明 PNG，每个精灵最多 16 色；支持单图的「揭示式预览」，也支持一次最多 20 张图的批处理；面板提供中英双语。运行方式比较特别：它不需要单独的 API key，而是复用一个具备图像生成工具的 Codex 会话的工具和配额。安装方式是直接让 Codex「从这个仓库安装 Picxel 并按照 SKILL.md 完成设置」，之后用 `$picxel` 触发工作流，工具会自动准备并打开本地面板，用户在面板里选图、选输出目录和尺寸即可。

技术流程分六个阶段，README 里对每一步做了相当细致的说明：

- **重绘之前**：先生成一份简短的「保留/舍弃」计划，用来保护主体身份、姿态和关键细节；如果需要预处理图，会做区域性简化，减少会干扰识别的纹理。
- **背景移除**：保留真实的 alpha 通道；只有在用户明确指定了键控色的情况下，才移除该背景色并有针对性地清理边缘溢色，同时保护深色轮廓线。
- **调色板选择**：在全分辨率下统计源图色彩，并在 Oklab 色彩空间中比较感知色差；重要区域权重更高，透明像素和不确定的边缘权重更低；所选颜色全部来自原图，而非凭空生成。
- **像素化转换**：先对可见剪影做 padding、对颜色做吸附，再在每个网格单元内进行投票；相近色调合并投票，透明覆盖率单独统计，以减少形状破碎和色彩噪点。
- **局部清理与面部处理**：合并颜色接近的碎点，同时保留高对比度细节；对复杂面部，助手会检查视线和表情，仅在必要时应用受约束的眼部/嘴部补丁，眉毛保持完整。作者特意说明这是助手的视觉判断，不是自动人脸检测器。
- **高效收尾**：一个概念图和一套调色板服务于所有请求的尺寸，共享解码和合并的审阅表减少重复工作，只修复实际观察到的缺陷。

项目还附带可选的 ComfyUI 导入/导出节点，以及 SKILL.md（助手工作流）和 SPEC.md（技术规范）两份文档。许可方面，代码是 GPL-3.0，但明确说明生成的图片不会因为使用本工具而变成 GPL 作品，商业使用仍取决于你对输入素材的权利和图像服务商的条款。

## HN 评论精华

这条 Show HN 帖子讨论极少（8 分，只有一条实质性评论），下面如实呈现。

唯一的评论来自 **kdeary1**，但内容相当有信息量，代表了像素美术社区对这类工具的典型态度：

他指出这类工具已经见过很多，管线几乎都一样——用生成式 AI 造图或找参考图，然后用相当基础的算法做清理、对齐网格、强制调色板。他承认 Picxel 给出的示例效果确实不错，但也直言「我看不出自己有任何会用它的场景」。

理由是核心痛点没被解决：这些工具至今无法在一个游戏里保持统一风格，尤其是在 16×16 到 32×32 这种小尺寸下。而且做一次性的单帧素材本来就很简单，itch.io 的素材页上已经充斥着大量免费资源，AI 生成的和手绘的都有。

他真正想看到的是另一件事：给定一个角色概念图和一个基础角色，能稳定生成带行走循环等动画的像素精灵表（spritesheet）。「能一致地做到这件事的工具，会非常令人印象深刻。」

截至抓取时，作者尚未在帖子中回复这条评论。讨论到此为止，没有更多可供总结的内容。
