## 文章摘要

这是博主 Pinecoder 写的一篇个人回顾，页面上特意标注"人类撰写"。他按时间顺序梳理了自己从第一次接触 ChatGPT 到如今用 Opus 5.5 写代码的每个阶段，结论是：几年前的工作方式感觉就像昨天，却又在迅速飘远。

**第一阶段：更好的 Google。** 他已经记不清第一次用 ChatGPT 是什么时候，只记得某一刻意识到它是"更好的 Google"，就像当年 Stack Overflow 兴起后，编程类搜索结果从没用变得有用。同事 Bryan 总追着问"你问过 ChatGPT 了吗"，他起初很烦，后来那就成了他的默认起点。

**第二阶段：复制粘贴生成代码。** 他开始让 ChatGPT 写不想手写的 Ruby 测试。他坦言一直讨厌写 Ruby，前五六门工作语言他都学会了热爱，但到 Ruby 已经到了极限，ChatGPT 给了他一个逃生口。

**第三阶段：Tab 补全和新领域。** 在 Cursor 里用 Tab 补全，它基本只能延续你写下的模式，他很少依赖它的"智能"。真正的变化发生在他临时接手一个 Python 计算机视觉项目时：他对这个领域一无所知，却能以"搜索"的速度把问题变成代码，在 Jupyter 里运行、修改、画图，边做边学 API 和领域知识。这是他最喜欢的阶段，那时还没有后来 Opus 模型的"话痨"毛病，ChatGPT 按他喜欢的方式只吐一行代码，有时还按他的要求附带一句挖苦。这也是他接触幻觉最多的时期，他发现幻觉很容易识别，它们恰恰出现在模型知识的边界上，提示他该自己去填补空白。

**第四阶段：智能体编程。** 起初他对 Karpathy 等人的言论感到困惑，后来慢慢转到 Claude 上用智能体提示，学会识别它的边界。他看着别人写又长又啰嗦、像愿望清单一样的提示词觉得好笑，而他自己的提示更像压缩过的指令，比如"给 Tasks.tsx 详情页加日期排序，参考某某组件和测试的写法，避免 mock"。某天他抬起头，发现提示已经不是小把戏，而是主要的工作方式，但整个代码库仍在他脑子里，每一行都审过。

**第五阶段：Opus 4.5/4.6。** 他需要描述任务的粒度和手把手引导的时间骤降，按几个月合并的 PR 来算，生产力从"略好"变成大约 3 倍。瓶颈变成了 PR 审查。他学会扫读，并更加重视使用标准库、标准组件和标准模式，因为只要代码走在"轨道"上，大部分改动就可以略过，只盯住独特的业务逻辑、涉及客户数据的部分以及数据库迁移、加密等可能不可逆的地方。机械、枯燥的部分消失了，他几乎只思考架构、迁移计划、关键业务逻辑和数据保护。

**第六阶段：Opus 5。** 每代模型都更好一点，但让他印象深的反而是成本和啰嗦。他一度厌烦 Opus，短暂换到 ChatGPT，后者在他的用例里几乎一样好、更便宜、更自主也更简洁。他不信任 OpenAI，所以只要 Anthropic 的编程模型差不多好，就愿意回去。

**第七阶段：Opus 5.5。** 他又一次感到自己被打回原点。他开始基于计划工作，但不再考虑想做的代码审查，而是考虑想做的 QA：应用能走多远，才会让回头比前进更费劲？架构决策是可逆的；不确定 UI 怎么做，就让它多做几版；有三个相似的想法，就三个都做。他让 Claude 把计划、进度和项目笔记写进笔记应用，搭建了一个统一的活动流来查看各项目中机器人的提交，还做了可以同时供人和模型使用的指标仪表盘；漏洞报告成批修复，他看燃尽图；把更多工作交给子智能体，上面再放一个总览全局的监督者。他甚至想，能不能让另一个模型去攻击设计中的漏洞，再让模型们协同加固。有一次他本想写"图片处理应在 150 毫秒内完成"，手误写成 15 毫秒，干脆看看模型能不能做到，结果做到了，他意识到需要重新评估什么是可能的。他又随手让模型探索把他的 Electron 笔记应用移植到 iPhone 原生 Swift，回车后就走开了；几小时后在手机上看新闻时，一个基本可用的应用已经通过网络安装好，等着他做 QA，只用了他 20 美元订阅五小时额度的 40%。他导入所有笔记，效果很好，对着屏幕发呆了好一会儿。

**结尾。** 一切又颠倒了。他想着未来，但活在当下；放下恐惧时，他更多感到兴奋，越快放下旧的工作方式就越有力量。代码变快了，他就设计新的指标和仪表盘来继续理解它，更认真地思考设计中最重要的部分和约束，"那是唯一值得投入注意力的地方"。旧方式的很多东西他怀念，也有很多并不怀念。

## HN 评论精华

本帖 150 分、约 130 条评论。讨论很少涉及文章具体内容，主要是对"AI 时代程序员前途"的老话题再争一轮：有人警告作者正开车冲下悬崖，有人怀念旧日的编程乐趣，也有人说早在 AI 之前编程工作就已经不好玩了。

**"他正开车冲下悬崖"。** 排名第一的 drudolph914 说，作者下次"浮出水面换气"时，会发现雇主已经用一个时薪 10 美元的大学生替换了他；他很庆幸一年前就离开了科技行业。dspillett 纠正说不会是学生：满街都是被裁的资深开发者，雇一个再配几个 AI 许可证就能顶替好几个人，等到投资方开始收回资本、好模型变贵时情况或许会变，但那样二十年后有经验的人会越来越少。bayarearefugee 更悲观：取代他的会是一个时薪 10 美元的资深开发者，"至少比饿死强"，"初级没戏、资深还有活"之后的下一步显然是资深薪资迅速下滑。vanuatu 不认同 AI 会变贵的说法：消费订阅有补贴，但 API 定价利润可观，单位智能成本在快速下降；zzzeek 补充说中国的开放权重模型已经够用，OpenAI 或 Anthropic 发生什么都不影响"我有没有智能体可用"。ToucanLoucan 说确实有很多公司这么干，结果频频因为长达一周的宕机和糟糕的工程实践上 HN 首页；他的雇主卖的是实打实的产品，对用 AI 裁工程师毫无兴趣。spicyusername 则反问为什么大家总说这是作者的个人选择：这是整个行业正在发生的事，"要么现在用这些工具、以后找不到工作，要么现在就找不到工作"。

**"幸好它们永远需要我按回车"。** ryandvm 说他最喜欢这类文章的一点，是作者们总对下一阶段浑然不觉：模型的推理能力以惊人速度增长，"但幸好它们永远需要我坐在这里按回车键"。sublinear 不满大家一次次重复同样的争论而不讨论文章本身；coldpie 顺手推荐了自己维护的屏蔽 HN 上 AI 文章的浏览器扩展。mock-possum 认为需要的不是按回车的人，而是开头决定做什么、结尾判断是否完成的人，至少在一段时间内专业知识在这两端仍是巨大资产；saulpw 觉得这句话说得很好。scotty79 则说按回车恰恰是他最讨厌的部分：他仍然觉得自己是"从无到有"之间的瓶颈。uludag 担心最好的结局是坐上流水线椅子，工资降到熟练工人水平；vanuatu 则认为恰恰相反，"代码猴子"式的工作会消失，未来要求更多业务、产品方向和人际关系能力，"我们都会成为指挥智能体公司的迷你 CEO"。jplusequalt 反驳说代码正在商品化，就像如今人类吃的食物比以往多，但从事食物生产的人比例远低于 150 年前；sandcat_ 认为这个类比不成立，人的饭量有限，而对软件的需求几乎没有上限。

**旧日的乐趣。** science4sail 说他入行是因为享受编程这种脑力锻炼，现在有趣的部分被自动化了，只剩下对齐利益相关方、拍管理层马屁、盯着绩效周期这些他以前勉强忍受的事；他希望能撑到提前退休，再去给开源做贡献。whstl 说他的转折点在 10 到 15 年前：行业被"兄弟程序员"占据，20 人的团队产出和 2 人一样，设计师、产品经理、拿了 Scrum Master 证书的人都想对程序员发号施令，人人都在模仿谷歌和 Spotify，每个决定都要开会；"现在只需要一两个人就能做产品"，这在 2000 到 2016 年本来就是他的日常。hax0ron3 说早在 AI 之前，职业编程就已经把乐趣榨干了，一张接一张的工单、一个接一个的会议；AI 反而让它"稍微没那么无趣"，让他的职业倦怠更可以忍受。Grombobulous 说他属于"工作只是手段"的那类人，公司又不要求 2 到 3 倍的产出，于是他在上班时间学会了一门新乐器，重温了《上古卷轴：晨风》，还每天去健身，只是不知道这种日子能持续多久。maerF0x0 则提供了反例：他入行是为了造东西，编程只是必经步骤，他真正喜欢的是想点子、琢磨用户体验和出错时的处理。

**AI 代码的质量。** dsego 说他回头看生成的代码，常常发现大量糟糕选择：Claude 从不做减法，只会往上堆代码，还会把一个微小的例外记成铁律、让后续代码都遵循它自创的规则；让它审查十遍，它总能找到点什么，却意识不到自己把渲染代码塞进了核心逻辑。rlander 深有同感：开发者知道什么时候该停下来问人，Claude 只会一条路走到黑。IshKebab 说只要你要求，Claude 是会做减法的，他经常让它列出可以简化和"你不会需要它"的地方并排序。

**开源维护者的苦恼。** 202508042147 说当开源维护者现在很糟，不是因为没人感谢（他有企业赞助），而是公开 PR 里塞满了"想帮忙"的人提交的大段文字和代码，两天后还来催为什么没合并。tpoacher 建议在贡献指南里写明不接受风格、冗长度、泛化程度和信噪比"类似 AI 生成"的提交；但他说项目不归他所有，上级全面押注 AI，不会同意。Brian_K_White 讲了一个更荒诞的例子：他在别人的项目里手写了三步正确的操作说明，对方让 Claude 加进文档，Claude 把它改成了一段乱七八糟的东西，项目作者直接合了进去，"就算你不用 AI，别人也会把 AI 用在你身上"。

**作者描述的那些"魔法时刻"。** aaronbrethorst 说文中 15 毫秒的段落让他很有共鸣：他维护的开源 iOS 应用的 GitHub Actions CI 要跑一小时左右，他告诉 Claude Code"让 CI 在 10 分钟内通过，别再问我问题，我要去睡觉了"，Claude Code 祝他睡个好觉，第二天早上问题已经解决。GrinningFool 提醒他看看到底改了什么，比如省掉测试也能加快 CI，他贴出了 PR 链接；他还说用的是每月 200 美元的 Max 20x 套餐，一晚上只花了大约 5% 到 6% 的额度。chrisra 说他发现自己再也不会卡住了，"用头撞墙"已经不在他的词汇表里；mythrwy 说他学到的很多东西恰恰来自撞墙，未来也许不需要了，但那是很好的锻炼；throwaway_1016 说用大模型完成了很多以前不敢碰的大项目，但学到的东西几乎立刻就忘了；m_fayer 说他比周围人更耐挫、更能坚持，正是这样练出来的，这个行业失去这些特质会很可惜。
