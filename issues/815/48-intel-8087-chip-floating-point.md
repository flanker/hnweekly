## 文章摘要

这是 Ken Shirriff 逆向分析 Intel 8087 浮点协处理器系列的最新一篇。8087 于 1980 年推出，让 IBM PC 等机器的浮点运算快了一大截：与在 8086 上用软件模拟相比，加法快了将近 100 倍，复杂运算的提速还要更多。8087 虽然支持正切、平方根、对数等高级运算，本文只看最基础的加法和减法，追到微码和电路层面，讲清楚它们具体怎么实现，包括对无穷大等特殊值的大量特殊处理。

**芯片上的相关部件。** 作者用凿子撬开芯片封装，在显微镜下拍了高清晶圆照片。芯片中央的大块矩形是微码 ROM，存放着控制整颗芯片的 1648 条微指令；下半部分是数据通路，负责对 80 位数值做浮点计算。和加减法相关的部件有：位于中央的整数加法器，一个输入来自 B 寄存器，另一个来自临时寄存器或栈寄存器，结果写入和寄存器（sum register）；移位器，能把数值一次左移或右移任意位数，所以占了很大面积；前导零电路，统计数值左侧有多少个零位或零字节，以便移位消除；还有指数转换器，用来检测上溢和下溢。

**浮点加减的基本原理。** 浮点数一般表示为「符号 × 有效数 × 2 的指数次方」，有效数形如 1.bbb…。两个数相加前必须先对齐二进制小数点，也就是把指数较小的那个右移；相加后再规格化结果。以 13.5+3.5 为例：第二个数右移两位对齐，相加后最高位溢出一位，于是结果右移一位，指数加一。减法更麻烦一些：结果可能为正、为负或为零，也可能比操作数小好几个数量级。比如 8−7.5，相减后要左移四位才能规格化，指数减四。结果为负时要取有效数的绝对值并翻转符号；结果为零时无法规格化，只能按情况返回 +0 或 −0。

**硬件细节。** 8087 内部统一使用 80 位的「临时实数」（temporary real）格式：1 位符号、15 位指数（偏置值 16383）、64 位有效数，能表示超过 10 的 4932 次方的数。8 个寄存器组织成栈，每个寄存器附带一个标签：零、有效、特殊（无穷、NaN、非规格化数）或空，空标签可以用来检测栈上溢和下溢。内部还有临时寄存器 tmpA、tmpB 和 tmpC，其中 tmpC 是 68 位，多出一位防溢出，另外三位是用于舍入的 guard、round、sticky 位。每条 16 位微指令完成一个底层操作。整数加法器有 69 位，一次加法要两条微指令：第一条指定参数和选项（减法时对第二个参数取反），第二条把结果从和寄存器搬到目的地；移位操作同样分两步。

**加减法微码。** 加、减、乘、除共用从地址 #0001 开始的公共微码，先把两个参数装进 tmpA 和 tmpB，再通过一个微子程序调用分派到具体运算。作者顺带吐槽了一个设计上的「黑科技」：跳转地址表里的 0 号目标由 ROM 中的特殊电路实现，会根据乘、除或加减跳到三个不同地址。加减法子程序从 #0232 开始：先处理 0±0，再比较两个指数，必要时交换参数，让指数较大的数排在前面，并用「符号锁存器」记录结果的符号。接着调用 CREATE_DENORM 把 tmpB 右移对齐。关键一步在 #0250：判断底层到底是无符号加法还是无符号减法。例如 2+3 和 −2−3 都是数值相加，而 −2+3 和 3−2 都是数值相减，所以加法指令可能做的是减法，反之亦然。芯片用专门电路计算「tmpA 符号 ⊕ tmpB 符号 ⊕ 操作类型」，直接得出结论。

- **无符号加法路径**：对齐、相加，最高位有进位就右移一位，并让一个专门的 2 位指数调整计数器 expAdj 加一。之后设置符号；如果目标是 64 位或 32 位格式，调用 ADJUST_PRECISION 截断精度（舍入可能再次引起指数变化）；最后由原指数、调整量算出最终指数，并送入指数转换器检查是否溢出。
- **无符号减法路径**：做 tmpA−tmpB，结果为负就取反并翻转符号。结果为零时还要看三个舍入位，并决定是 +0 还是 −0。两个符号相反的零相加抵消（例如 +0 + −0）时，向下舍入模式得到 −0，其他舍入模式得到 +0。规格化时，前导零统计分两步：先按字节统计并移位，再统计剩下的 0 到 7 个零位。

**公共微码中的特殊情况。** 这段公共微码被作者称为「意大利面条代码」，连续 18 个条件分支处理各种特殊值。当某个参数为空或带特殊标签时，SPECIAL_TMPS 子程序设置标志：参数为空（通常是栈下溢）就返回 NaN；参数是非规格化数则继续运算。有 8 条路径返回 NaN，包括 0÷0、∞×0、∞÷∞ 等。8087 还有两种无穷模式：「仿射闭包」区分 +∞ 和 −∞，此时 ∞+∞ 合法而 ∞−∞ 得 NaN；官方推荐的「射影闭包」中无穷不分正负，所以任何无穷与无穷的运算都没有意义。有 8 条路径返回无穷：乘除可以翻转无穷的符号，加减则只沿用无穷那个参数的符号。

**前导零电路。** 64 位前导零检测如果一步完成，每个输出位都依赖全部 64 个输入，电路会很复杂。8087 选择了慢一点但简单得多的办法：用两个 8 输入检测器分两遍处理，先去零字节，再去零位。作者画出了把 0 到 7 个前导零编码成 3 位二进制的门级电路，其中中间那一位需要多一层逻辑。

**结论。** 加减法这种看似平常的操作背后有许多精巧的算法和电路。8087 对正负零、正负无穷和 NaN 的处理规则后来演变成今天通用的 IEEE-754 标准。不过 8087 在特殊情况上做得有点过头，射影无穷、unnormal（非正规数）、伪零等特性因为得不偿失而没有进入标准；到了 80387，Intel 也去掉了 unnormal 和伪零。作者感谢「Opcode Collective」的 Smartest Blob 和 Gloriouscow，他们把 ROM 图像转换成了微码数据。文末还有一份 AI 声明：尽管文中出现了破折号，写作没有使用 AI，只有提取微码时用了机器学习算法给 ROM 单元分类。脚注里提到，8087 背后的浮点专家 William Kahan 曾写文解释设计动机，其中谈到 0 的 0 次方，他认为业界共识正趋向「对任何 x，包括 0、∞ 和 NaN，x 的 0 次方都等于 1」。

## HN 评论精华

本帖 126 分、35 条评论，规模不大但质量很高，有不少当年亲历者的回忆，主要话题是 80 位扩展精度的功过。

**作者互动。** 作者 kens（Ken Shirriff）在评论区问下一篇该写 8087 的哪部分。n923263 指出文中「1.1（二进制）× 2^8 = 304」应为 384，kens 说自己「大概读那个数时没戴眼镜」，原文已改正。bonzini 问 FSTSW AX 这类指令怎么写入 CPU 的 AX 寄存器，rep_lodsb 解释这条指令到 80287 才出现：286 能识别不同类别的 x87 操作码，由 CPU 微码从保留的 I/O 端口读出状态字放进 AX；386 集成得更紧，部分 FPU 状态直接复制在 CPU 内部。chj 想了解超越函数指令，bonzini 指出作者已写过 CORDIC 求正切的文章。

**80 位精度：远见还是负担？** D 语言作者 WalterBright 说他一直觉得 8087 很酷，却从没真正流行起来。他曾打电话请微软不要在 Win64 的上下文切换中丢掉 x87 寄存器，对方让步了；他还纳闷数值计算圈为什么无视 80 位浮点，自己在 D 中支持 80 位运算时受到很多反对。jcranmer 回应：8087 是 IEEE 754 的主要源头，谈不上被无视；问题在于 x87 只在一种带显式整数位的怪异 80 位类型上正常工作，很难逐位精确地模拟常见的 32 位和 64 位运算，再加上很多编译器把寄存器溢出到内存时只存 32 或 64 位，程序的数值结果实际上带有随机性；80 位也不利于向量化，在 SIMD 时代被甩在后面。在他看来，x87 是「最后一个还没退场的前 IEEE 754 浮点系统」。WalterBright 回了一句：「我的编译器是正确处理的。」

**Cray、Java 与确定性。** downut 回忆，8087 问世时顶级的数值计算机是 Cray，Seymour Cray 在硅片上对低位的处理相当「离经叛道」。他曾担心长时间计算的精度，结果在世界前几名的超算上干了五年，从未对任何要紧的计算产生实际影响。他认为 8087 用 80 位做运算，实际精度优于非扩展格式，「有 Kahan 背书就够了」。rofluto 补充，Sun 为了让 JVM 在不同机器上结果完全一致，把中间运算精度砍到 64 或 32 位，惹恼了 Kahan。downut 认为这是个蠢决定；rofluto 反驳说「这话一听就是没写过多精度库的人说的」，幸好 Sun 的思路赢了，如今所有处理器的 float64 四则运算都是完全确定的，四倍精度、多精度、区间算术库才能可靠移植。曾在 Weitek 工作的 librasteve 说，他的第一份工作就是用 C 写 IEEE 754 测试套件，Sun 工程师的 paranoia 测试经常在他们的 FPU 设计里挑出毛病，后来 Sun 自己做了 SPARC FPU，Weitek 就垮了。他认为 IEEE 754 是他见过考虑得最周全、最精妙的文档，但「认为 FPU 数学是确定性的人，都没真正接触过这些怪兽的电路设计」。

**当年的使用体验。** downut 至今保存着读研时买的 8087，可惜搬家时掉了一根针脚。indymike 15 岁时在第一份开发工作里用带 80287 的 AT 兼容机给会计重算 Lotus 1-2-3 模型，后来以此为理由申请到了 386+387，一个模型的计算时间从 5 分钟降到 40 秒左右，他一直不理解为什么有人舍不得多花几百美元买协处理器。jakzurr 说当年朋友们都不愿为 8087 掏钱，他自己攒钱买了 486DX。WalterBright 还讲了个段子：Turbo C 生成的代码不算好，但小程序跑得飞快，原来是运行时库全用手写汇编实现，正好让基准测试程序占了大便宜。

**其他。** dsign 感慨 1980 年的芯片就能做 80 位浮点，而 46 年后的微控制器很多连 FPU 都没有，倒是配了「安全岛」和能联系外星人的无线电；shakna 提到 Espressif 一度想把 FPU 做成付费选项，后来在 ESP32-S3 上又加了回来。kar1181 感谢 Ken 多年来的文章和视频，称他是「一片 AI 垃圾内容之海中的灯塔」。
