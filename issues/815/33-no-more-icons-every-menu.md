## 文章摘要

这是 Jim Nielsen 的一篇短博文，是他 2025 年 12 月那篇《菜单里到处都是图标，救命》的后续。那篇旧文当时在 HN 上拿到 846 分、333 条评论，批评的是 macOS 26 Tahoe 的一项改动：系统和苹果自家应用的菜单里，几乎每个菜单项前面都加上了图标。

**旧文的论点回顾。** Nielsen 并不反对菜单图标本身，他反对的是"每个菜单项默认都配一个图标"的做法。他以 Google Sheets 为例，说这种做法会让设计师抱着"这里空着，得塞个图标"的心态，而不是认真考虑"在这里加个图标、让用户多一层识别和理解的负担，到底是帮了忙还是添了乱"。前者只是套模板，后者需要针对每个场景用心思考。他原本总拿 macOS 当反例，说苹果的系统菜单一直克制，直到 Tahoe 上线。他逐个截图分析 Safari、Mail 的菜单：有的分组有图标并缩进，有的没有；"设置"有图标，同组的"隐私报告"却没有；"显示"菜单里勾选标记和图标叠在一起，对齐乱成一团，他看不出任何取舍逻辑。他也承认有好的例子，比如 Finder 里窗口平铺的菜单，用图形示意窗口会被摆到哪里，比读"左上角""上下排列"等文字直观得多。他还指出，苹果 1992、2005、2020 年的人机界面指南（HIG）里都有专门章节讲"在菜单中使用符号"，Tahoe 等于违背了自家的指南。

**这次的新消息。** 在 macOS 27 Golden Gate 中，这种默认给每个菜单项加图标的做法被撤销了。John Gruber 早在 6 月 WWDC 期间就撰文报道，称这是他整个 WWDC 最喜欢的消息；Nikita Prokopov 贴出了前后对比截图。更关键的是，苹果更新后的 HIG 明确要求"谨慎且有目的地使用菜单项图标"：图标适合用于最常用的操作和关键功能、文件系统位置、已连接设备、旋转或翻转图像这类视觉概念，以及文件夹、文档等用户内容；找不到能清楚表达含义的图标时，就不要放。新版 HIG 甚至把 Tahoe 那种做法当成反面示例。

**作者的感想。** Nielsen 说，过去他反对这种做法时有一个有力论据："苹果都不这么干。"Tahoe 一出，这个论据没了。而现在他手里有了更强的论据："苹果试过给所有菜单加图标，连他们自己都退回去了。"苹果设计了它、发布了它、和它共处了一年，然后公开修改了自己的指南，这比单纯说"苹果不这么干"更有说服力。他用一句话收尾：不做一件从没做过的事是一回事，不再做一件做过的事，那叫经验；在实践中学习，正是生活的本质。

## HN 评论精华

本帖 474 分、约 275 条评论。讨论很快超出菜单图标本身，扩展为对苹果设计水准下滑、UI 设计行业知识断代、UX 与视觉设计之分的长篇反思，也有不少人跑题聊起菲茨定律、HyperCard 和 Windows Phone。

**该不该为苹果"认错"喝彩？** 置顶的 netsharc 认为作者的结论太宽容：真正有说服力的是一开始就不要发布这么粗糙的东西。happytoexplain 反驳说在软件行业，犯错后改正已经难得，苹果的决定无论好坏都是经过考虑的；socalgal2 认为"苹果的一切都深思熟虑"只是公关神话，那里的人和去年在 Meta、Google 工作的是同一批人。kevin_thibedeau 翻出 2008 年版 HIG 第 170 页，原文就写着"只为能显著增加价值的菜单项加图标，不要每项都加，图标太多会显得杂乱难读"，"苹果 20 年前就知道这不好，只是没读自己的文档"。Wowfunhappy 问苹果为什么不去问问当初写指南的人，难道 15 年后还要拿用户再做一次实验。epihelix 吐槽文章结尾那几句排比"太像 LLM 写的"，tpmoney 认为 LLM 只是放大了人类本来常用的修辞套路。

**矛头指向 Alan Dye。** ludwigschubert、hn_throwaway_99 等人引用 Gruber 的观点，把 Tahoe、Liquid Glass 等一系列设计失误归咎于前设计主管 Alan Dye，认为他重视平面设计而非人机界面设计，他跳槽去 Meta 后苹果才开始纠正；publlus_enigma 补充 Dye 出身时尚和包装设计。diskzero 列出 Bas Ording、Mike Matas、Greg Christie 等苹果早年的 UX 高手，认为乔布斯去世后那种基因已经流失。

**设计行业的知识断代。** cosmic_cheese 的长评获得大量认同：老一代 UI 设计师退场，年轻一代没有接上知识传承，还在不问缘由的情况下推倒前人的规则，违背了"切斯特顿的篱笆"原则；加上 Dribbble 这类只奖励漂亮效果图的平台，导致视觉压倒可用性。jerf 补充说，很多人根本不知道那里有篱笆。quacked 最痛恨的是可点击元素不再有视觉提示，以及紧凑的目录树被圆角卡片取代；bunderbunder、Maxion 抱怨大片留白对需要放大页面的视力障碍者是灾难。linguae 引用 Alan Kay"计算机是一种不重视历史的流行文化"，说很多从业者没听过 Don Norman、Tognazzini、Susan Kare。paulmooreparks 说他曾向有学历的 UI 设计师提起菲茨定律，对方像听到古苏美尔语。在 Nielsen Norman Group 工作的 TonyAlicea10 认为"设计"一词被滥用，平面设计师为了吃饭转行做 UX，但乐趣仍在视觉上，不如把这行叫"应用认知与行为心理学"。有 30 年经验的 vitaflo 则怪罪设计教育：过去设计课的核心是学会给予和接受批评，如今很多人出自只教 Figma 的速成班，讨论设计时"凭感觉"代替了批判性思考。montagg 区分了作为系统学科的 UX 设计与作为审美学科的 UI 美术，groundzeros2015 说在大厂之外从没见过不是平面设计师出身的 UX 设计师。

**图标到底有没有用。** noduerme 以 30 年 UI 设计经验给出更细致的看法：有效的图标不一定是天生"象形"的，而是用户逐渐熟悉的，任意图标也能通过有意识的长期使用获得含义，但必须服从整体的品牌与图标体系，否则比没用还糟；有快捷键时他宁可显示快捷键，"装饰与好设计是对立的"。Andrew_nenakhov 回忆一项 2000 年前后的研究（他认为是 McDougall 等人关于图标具体性、复杂度和辨识度的论文），把 Word 的图标换成红方块、蓝圆圈之类的随机形状，用户熟悉后找起来一样快；他也批评把各式图标统一塞进圆形底板的潮流抹杀了辨识度。Waterluvian 认为只有当同一功能在别处只以图标出现时，菜单里才需要图标。OnlineTux 说给邮箱标签加了 emoji 后扫视快了很多。BurningFrog 说当年许多人误以为 Mac 成功靠的是图标，于是到处加图标，真正的原则写在苹果的界面指南里，却没人读。多位用户（trash_cat、jmaw）笑话新版 HIG 用星期几配图标（周五爆米花、周六派对）做反例。

**其他平台与吐槽。** VyseofArcadia 想象了 Tahoe 菜单诞生的会议："数据显示带图标的菜单项点击更多，那就全加上，指标好看能拿奖金。"Kuraj 希望 KDE 也学学，它要么全有图标、要么全关。farmin 呼吁 Windows 11 的右键菜单也该改回来，galad87 说它在新电脑上都要两秒才弹出。quibono 指出作者博客右上角的汉堡菜单里每项都带图标，centuryfall 也问了同样的问题，tkdb 调侃"那些是经过深思熟虑的图标"。Grombobulous 认为这件事被过度渲染，tpmoney 回应它之所以引发众怒，是因为这是一个无法用"人们只是不喜欢改变"来搪塞、所有人都同意不好的具体例子。dchest 说他最喜欢 Xcode 界面编辑器里菜单项图片旁边那个"仅限 macOS 26"的复选框。
