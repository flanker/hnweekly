## 文章摘要

2026 年 10 月 21 日，Anthropic 以研究预览形式发布了 Claude Duet，这是一个独立的 App，让 Claude 以「主动型智能体」的身份工作：它会主动告诉你什么事需要关注，接手你交代的任务，在你离开时继续干活，并在代你行动之前征求你的同意。官方说它面向「事情多到跟不过来」的专业人士和小企业主。本文结合产品页和同日发布的公告《Introducing Claude Duet》整理。

**它做什么。** Duet 基于 Claude Opus 5.5，官方强调它的核心价值是「判断力」：决定什么需要你、什么可以等、什么时候要先问你。每天早上它会发一份简报，汇总已连接应用里最重要的事项；白天它会盯着这些应用，只在真正需要你时才发消息。你也可以把各种大小的任务交给它，小到约会议，大到用几十个工具搭仪表盘、做财务或销售预测、做原型、搭建网页应用。产品页的示例是一位连锁咖啡店老板 Maya 的一天：晨报里列出招聘 offer 即将过期、大客户续约被改了条款、芝加哥新店的卫生许可需要她批准 640 美元费用、A 轮融资的路演材料已用三季度数据重做，以及周末送错单的退款已起草好；随后 Duet 帮她补齐数据室文件、调研投资人背景、拆分过于拥挤的幻灯片，并在发送邮件前请她确认，最后还按她的要求做了一个每天早上 5:30 自动刷新的经营健康看板。

**如何工作。** Duet 沿用你 Claude 账户里的记忆、技能和已连接应用，几乎不需要额外设置。所有交流都在一个持续的对话线程里进行，可以打字也可以语音。它拥有一台带独立浏览器的云端虚拟机，所以不需要你的电脑或手机开着。它每隔几个小时检查一次已连接的账户，官方解释说持续检查会太快耗尽套餐额度。它可以使用 Claude Marketplace 中 6000 多个连接器和插件，比如在 Gmail 和 Slack 里找出漏回的消息、在 QuickBooks 或 Stripe 中找未付发票并起草催款、在 Gusto 准备工资单、通过 Docusign 发合同、在 Shopify 管理店铺等。它还能通过 Stripe 的 Link 钱包或 Shopify 的 Shop Pay 代为购物，用虚拟卡付款而不暴露真实卡号；之后还会支持在你允许下用 1Password 中保存的登录信息登录网站。

**安全设计。** 发送消息、付款、签署文件或删除任何东西之前，Duet 都会展示它要做的事并等待批准；交易证券、在账户间转账等操作即使你批准也不允许。凭证处理沿用 Claude Managed Agents 的设计，它从不直接看到密码或登录令牌；动作审批使用与 Claude Code 相同的自动模式分类器；防提示注入的能力来自浏览器使用方面的研究；系统经过红队和外部公司的渗透测试，并纳入公开漏洞赏金计划。此外还专门配备了一个新的分类器和安全系统提示，拦截分享信用卡号、政府证件等最高敏感级别信息的请求，健康、个人财务等敏感信息只有在你明确指示时才会发出。

**谁在用、怎么收费。** 公告提到 Claude Code 负责人 Boris Cherny 会在散步时跟 Duet 过一遍脑子里的待办；几位早期测试的小企业主也分享了体验，比如一位房产经纪人说它主动发现日历上一场看房日期写错了，一位有 110 名员工的餐饮店主用它处理会计、客服和营销，「不用再开 100 个标签页」。目前 Duet 仅对美国的 Pro 和 Max 订阅用户开放等候名单，Team 和企业版暂不包括；它与 Claude 其他功能共享套餐额度，后台检查也计入用量。提供 iOS 和 Android 独立 App，电脑上可在 claude.ai 使用。官方坦承它可能误读对话、误判紧急程度，也可能漏掉两次检查之间到达的事情；个人事务（如订票）不如工作场景强，也还不能向你展示它的浏览器画面。

## HN 评论精华

本帖获得 551 分、约 500 条评论，是本周最热闹的讨论之一，但大量篇幅偏离了产品本身：一位用户分享用同类助理在日本买房的长线引发了关于 AI 代劳、隐私和「这条评论是不是 AI 写的」的激烈争论，另一条长线则是抱怨 HN 首页被 AI 新闻淹没。

**又一个同质化产品。** 多位评论者指出，这是一个月内各大实验室推出的第四个「常驻个人助理」，与 OpenAI 的 Dot、Meta 的 Muse、xAI 的 Grok Bot 正面竞争。devindotcom 调侃「Dot、Bot、Duet 一个月内全发布，这种行业步调一致简直编不出来」，dgellow 感叹「号称革命性的技术，前沿实验室却只能做出一模一样的托管智能体」。ZeroCool2u 认为它没有明显差异化，而且被锁定在单一模型家族；LUmBULtERA 和 0gs 则认为 Opus 5.5 本身就是足够的差异化，毕竟 OpenClaw 最初就是为了把 Claude 放进一个能用 Telegram 召唤的常驻智能体。alberth 批评这是「按组织架构发布产品」，应该直接内置在 Claude 里。minimaxir 注意到 Duet 没有采用拟人化的萌宠式品牌包装，用途因此更清晰、更偏职业场景。

**到底有什么用。** charlesabarnes、howunfortunate、jstummbillig 都在问这类助理实际用来做什么。回答五花八门：remich 说同类产品 Instinct 发现他订错了一周的餐厅，帮他省了取消费；UFOFlyer 用 Muse 的浏览器能力绕过难用的订餐网站；aliasxneo 说 Dot 发现了一个月初随手开的 AWS 账户已产生 50 多美元账单；dgunay 把它当作「更有弹性的提醒服务」。torben-friis 认为它们主要面向经理和创业者，nunez 和 rozap 则嘲讽官方演示的用户本来就有行政助理，「能用来干什么？呃……找投资人要钱」。willchis 拿演示里「我已向县政府申请 11 月 6 日或 7 日检查」开玩笑：祝 Claude 好运，接下来八个月记得隔天就去催一次。trallnag、ExtremisAndy 坦言自己的生活太简单，用不上常驻助理。

**和自己搭的方案比。** loveparade 和 Gareth321 认为 Claude Code 的定时任务加一个状态文件就能做到同样的事，Gareth321 还指出 Duet 每隔几小时才轮询一次，紧急邮件可能在两次检查之间漏掉；user43928 反驳这种体验作为个人助理显然很糟，stnmtn 则联想到 HN 上那条著名的「Dropbox 不就是 rsync 吗」评论。sksksk、juanre 分享了用开源 Hermes 智能体加本地或廉价模型的自建方案，juanre 提醒不要把管理生活外包给某一家公司，关键是要能随时替换底层模型。ttul 推测这类不要求实时响应的任务可以放进低优先级批处理，对实验室是高利润业务；robgough 引用一段预览视频说 Duet 虽然聪明但很慢。

**信任与安全。** roarcher 质疑让 LLM 接入 1Password 是否是「最糟糕的主意」；doctoboggan 解释正确的做法是智能体只能请求填充密码，秘密本身由密码管理器处理，juicypeach 揶揄「如果做得正确」在 Claude 的话术里承担了太多分量。pants2、tylergetsay 分享了自己给凭证加租期、在工具调用输出里遮蔽密码的做法。jesse_dot_id 说 LLM 无法揣测哪些行动他会批准，所以永远不会用这类东西；threecheese、YmFzZTY0ZGFkZHk 等人则对把个人数据全盘交给一家公司感到不安。

**一条跑偏的长线。** intenex 说自己用 OpenAI 的 Dot 一个月里买了车，还在完全不会日语的情况下推进在京都买房，并贴出了 150 页的聊天记录作为证据，还提到他让 Astra 审核报税单，发现了会计师的错误。这引出了几个方向的争论：monitron 认为以前去适应当地语言和文化本身就是准备移居的必要过程；有人质疑他的回复都是 AI 写的，随后演变成一场「AI 检测器靠不靠谱」的口水战；他又提到自己运行着一个有独立「生活」、会给研究人员发邮件的 Claude 智能体，被质疑在浪费研究者时间，他则贴出邮件证明对方知情。cjonas、sahn44 也说用模型复核报税单确实找到过真实错误。

**其他吐槽。** TheAceOfHearts 抱怨明明已登录 Claude，加入等候名单却还要手动填一遍表，引发一串关于「每天合并三万个 PR 却顾不上 UX」的调侃，也有人（helsinkiandrew、mcbishop）干脆让 Claude 帮自己填了表。krzyk 不满又是仅限美国。herodoturtle 引出的「HN 首页全是 AI」话题下，paxy 总结得好：首页 100% 是 AI，评论 100% 反 AI。jasonjmcghee 建议帖子链接应改为公告文章，发帖人 kuberwastaken 表示同意但已无法修改。
