## 文章摘要

作者 Simon Edwardsson（V7 联合创始人）去年看到 Google 的 Genie 3 之后，开始设想一种未来：应用不再由代码写成，而是"学"出来的，模型根据用户输入预测下一帧画面。他没有 GPU 集群和海量视频数据，于是把野心缩小到终端：终端只是一张字符网格，训练数据可以靠在真实 shell 里跑命令无限生成，而且预训练语言模型本来就知道 `ls`、`cat` 大概该输出什么。他真正想验证的是：模型能否维持一个**前后一致的世界**，而不只是吐出看起来像样的终端输出。

成品叫 WorldTUI，基于 Qwen2.5-Coder-0.5B 微调，背后没有任何 shell 或文件系统。每一次按键输入模型，模型预测屏幕如何变化。它能建文件、跑 vim 和 tmux、玩贪吃蛇，通常还能记住几条命令之前写进文件的内容。浏览器版只有 208MB，可以在本地通过 WebGPU 运行；作者建议输入 `pythoon` 体会它并不是真 shell（它会照样启动 Python）。

**表示方式。** 普通 LLM 只会在末尾追加文本，但终端不一样：vim 里按一下 Esc 就有效果，`clear` 会把光标送回左上角。所以模型预测的是"屏幕的增量更新"。每个会话以一个快照开头（屏幕尺寸、内容、光标位置），之后每次按键以真实终端发送的原始字节输入，模型输出"改写哪些行的哪些列、光标停在哪"。没有按键时输入一个带时长的 WAIT token，贪吃蛇就是这样自己动起来的。为了避免滚屏时重写整屏（约 3000 个 token），作者加了 COPY 操作，把旧屏的某一行复制过来，滚屏成本从每行约 96 个 token 降到 3 个。整个词表只有 333 个 token：256 个字节 token、64 个行 token 和少量特殊操作，解码时用语法约束保证每次输出都是合法的屏幕更新。

**训练数据。** 现成的 asciinema 录像没有精确的按键与屏幕对齐，他就自己在 Docker 里生成：随机用户名、主机名、提示符风格和终端尺寸，按虚构身份（开发者、运维等）生成目录和文件，每个会话挑 6 到 24 项活动（改文件、vim、python、tmux 等），追踪状态以保证打开的文件确实存在，模拟人类逐键输入、Tab 补全和 1.2% 的错字率；35% 的会话从中途开始。最终共 33.6 万段会话、约 20 亿 token。

**学会修复自己的错误。** 普通监督微调学会了基本打字，但长会话里错误会滚雪球。他借鉴 DAgger 的思路：让模型自己往后预测 1 到 4 步，与真实屏幕对比，若差异不大就构造一个"修复"帧，让模型在下一次按键时把错误屏幕改回正确状态。关键限制是修复引入的词必须在之前的真实屏幕或用户输入里出现过，否则等于奖励幻觉。这样迭代三轮后，作者自建的 PresetBench 从 24/47 提升到 38/47。整个训练大约用了 RTX 4090 上 75 个 GPU 小时。在 106 条命令的 ShellBench 上，WorldTUI 得 80 分，而直接提示的 Qwen2.5-Coder-0.5B 和 Qwen3-0.6B 分别是 52 和 60；文件回读正确 9/13，对方只有 2/13 和 3/13。不过它离可靠的文件系统还很远，比如 `echo green >> colors` 之后 `cat colors` 经常看不到追加的那行。

**提速。** 逐 token 生成时打字约 38ms 一键，但 `vim`、`man`、`clear` 这类整屏重绘在 4090 上要 12 秒。他意识到同一帧里各行基本互不依赖，于是每行作为一个 batch 元素并行生成，共享历史和 KV 缓存，解码步数从所有行之和（最多 3000 步）降到最长一行（约 100 步），大帧 p95 延迟从 6.7 秒降到 0.87 秒。但行与行无法协调，会出现 vim 从第 3 行开始显示、贪吃蛇一次冒出好几个食物的问题。解决办法是"自己给自己做投机解码"：并行行的结果作为草稿，再由同一个模型顺序验证，保留到第一个分歧点为止。在 M4 Mac 浏览器里，单字符约 60ms，`man test` 从 2.5 秒降到 0.9 秒。

**瘦身与蒸馏的意外发现。** Qwen 的 15 万词表嵌入就占 1.36 亿参数，只保留 333 个 token 后模型从 4.94 亿降到约 3.6 亿参数，再做 int4 量化得到 208MB，推理用自写的 JavaScript + WGSL 计算着色器。他还尝试蒸馏成更少层数，发现记忆高度依赖某些特定层：只删掉第 7 层而不重训，下一 token 准确率从 99.3% 只掉到 98.9%，但精确记忆回读从 64/64 直接跌到 0/64。保留偶数层的学生模型输出看起来正常，却只有一半概率选对写入的值，相当于瞎猜；保留第 1、7、15、22 层的 16 层学生则记忆全对，但 ShellBench 掉到 65。"学生模型可能看起来没问题，却悄悄失去了记忆"，最终他放弃了蒸馏。

**效果与局限。** 他第一次在 tmux 里用 vim 改文件、保存，再切到另一个窗口 `cat` 出更新后的内容时，感觉自己像弗兰肯斯坦博士。tmux 多窗格、环境变量展开都能大致工作；Python REPL 简单运算通常正确，复杂一点就像 GPT-3 时代的幻觉。嵌套目录有时会让它迷路，Firefox 上比 Chrome 慢约 20 倍，原因不明。作者坦言这东西"没什么用"，但对一个跑在浏览器标签页里的 3.6 亿参数模型来说，表现远超预期；最让他感兴趣的是它在不实现任何底层规则的情况下维持了一个大致一致的世界。下一步他想用成千上万个随机生成、各有规则的应用来训练，看模型能否预测从未见过的应用的行为。权重稍后会公开。

## HN 评论精华

本帖 566 分、约 175 条评论，整体气氛轻松，大家一边试玩找 bug，一边回忆 ChatGPT 早期"假装终端"的玩法，讨论最多的延伸用途是蜜罐，也有人借题探讨"模型生成 UI"是不是未来。

**作者答疑。** 作者 simedw 在评论区回答了几个技术问题：窗口尺寸写在上下文开头（`SCREEN_START 32 96`），训练用了三种分辨率，中间尺寸大概也能用；平时只有按键才会触发下一"帧"，WAIT token 由运行器决定何时发送，用来表示时间流逝。sandworm101 问它只看屏幕的话，能否认出 `********` 是密码，作者说训练时输入的是真实字符、渲染的是星号，所以模型应该能区分。被问到基座模型起什么作用时，他说基座已经掌握语言，所以 man 页面读起来通顺，还懂 Python，`1+5` 之类能算对；他也试过从零训练，效果弱得多。他还提到更大的模型记忆也更好。有人问能否真的在磁盘上创建文件，答案是不能，一切只存在于模型上下文里。

**ChatGPT 终端的回忆。** prodigycorp、ponyous、air7、dpflan 等人都想起 2022 年那篇《在 ChatGPT 里构建虚拟机》，作者在相关工作一节也引用了它。billypilgrim 说那是他记忆里的重要时刻，玩了几个小时，模型甚至记得他之前改过文件；那时编程甚至不是 LLM 的主要用途。hydrolox 回忆当时还能"安装" lynx 浏览一个平行宇宙的互联网，后来加了护栏就不行了。psandor 和 soulofmischief 提到微软的 Quake II 模拟模型和 Google Genie，指出这类东西统称为"世界模型"。gavinray 引用了"神经计算机"的研究论文：整个 UI 都由用户输入到预测输出的循环生成，理论上完美的神经计算机无法与真计算机区分。

**拿来做蜜罐。** 这是被提得最多的点子，Meleagris、gdevenyi、thinkski、wolvoleo、n0on3 等都提了。作者觉得很酷但扩展起来可能贵。root_axis 质疑它比普通蜜罐好在哪，Meleagris 解释：高交互蜜罐的目的是从攻击者身上套出尽量多信息，用模型可以设定情报目标、动态引导攻击者暴露能力和基础设施，过去这需要人工设计场景。wmchen 指出 Cowrie 蜜罐已经支持 LLM 后端。harperlee 建议放一个智能体进去，看它会不会在一个"不可能完成的任务"里抓狂，busssard 笑称这是一个它们真正黑不进去的沙箱。

**这是 UI 的未来吗？** thorum 遗憾地认为这大概就是 UI 的未来，只要本地模型够快。skohan 反驳：一个程序在 CPU 上用几 KB 内存几毫秒就能做完的事，为何要用 GPU、几 GB 显存跑一个非确定性过程？他也承认人们早就让 2nm 芯片的大部分时间花在跑 JavaScript 上了。hnlmorg 说原因和桌面应用都变成 Chromium 实例一样：开发便宜、上线快。mrweasel 指出非确定性是硬伤，终端命令里不想要随机性；claykkari 则说如果"随机"指的是能处理意外用法，比如 `ps "哪些进程拖慢了电脑？"`，那他倒挺想要。ilaksh 写了长评认为模型正在"吃掉"外部框架，大模型为了少写 bug 可能已经在权重里隐式学会了执行预测，这种方式在速度和自包含上有潜在优势。

**真实试玩体验。** donperignon 说实际效果远不如演示动图：它坚称他要建的 `test1` 目录已存在，又允许 `mkdier test2` 却 `ls` 不到。IncRnd 发现 `LS`、`els`、`lsl` 等都会执行 ls。mattstir 发现模型对 `$_` 很困惑，`cd $_` 进了 foo 而不是 foo/bar/baz。LoganDark 贴出 `cat /etc/nginx/nginx.conf` 输出了一屏 `cactus=true`，配一句"很准确"。gitowiec 抱怨 Firefox 上每次按键都像慢动作，作者怀疑没走对 Firefox 的 WebGPU 路径。4ggr0 借本期 PHP 漏洞事件调侃：这个幻觉终端里的 PHP 打补丁了吗？claykkari 回答它可能幻觉出一个从没有过那些漏洞的 PHP。

**相关项目与延伸想法。** rowbin 介绍了自己 6 月做的 vibeSH：不训练，直接用前沿大模型加长提示词模拟整台计算机，每轮重绘整屏，交互式程序像"1996 年的调制解调器上跑 SSH"，但一致性更好；还能用 `@ai` 前缀让"导演"把机器改成 1996 年闹鬼的 Solaris。他认为双方最难的是同一个问题：作者是小模型丢状态，他是上下文窗口装满后机器"失忆"，他干脆把"这台机器记性不好"设成了设定，而作者的 DAgger 方案是真正的修复。nico 分享了"有损 git"，用神经网络训练来存代码、checkout 时再生成出来，InsideOutSanta 调侃提交进去的代码 checkout 出来 bug 可能更少。qurren 提出了一个实用方向：训练一个 1000 万到 5000 万参数、延迟低于 10ms 的小模型，做"零延迟 SSH"，本地即时预测按键效果，等服务器返回后再校正；pinusc 提醒 mosh 已经有即时回显，dTal 说那就是 mosh 加上这个。saagarjha 指出 Anthropic 已经在对齐评估中使用这类模型。OtherShrezzing 认为这个项目是思考"预测智能输出的模型和智能本身有什么区别"的绝佳实验品，引出了一串关于图灵测试和中文房间的讨论。
