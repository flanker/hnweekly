## 文章摘要

Mozilla 推出了面向企业的付费产品 Firefox Enterprise（Firefox 企业版），口号是「要做一款与众不同的企业浏览器，得靠一家与众不同的科技公司」，强调把客户的隐私、独立性和控制权放在首位。产品页没有公开价格，主要入口是「申请演示」和「联系销售」。

**定位：浏览器是企业风险的新前线。** Mozilla 的论点是，现代工作都在浏览器里完成，工作、数据、身份和 AI 在这里交汇，因此浏览器是治理与合规的关键一层，而许多企业的技术栈还没有完全覆盖这一层。Firefox 企业版主打三点：

- **主权（Sovereignty）**：可以部署在企业自己的基础设施里（本地部署），由企业自己定义并审计数据、策略和管理功能放在哪里。数据、密钥、遥测和策略都留在企业的控制边界内；浏览器事件和管理员操作可以导出到 SIEM，消除安全运营中心在浏览器层的盲区；还能根据用户和设备状态动态控制访问，并接入企业 SSO。
- **控制（Control）**：内置数据防泄漏（DLP），可以按域名和用户操作设置细粒度规则，阻止敏感数据流出浏览器；已经在用 Trellix、Broadcom 等方案的企业，可以把它们的内容分析能力延伸到浏览器里。员工、外包人员和合作伙伴可以从受管设备或自带设备（BYOD）按身份分级访问内部应用，不需要 MDM、VPN 或 EDR，省去传统远程访问基础设施。产品页还提到原生隔离、扩展管控和受管安全更新，用来防范钓鱼和恶意网站，宣称「没有渲染开销，也没有 VDI 账单」。
- **韧性（Resilience）**：基于 Mozilla 独立的 Gecko 引擎，为企业增加浏览器多样性，降低对单一主流引擎的依赖，「不至于一个零日漏洞就让全公司的浏览器同时沦陷」；同时能与现有的 AI、身份、SIEM、DLP 工具集成，订阅模式也不依赖变现用户数据。

**功能清单。** 集中策略控制；外部连接控制（管控浏览器的对外调用和遥测）；原生 DLP（按域名警告或阻止敏感数据操作）；AI 控制（允许、限制或禁用 AI 工具）；SIEM 集成；用于高风险浏览场景的锁定模式（Lockdown Mode）；全组织范围的扩展白名单和黑名单；以及包含在内的专业支持服务。页面列出的合规框架包括 DORA、GDPR、NIS2、ISO 27001 和 SOC 2，并设有信任中心。解决方案栏目分为「数据控制与主权」「AI 治理」「减少 VDI 与远程浏览器隔离（RBI）」三类。

**专业支持与后续产品。** 同时推出的 Firefox Professional Support 让企业 IT 团队可以通过私有支持门户直接联系 Mozilla 专家，有明确的响应时间，并提供部署和集成指导。支持分三档：社区支持（论坛）、标准支持（邮件和门户，共享联系人，随企业版附带，也可单独付费购买）和高级支持（指定技术成功负责人、季度业务回顾，可作为升级选项购买）。支持范围覆盖 Firefox 配置、策略、部署、更新和兼容性诊断，不包括终端用户服务台、定制功能开发、托管 SOC 或托管 DLP 等。页面还预告了「即将推出」的 Thunderbird Enterprise，可以在同一个 Firefox 企业版控制台里集中管理 Thunderbird 的邮件、日历和联系人。

**「不同的商业模式」。** 页面最后总结说，只有不同的商业模式和不同的激励机制，才能做出本质上不同的企业产品：管理控制台运行在客户自己的基础设施上（更多控制）；浏览器开源，可以查看它如何处理数据（更多透明）；能与现有工具集成，没有生态锁定（更多选择）；基于 Mozilla 自己的引擎（更多韧性）。

## HN 评论精华

本帖 784 分、约 330 条评论，热度很高。评论区情绪两极：一边是「早该这么做」的支持者和熟悉企业 IT 的人，一边是对 Mozilla 积怨已久的批评者。Mozilla 新产品负责人 peterrojas 和疑似 Mozilla 工程师的 gcp 在评论区大量答疑。

**企业禁用 Firefox 的现实。** 最热一楼来自 nicoburns：这一步是必需的，很多大企业因为缺少这类管控而禁用 Firefox，他自己在工作电脑上都没法装 Firefox 做测试，这对 Firefox 伤害很大。insin 说他所在的大公司几年前以「使用率太低」为由封禁了 Firefox。miroljub 则说，比起预装中间人证书、禁用 uBlock Origin、强装 Copilot 等插件的 Firefox，他宁愿公司不装 Firefox，benhurmarcel 也说公司只允许无扩展的 Chrome 或 Edge，他另外用 Firefox 浏览是因为 IT 管不着。DoctorOW 从 IT 角度提醒：用户会想尽办法装 Chrome，没有 Chrome 就报修说「电脑坏了、上不了网」，graemep 建议干脆把图标改成 Chrome 的样子。Hugsbox 的经历正好相反：他所在的加拿大制造企业正在淘汰 Firefox，每周都有非技术用户投诉打不开 Firefox。

**这是一个大市场。** solatic 说很多人低估了这个市场：企业浏览器公司 Island 刚以 64 亿美元估值完成 4 亿美元 F 轮融资；企业既有预算也有动机，比如防止员工把敏感数据粘贴进 AI 聊天应用、让外包人员在自带设备上免 VPN 访问内网应用、屏蔽色情赌博网站。他说 Mozilla 在这场竞赛中远远落后，但潜力是真实的。peterrojas 回应说，自己在 Mozilla 负责新产品，这条产品线归他管，团队清楚还有多少工作要做，会先聚焦欧洲那些现在就能用上的企业客户，同时快速补齐功能；企业版团队特意放在新产品部门而不是 Firefox 部门，以保证它能得到足够重视。jrochkind1 觉得这些功能大多是在控制员工，令人沮丧；gcp 回答，首个市场是欧洲，那里对「监控员工」有严格的法律限制。unethical_ban 指出安全厂商正在卖各种 Chrome 的软分叉，把 DLP 和 URL 过滤从中间人设备挪到浏览器里，从而不再需要 TLS 解密；sekinfo 说这本来就该在浏览器里做，而不是靠破坏 TLS。

**和现有组策略有什么不同？** 不少人（mossTechnician、ihuman、Grimeton、VCFundedGenYer）问这和早已存在的组策略、autoconfig 或 policy-templates 有什么区别。gcp 反复解释：部署策略更省事、可以在浏览器运行时更新策略、集中的安全日志、内置 DLP、企业 VPN/代理、设备状态检查、配置文件加密、强制更新重启、有保障的支持，以及最关键的一点：可以把同步、更新、遥测等所有配套服务部署在本地，让浏览器完全不需要「回连」Mozilla。edelbitter 补充，现有策略对企业并不友好，每次更新还会冒出新的弹窗和功能邀请。gcp 还回答了 rkagerer 关于 DLP 的提问：可以按站点包含或排除规则（比如把购物网站排除在信用卡规则之外），支持警告而不是直接阻止；用本地 LLM 判断敏感内容第一版还没有，但正在开发；第三方集成用的是 Chromium 系产品同样采用的标准 SDK。s17tnet 抱怨至今没法方便地自建同步服务器，gcp 说企业版管理控制台恰好自带可以本地运行的同步服务器。

**AI 开关与对 Mozilla 的积怨。** zecg 担心「AI 控制」被列为企业版功能，意味着普通版会取消一键关闭 AI 的开关；gcp 明确说没有这种计划，driverdan 也提醒普通版的设置里已有 AI 控制选项。chrismorgan 言辞激烈：Mozilla 作为组织「已经腐烂，需要死掉，Firefox 才能活」，几年前裁掉四分之一员工后宣布的重点方向与 Firefox 毫无关系，而且做浏览器根本用不了 750 人。gcp 反驳说，浏览器引擎极其复杂，同时对性能和安全高度敏感，还要兼顾向后兼容和多平台，所以只剩 Gecko 和 WebKit/Blink 两家；「做一个浏览器」一个人就够了，把 Chromium 源码里的品牌名替换掉就行。SuperNinKenDo 批评评论区过度负面：Mozilla 是在尝试让浏览器本身产生收入，否则就只能继续依赖谷歌的钱。kevincox 指出企业用户的意义不只是收入，还有市场份额，比如 Slack 通话至今要伪装 UA 才能在 Firefox 上用，企业用户多了，网站自然会更好地支持 Firefox。

**其他。** CodesInChaos 注意到没有公开价格，InsideOutSanta 调侃：「企业级嘛，价格是 50 万，如果你不想付那么多，就是 5 万。」ksec 和 mosdl 感慨 Mozilla 晚了 20 年，当年连推动它支持 Windows 组策略都很难。projectescape 认为人们低估了 Chromium 垄断的危害，Manifest V3 就是证据；shevy-java 则引用数据说 Firefox 份额只剩 2% 到 3%，oscargrouch 补充桌面端约 5.3%，与 Safari 相当。wejick 吐槽落地页像 AI 生成的空话，「与众不同于核心，因此更强大」不知所云。rockdoe 找到了比新闻稿详细得多的企业版发布说明，gcp 贴出了 GitHub 上的 mozilla/enterprise-firefox 仓库。
