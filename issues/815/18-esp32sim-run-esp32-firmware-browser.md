## 文章摘要

esp32sim 是一个用 Rust 编写的开源 ESP32 模拟器，可以在电脑上或浏览器标签页里运行真正的 ESP32 固件，完全不需要实体硬件。作者之一 Joakim Eriksson（来自瑞典研究机构 RISE）在 Show HN 帖子里介绍说，演示最好玩的地方在于全程没有任何 ESP32 芯片参与，固件完全在模拟器中执行。项目的目标是让人们在不必总是连着实体硬件的情况下，更方便地试验、测试和模拟 ESP32 软件。他特别想听嵌入式开发者的意见：这样的模拟器还需要支持什么，你才会真正把它用于开发、测试或 CI？

与很多"功能级"模拟不同，esp32sim 走的是相当硬核的路线：它会启动芯片自带的掩膜 ROM、真实的二级引导程序和未经修改的应用程序，完整走一遍"掩膜 ROM、引导程序、FreeRTOS、你的应用"这条启动链，不需要给固件打任何补丁。它还对芯片周边的电路板进行建模，包括显示屏、触摸、LED、按键、音频、摄像头和 WiFi，所以固件可以真的在屏幕上画图、读取触摸、点亮 LED、播放声音。WiFi 部分直接运行乐鑫原版的 WiFi 库，固件会连接一个虚拟接入点，获取 DHCP、DNS 和 NTP，甚至可以访问真实网络，包括 HTTPS。

芯片支持情况：ESP32-S3（双核 Xtensa LX7）最成熟，支持多款开发板；ESP32-C3 和 ESP32-C6（RISC-V）处于草稿阶段，C6 还模拟了 802.15.4 无线电；经典款 ESP32（双核 Xtensa LX6）处于早期阶段。性能方面，S3 实现了块缓存和 JIT，运行 hello_world 比真实硬件快约 30 倍。同一个模拟器还编译成了 WebAssembly 版本供浏览器使用。为了验证准确性，S3 通过 JTAG 与真实芯片锁步对比，C3 和 C6 则比对控制台输出。

演示站点上可以直接体验多个例子：在 ESP32-S3 上运行带登录 shell 的 Linux 6.11；Atech 套件的口袋合成器和 C64 SID 音乐点唱机；480×480 的 LVGL 触摸面板；一个由小型 Transformer 模型控制鱼游动的电子鱼缸；ESP32-C6 上的 802.15.4 能量扫描器和两个运行 RPL/IPv6 的 Contiki-NG 节点；以及经典 ESP32 T-Display 上的 MicroPython。你也可以加载自己的固件。

项目采用 MIT 协议。README 说明模拟器是根据 ESP-IDF 寄存器头文件、ESP-IDF 附带的 Xtensa 核心配置、RISC-V 规范、芯片技术参考手册和观察到的固件行为编写的，QEMU 只用来确认指令语义，没有复制任何代码。项目与乐鑫官方无关。

## HN 评论精华

本帖 209 分、近 50 条评论。整体反响积极，嵌入式和物联网开发者看到了不少实际用途；但也有相当一部分讨论围绕"这是 AI 写的"以及 README 难以阅读展开。作者 joakimeriksson 在评论区逐条回复。

**和 Wokwi 有什么不同？** turbine401 第一个发问：Wokwi.com 已经做了好多年，支持大量微控制器，这个有何区别？tyromaniac 回了一句"这个是氛围编程出来的"。作者坦然回应说，如今大家都在用比纯汇编更好的工具，他最痛苦的时期是在 C64 上手敲 DATA 语句。他解释，Wokwi 是按月付费的 SaaS 模拟器，而他需要一个工具来给自己用 AI 开发 ESP32 软件，这就是他需要的工具，计划永久免费开放。他更愿意称之为"由模拟器开发者借助 Claude 开发"，一部分靠规格驱动，一部分靠"氛围"；Claude 替他读了大量规格文档，但你仍然得知道自己在做什么，他从 90 年代中期就开始写模拟器了。matthewfcarlson 说他多次尝试 Wokwi，都因为付费限制碰壁，很喜欢开源方案。the__alchemist 则反对这类"和 X 有何不同"的提问，认为它几乎可以套用到任何 Show HN 上；calmingsolitude 觉得这不是批评，而是想知道作者"为什么"要做；qup 说当一个项目可能只花了二十分钟时，很难给出有意义的"为什么"，而且到 2027 年他也不会再去四处比较现有项目，自己做可能比学别人的还快。

**README 读不下去。** dofm 说他很想试试，但 README 里那种格式混乱、括号、命令行参数和元件型号挤成一团的超长段落实在太累人，"连年轻的专家读者也会觉得疲惫"。rvz 更不客气：README 像小说一样长、格式差、每句都有 Claude 腔时，它就变成了"DONTREADME"，"连作者自己都没读过"，这也是项目质量的预兆。exe34 简短地说"这本该是个表格"。作者承认文档太长太乱，计划在 0.3.0 版本时改写，让 README"不只是给智能体读，也能给人读"，还说自己最初只是为了演示时不用随身带一堆 ESP32 设备，没想到会引起这么大关注。

**实际用途。** raminf 说很多物联网项目会先做一个"功能级"模拟器，在 BLE 或 WiFi/API 层面模拟硬件，让移动端和云端的人不必等测试硬件；有了 esp32sim，每个开发者和 CI 运行器都可以跑真实固件。作者补充说它对用 AI 智能体开发 ESP32 软件特别有用，在软件基本可用之前不必折腾硬件和反复烧录。crote 提出不同看法：外设模拟很难做到足够细致，你在克隆一个文档模糊、本身就有 bug 的黑盒，既然终究只是近似，不如在更高几层模拟 HAL，就像云应用不需要周期精确地模拟整个亚马逊云，模拟几个 REST 调用就够了。beachy 的团队正在做基于 ESP32 的高尔夫硬件产品，他认为浏览器内模拟对硬件厂商是"超能力"：可以把带像素级显示和声音的产品直接放到用户的（虚拟）手中先试后买，成本几乎为零；他们还打算做一个开源应用商店，让玩家用 AI 给设备扩展功能。ThePinion 想用它试验 Meshtastic 固件而不必担心把设备刷成砖。BHSPitMonkey 问能否用来预览 WLED 灯效，aforwardslash 指出那需要在时序层面忠实模拟 DMA 和 RMT 子系统。

**相关项目与功能请求。** mrtksn 分享了自己用氛围编程做的无人机模拟器 LiftLab，把真实 ESP32 飞控的 C 代码编译成 WebAssembly，在物理模拟中飞行，并能直接烧录到真实板子上。westurner 介绍了自己为 Meshtastic 墨水屏界面写的 SDL 模拟器，并问 QEMU 的 WASM 版本能否跑 ESP32、哪个更快。0xmaxallen 发现乐鑫官方也在做一个 esp-emulator，但源码尚未公开。noahnathan25 推荐了同样支持浏览器内模拟的 velxio.dev。功能请求方面：snakeman 问是否支持 ESP32-P4，作者说已在计划中，等拿到实物后几周内应该就能支持；djmips 问 RP2350，作者说 esp32sim 不支持，但他的另一个项目 Cooja-NG 已经有 RISC-V 和 ARM Cortex-M33，模拟它并非没有希望；noah_buddy 问 H2，eduardsik 问 ESP-NOW 和 mesh。也有 djndndeb 直接留下"AI slop"，作者回应："AI 是的，slop 嘛，取决于你怎么定义。"
