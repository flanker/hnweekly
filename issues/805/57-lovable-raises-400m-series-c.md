## 文章摘要

2026 年 8 月 12 日，AI 应用生成平台 Lovable 宣布完成 4 亿美元 C 轮融资，估值 133 亿美元。本轮由 Menlo Ventures 领投，EQT 管理的 Scaleup Europe Fund 联合领投。新进投资方阵容刻意做得很「全球」：欧洲的 Balderton Capital 和 Carmignac、拉美的 Kaszek Ventures 和 LTS Growth、亚洲的腾讯和 World Innovation Lab、美国的 Regent。老股东 Accel、Antler、CapitalG、DST Global、Evantic Capital、HubSpot Ventures 和 Salesforce Ventures 继续跟投。

官方博客把公司定位表述为「软件创造平台，让离问题最近的人拥有解决问题的能力」，并给出了一组增长数字：自 2024 年 11 月上线以来，用户创建了超过 6000 万个项目，Lovable 构建的应用每月访问量超过 9 亿次；上线第一年内产品就触达了半数财富 500 强企业的员工，不到一年后这个比例升到接近三分之二。

自 2025 年 12 月 B 轮以来的产品重心，官方总结为「帮人触达客户、管理日常运营、安全地运行软件」，具体包括：支付功能（帮用户变现）、SEO 与 AI 搜索优化工具（提升可发现性）、与 Google Workspace / Microsoft 365 / Salesforce / Stripe / ElevenLabs 的深度集成、自动与定时安全扫描、拿到 AIUC-1 认证（号称首个面向 AI agent 的安全标准）、发布控制与废弃应用清理等治理能力，以及为企业提供的专属安全页面——公开发布的 Lovable 应用现在可以带自己的信任中心。

用户调研数据显示，接近 8 成用户是在做一个希望变现的生意或副业，其中超过三分之一已经在产生收入。企业侧的案例列举了 Adidas、NVIDIA、德国电信，客户引语来自 Zendesk、Handshake、Checkr 的高管，主题基本一致：用 Lovable 自建内部工具、替换掉昂贵的现成 SaaS。几个被重点讲述的故事包括：英国的 WNTD（连续创业者 Lex Deak 用 Lovable 做的时尚发现应用，号称每月省下 2.5–3 万英镑）、巴西的 Viver de IA（54 人的 AI 教育公司用 Lovable 搭了 CRM、财务工具、官网和 AI SDR 工作流，今年营收有望达到 1 亿雷亚尔）、美国的 Nursa（产品副总裁用一个周末做出面向护理学校的企业级新产品，公司随后向 200 多名员工推广，核心平台重建速度快了 12 倍，正在退役 10 套 SaaS 系统）。

## HN 评论精华

162 分、大几百条评论，但气氛与官方博客的乐观基调形成了强烈反差。讨论主线只有一个问题：**在 Claude Code 和 Codex 已经这么强的今天，Lovable 的护城河到底是什么，133 亿估值凭什么。**

**「还有人用 Lovable 吗」**

- 全场最高的开场问题来自 **hudn33**：Lovable 在 Codex/Claude Code 之前极受欢迎，但之后感觉大部分人（包括非工程师）都转投这些工具了，Lovable 还是最快搭起一个站/应用的方式吗？

- **cute_boi** 更直白：「我们都有 codex 和 claude code 了，居然还有人用 Lovable，太疯狂了。」**hackernud3s** 给出了具体反例：他有个客户在 Lovable 里做原型然后交给他上线部署，「他在 Claude Code 里会彻底迷路」。**willnz** 说自己重度使用 Claude Code，但 Lovable 是最快拿到登录系统和数据库的方式，做真正的 MVP 很合适。

- Lovable 创始人 **antonoo** 亲自下场（明确标注了利益相关，他写了 Lovable 的第一个版本）：他的偏见观点是，从发布、自定义域名、支付、后端部署、邮件、连接任意 SaaS 工具到 git 同步，Lovable 是最省事的一站式方案，全部在浏览器里完成。

- 前 Lovable agent 团队成员 **neongreen**（已离职）提供了这条串里最有信息量的辩护：对于 Lovable 优化的那类应用（带第三方 SaaS 集成的 CRUD），多数独立开发者用 Lovable 会比用 Codex 或 Claude 更省事——如果不计成本的话，Codex 订阅确实很难打。他强调「Lovable 就是一个正常的、功能完整的 agent harness，配了一台 Linux 机器，MCP、skills、子 agent、浏览器这些常规特性都有」。他试过让 Lovable 从 nixpkgs 拿 Rust 写光线追踪器并编译到 WASM，也试过让它用汇编写个 OS 跑在 v86 里，都成了。他的关键判断是：「Lovable 的替代品不是 Codex，而是『Codex + 一个 Cloudflare 账号』。」

- **jvwww** 火力全开地反驳「Lovable 很蠢」的说法：用户群中很大一部分不是技术人员，他们要用 CC 或 Codex 然后自己去某处托管数据库、前端、后端？不可能。而且大量 Lovable 应用是内部用途、不对外公开的。「它值 133 亿吗？大概不值。但我完全理解为什么有人觉得它值。」

**护城河与「模型厂商会自己吃掉这一层」**

- **sailfast** 提出了被反复呼应的核心质疑：如果模型真的变得那么好，你就根本不需要 Lovable 了——模型公司会自己把基础设施层吃掉（Claude 直接帮你管 AWS）。「这看起来是个很浅的护城河，却往里倒了 4 亿美元。」

- **jongjong** 用一段很生动的独白反驳：人们仍然需要一个托管平台，AWS 对普通人来说太复杂了，即使有 AI 帮忙也一样。多数人看到「AWS」「IAM」「EC2」这几个字母就会跑；agent 撞上第一个「port already in use」时又跑掉一批；勇敢留下来熬了一整天解决连环问题的人，好不容易搞定了端口、nginx 反代、systemd、socket ulimit，还是看不到自己的应用——然后 Claude 说「当然啦，我们还没买域名、迁到 Cloudflare DNS、配 A 记录 CNAME 和 IPv6 的 AAAA 记录呢，还有 MX 记录、Let's Encrypt 证书、nginx 装 SSL……」

- sailfast 追问：这算是 Anthropic 通过品牌集成和连接器解决不了的 133 亿护城河吗？**satvikpendem** 认为前沿模型厂商已经在做了——Claude 有能给出在线 URL 的 artifacts，OpenAI 有 sites，「他们会垂直整合，我们不需要 Lovable」。**mateo411** 则认为 Anthropic 这么做要花大量精力，会分散他们做最好基础模型的资源，Lovable 有相当的先发优势。sailfast 最后给出一个耐人寻味的解读：「做这轮融资，成为收购标的，好让某个实验室不用自己动手。这样这笔钱就说得通了。」

- **oblio** 补了一个政治经济学角度：AWS 有每年一千多亿的理由不让「Claude 帮你管 AWS」发生。「技术人慢慢从互联网演化中学到的：政治权力 > 金钱 > 技术。」

- **nadermx** 一句话概括多数人的判断：「现在品牌就是护城河。」**echelon** 展开这个观点：不管有多少 Lovable 克隆品，所有人都知道 Lovable 这个名字；开源模型只会帮 Lovable 改善自己的利润率，让它不用再交 Anthropic 或 OpenAI 的税。但 **ZeroCool2u** 直接否定前提：「我认识的科技圈以外的人，没有一个知道 Lovable 是什么，甚至没听说过。」**dominotw** 附和：「去年也许吧，现在不了。」

**收入、盈利与烧钱**

- **bix6** 算了笔账：一年前 Lovable 有 18 万付费客户，慷慨地全按每月 50 美元的商业版算是每月 900 万、每年 1.08 亿；他们现在说 5 亿美元的年化收入（run rate），也就是一年 5 倍以上的增长。**xenospn** 泼冷水：这类无代码生意的流失率肯定爆表，第一波尝鲜过后这些收入未必留得住。**eclipticplane** 提供了一个反直觉的观点：对很多公司来说这类工具属于「影子 IT」开支，可以在没有实际使用的情况下、挂在各种个人账号/信用卡上长期长期地续费下去。**minraws** 提醒：那是 ARR，一个月的注册和短期注册都被算进这个疯狂的数字里了。

- 关于盈利，**agos** 问「他们赚钱吗」，**paxys** 答：一家三岁的初创在融 C 轮，盈利不是关注点，很长一段时间内都不会是。**sigilis** 阴阳道：「哦，所以他们是台烧钱机器，而且再融几轮、再过几年都不该在乎这件事。明白了。」**oblio** 补充：直到跑道或经济周期先结束的那一个到来为止。**TeMPOraL** 说得更冷静：他们大概率瞄准的是在那之前 IPO 或被收购变现，「如今大多数初创不是为了造出能长久存在的东西，而是从第零天起就设计好退出路径。这已经是成熟的商业模式了。」

- **popalchemist** 引用了 Lenny 播客的分析：Lovable 之所以实现盈利，靠的是超级用户——一群混杂着完全新手和资深软件工程师的人，token 消耗量是普通用户的 10 倍以上，价值主张和定价正好击中了这块市场。**enos_feedler** 尖锐回应：他有老朋友讲同一个 App 点子讲了十年，现在在 Lovable 上花掉数千美元。「这不是可持续的客户，这是妄想的人在错误的东西上花钱。他们的点子在能写代码之前不好，现在能写了还是不好。」**pluralmonad** 给出一个绝妙的类比：「招牌公司能一直做下去，因为每家新开的餐厅都想要自己的招牌。那家餐厅统计上注定倒闭，这对招牌公司反而是好事。」

**非技术人员到底能不能造软件**

- **asdev** 表态看空非技术人员做软件，认为这只是在赌模型会变好。**chao-** 给出了这条串里最细致的中间立场：这些年他见过不少「非技术」的人用电子表格 + SaaS + Zapier 拼出自己的内部工具，他们熟悉业务领域、注重细节、执着于用任何手段做出改进——AI 应用生成器确实让这类人如虎添翼。「这可能是个定义问题：这样的人算技术人员吗（因为他们重视把人的流程系统化）？还是不算（因为他们不懂软件工程最佳实践）？」他还引了一句记不清出处的话：「AI 应用生成器意味着任何人都能体验构建软件的乐趣，但同时也会体验到维护软件的乐趣。」

- **JamesSwift** 的立场是「对更多人能造软件看多，对普罗大众能造软件看空」：AI 的残酷真相是它要求你像开发者一样思考，而很多人不是也不想这样思考。**gosolozero** 反驳说现在的形态就像 90 年代初建网站一样笨拙，等 AI 更好更便宜之后，一句提示词就能开发部署整个应用。JamesSwift 的回答：「我听到的是『等我们有了 AGI 就容易了』。⋯⋯我觉得你是在看着曲棍球棒曲线往无穷大外推。我们已经在逼近渐近线，线开始走平了。」

- **sonink**（自称在同一赛道创业）提供了最具体的真实用例：舞蹈学校管理 SaaS、荷兰的分类信息站、一个老派网站托管服务，全是没有技术背景的创业者做的——「没有技术背景」的意思是大多数不知道 GitHub，有些不知道 Reddit 或 LinkedIn，备份方式是把整个文件夹连续导到本地。他们过去唯一的选项是外包给开发商，起步 1 万到 5 万美元，而生意成不成还未知，所以一直在观望。现在他们每季度在平台上花 2000–5000 美元自己做。**Oras** 反问「这些以前用 Wix 或 Framer 不就行了吗」，sonink 回答这些是带多租户、数据库、支付集成的应用，分类站还有用户私信、社交分享、付费升级。**toyg** 给出了那句被顶得很高的历史观：「Lovable 实际上是『下一代 Wix』，Wix 是『下一代 WordPress』，WordPress 是『下一代 Dreamweaver』。每一代都被吹成终结一切，因为它总比上一代好，但它们服务的核心需求是同一个。」

- **killerstorm** 提供了一个反面案例：他女儿想做个静态网站发插画故事，用 Lovable 做出来的东西流程顺畅，但那根本不是静态网站——是 React 的 SPA，内容居然在 TypeScript 里，不会被索引。**jaapz** 反问「客户会在乎网站用什么技术做的吗」，**spockz** 回答：「他们不在乎技术，但他们大概挺在乎被搜索引擎收录的。」

**尖锐的批评**

- **alexashka** 亲自试用后写下最刻薄的评价：注册 Lovable、选了个网页模板，弹出一段免责声明要求他确认「remix 模板时，我同意对项目安全、合规、数据和运营负责；模板仅供教育目的，不保证开箱可用或安全」——而且**禁用了复制粘贴**，他只能手打一遍。「我无话可说，法官大人。」两分钟后他补充：「不敢相信有人往这里投了一分钱。它让那些失败的网站编辑器看起来做得深思熟虑，它让 Squarespace 看起来像个好产品。」

- **orf** 讲了个具体的技术翻车：朋友用 Lovable 做小众新闻站，用 WordPress 当无头 CMS，Lovable 造出了一个用 Cloudflare Workers 的怪物——每次页面访问都要打一次 WordPress，没有正经缓存，慢得要死，TTFB 超过 3 秒。「本质上就是 WordPress，但外面套了 10 层。」朋友既没有技术能力理解为什么这是个怪物，也不知道怎么用提示词绕出来。转到 Cursor 后用 Astro + Cloudflare Pages 两天重建，现在飞快。

- **epolanski** 抓住了一个讽刺：两年前他们还在炫耀「小即是美」——两打人加上 AI 就是增长的秘诀，没有官僚主义。24 个月后，人数膨胀到 1000 多人，产品每几个月软性转型一次，「没有任何一个基于 lovable 构建的平庸应用获得过任何关注度，至少我没听说过」。

- **mrhottakes** 的问题被很多人转述：「那些在这个平台上 vibe code 出来的、改变世界的大应用在哪儿？」**swyx** 回应说「如果你只是为了被打动才找这个，那你不太懂科技这门生意」，**agos** 反驳：「是他们的公关稿坚持说这不只是原型、是真正在生产环境干活的真应用。『那它们在哪儿』是个公平的问题。」

- **jongjong** 提供了一个有趣的实证：他在自己国家最大的招聘网站上搜「Lovable」，全国一个相关职位都找不到；换成任何其他技术栈，随便哪个大城市都能翻出好几页结果。**alchemism** 反驳：招聘广告一般不会写具体产品名，企业招的是「平面设计师」，不是「Photoshop 设计师」。

- **lbreakjai** 提供了一个被忽视的正面用例：Lovable 在他们公司取代了 Figma——产品和设计用它做可交互原型，有时直接和（潜在）客户一起做。「哪怕花几千块，只要能直接做出正确的东西，那也是零钱。」

- **GenerWork** 提出了一个 HN 式的犀利判断：「如果 Anthropic 多花点心思在 Claude Design 上，这个估值可以砍掉 75%。」**pixelready** 分析说 Claude Design 感觉像典型的「个人贡献者的热情项目，打磨到刚好能叫 beta」，如果有话语权的人愿意当它的旗手、把它推到 Claude Code 那个重要级别，它可能成为 Adobe、Lovable、Canva 市场份额的威胁——但它需要更好的直接编辑层（比如双向 Figma 同步），以及把图像生成请求智能路由到 nano-banana 级别的模型。「现在它感觉像个随时可能被砍掉的有趣概念验证。」
