## 文章摘要

Herdr 是一个面向 AI 编码智能体的终端多路复用器（terminal multiplexer），由土耳其开发者 Can Celik 一人开发。2026 年 8 月 6 日，他在项目博客上宣布 Herdr 加入 Y Combinator F26 批次，并承诺运行时部分继续保持开源。

文章以一句自白开头："四个月前我在找下一份工作，思考职业方向，思考软件工程的未来、我的业余项目、面试白板题（我到现在都不敢相信我们还在做这个）。某一刻我意识到：瓶颈是我自己。"他把这定义为一个管理与工程问题：他不想为了管理自己的智能体和自己的开发风格，去装一个新应用或学一个新工具，他想要的是贴合自己的东西。他顺手吐槽了当下的风气："你看现在每家公司都在发布自己的智能体？不，别这么干。让我的智能体接入你的产品，别再给我一个新智能体。"

关于什么是"运行时"，他的解释是：CLI 编码智能体运行在终端里，而终端一直是我们的家——编辑代码（对，还有 nvim 党）、跑服务、浏览项目、维护 CI、机器、配置。终端是根，是连接点，所以智能体需要在那里拥有一等公民级的原语。他定义的模型是：一个终端窗格属于一个智能体，一个窗格属于一个标签页，标签页属于一个项目。这些必须是持久化的——现在的智能体一跑就是几小时甚至几天。而一旦有了运行时，它们跑在哪里就不再重要，你应该能在任何地方运行并保持它们持续运行。

TUI 部分则是他每天在用的界面，也是把 Herdr 带到今天的东西。他强调 TUI 之所以永远保持一等地位，不是因为它是个 UI，而是因为它展示了 Herdr 所信奉的概念：一眼追踪所有智能体、按项目而不是按一堆智能体来划分工作、只在智能体真正需要你时才提醒你。它还有一个巨大优势——它是打包在一起的：把 Herdr 装到你的 VPS 上，ssh 进去，UI 就已经在那儿了；或者跑 `herdr --remote user@host`，它会自我安装。取决于网速，你离一个运行中的智能体只有几秒钟。他承认 TUI 从来就不该是唯一的客户端，运行时的意义正在于别人可以基于它构建，而且确实有人做了：一个 Raycast 扩展、一套带 Herdr 按钮的 Stream Deck、一个能从手机驱动整个会话的 iOS 应用——插件市场发布一个月后就有超过 500 个插件，这些全都不是他做的。

数据方面：一个单人项目做到了 25000 star 和 34 万次下载（页面上显示的实时数字是 25,976），"已经超出一个人能扛的范围"。他表示希望组建一支小团队，让运行时保持健康、稳健、快速、能轻松跑在任何地方并且更可扩展。关于许可证，他明确承诺："你现在用的这个运行时，保持免费，Apache-2.0。这也是我最近把它从 AGPL 换成 Apache 的原因：我希望所有人都能毫无障碍地自由使用 Herdr。"至于未来方向，他说需求已经显而易见：多个客户端、一台笔记本、一台跑六小时任务的 VPS、一个跑危险代码和临时智能体的沙箱——Herdr 今天已经能跑在任何地方，但这些机器彼此是断开的，它们应该是连通的。他强调不想操之过急："大家一直告诉我他们喜欢 Herdr 保持精简，这正是我想保护的。在一个多加一个功能几乎不花成本的时代，选择什么进入核心是最重要的决定。所以核心保持小，其他一切通过扩展保持可能。"

## HN 评论精华

这条讨论几乎完全没在聊 Herdr 的技术细节，而是变成了一场关于"VC 资助的开源开发者工具会不会必然烂掉"的大辩论，以及顺带的一场 AGPL 许可证战争。

**开场就是主基调。** **nlh** 说自己是 Herdr 的超级粉丝，几个月前发现它，正是自己工作流需要的东西，但对这个消息心情非常复杂："YC 意味着 VC，VC 意味着商业化，商业化意味着 enshitification（劣化）。我真希望不是这样，但太经常就是这样。"他特意补充自己整体上是 YC 的粉丝，不是在反 YC、反 VC 或反资本主义，"但涉及底层的核心开发工具时，我永远忘不了 Warp 的下场——它一开始是个多么清爽干净的终端项目，最后变成了彻头彻尾的捞钱烂摊子。" **Fervicus** 只回了三个字："不会不同的。" **an0malous** 说得更狠："这就是字面意义上的 VC 剧本，融资的全部意义就是用补贴的/免费的产品搞垮竞争对手，然后涨价、劣化。任何认为这次会不一样的人都是在骗自己。"

**YC 官方也在场。** 用户 **tomhow**（HN 管理员）回应说："不一定要这样。如果你只想拿 YC 的钱、不想要别的，保持团队精简、专注于把产品对客户做得更好，YC 的合伙人是支持的。事实上 YC 建议：如果你不需要 VC，就别拿。"**lrvick** 提供了一个务实的第三条路：他打算把 Herdr 提交进 stagex，这会给它一个完全独立的发布流程，由多方引导构建、复现并签名确定性二进制，与他们的 tmux 发布并列。"我们（stagex 团队）自然会把未来任何可能出现的公司追踪垃圾打补丁去掉，并在必要时跟随社区主导的分叉，就像我们对 terraform → opentofu 做的那样。"他还说自己的公司 100% FOSS、毫无保留，也在当前 YC 批次里，客户每周都在签，"承认这不典型，但确实可以做到"。

**"直接自己维护一个分叉"成了热门解法。** 当 **tamimio** 说"是时候找替代品了"时，**pecheny** 反问："为什么要'找'替代品？如果你是 Herdr 用户，你完全有能力给自己维护一个分叉。"面对"有能力做和有意愿及资源去做是两回事"的质疑，他给出了具体经验：当你维护一个除了自己没别的用户的个人分叉时，你只在遇到 bug 或需要新功能时才需要动它；他自己有 mosh 和 cmux 的个人分叉，每个总共大概花了一小时。（cmux 的作者 **lawrencechen** 恰好也在帖子里，特意来要了他的分叉链接。）**giodamelio** 把这个观点推到了极致，也贡献了本帖最有洞察力的一条评论：他每天用 Herdr 并维护一整叠改动，从只是个人偏好的小调整，到添加 jj workspace 支持、以及一个基于 xterm.js 的 web 视图这样的大改；而且不止这一个项目，他的很多开发工具都在堆积改动。"LLM 让对开发工具做个人修改变得如此毫不费力，以至于我现在极度抗拒使用任何非源码可见的软件。"他甚至构想了一种新的市场形态：他其实不在乎软件的许可证是什么，反正他不分享也不商用，如果有人做了很棒的软件并出售源码，他绝对会考虑。**skinfaxi** 说这完全说中了自己的想法："如果 AI 正在开启个人化工具的时代，那么关闭 harness 就与用户的需求背道而驰。"**vidarh** 补充说，他认为闭源对任何无法激进阻止用户内省的软件都将行不通，因为把智能体指向那个工具、让它复制你真正在意的功能或者做个包装，实在太容易了。

**关于 AGPL 换成 Apache 的动机，讨论非常直白。** **ValentineC** 问 AGPL 到底有什么实际问题，**rajangdavis** 一句话回答："如果人们用你的工具还被要求分享源代码，你就赚不到钱。"**koiueo** 补了句"拿不到投资人的钱"。**inigyou** 的分析更细致："如果他想赚钱，他需要卖许可证，而不是白送。为此，让免费版是 AGPL 通常是个好棋——它保证人们能用上瘾，等他们进了大公司就必须付钱才能继续用。"

这引出了一场关于 AGPL"有毒"与否的激烈争论。**tyre** 主张 copyleft 许可证对采用有毒，公司会默认回避，因为存在大量模糊不清的未知（比如你跑一个 copyleft 服务、通过 API 连接它，这算不算延伸？那个服务的源码必须公开吗？），实在不值得麻烦。**tlamponi** 给出了技术上准确的反驳：不算；一个通过网络 API 与 AGPLv3 服务通信的客户端仍是独立程序，完全不受该许可证影响；第 13 条的义务只落在运行修改版服务的人身上，而远程用户（包括 API 客户端）只获得接收该服务源码的权利。他还以自身经历佐证——他们在完全相反的前提上做了二十多年生意，Proxmox VE 及其他 AGPLv3 项目并没有遇到采用问题；极少数做额外尽调、不太习惯 FLOSS 的潜在客户会问到这一点，一封书面保证就能解决，虽然那份保证技术上毫无用处（并未额外授予任何东西），但对他们也不花什么成本。"如果 API 不构成清晰边界，AGPLv3 软件确实会像瘟疫一样蔓延到它接触或穿越的一切。如果你或你客户的律师声称并非如此，你/他们该换个真正懂软件和知识产权法的律师。"**mbreese** 则给出了现实主义的回应："你可能这么想，我也可能这么想，但真正重要的是你客户的律师怎么想。也许纯属 FUD，但 AGPL 项目在公司里确实很难获得采用，因为他们宁可回避问题也不愿冒着搞错的风险。"**jraph** 说得最直接："（A）GPL 里根本没有使用限制。任何人，包括大公司，都能用 AGPL 软件。阻止他们使用也不是重点，重点是试图保障最终用户的自由。他们只是选择回避 AGPL 软件。他们的损失。不幸的是他们还在这件事上散播 FUD，而这里很多评论者乐于替他们传播。"**croes** 的一句话总结了另一派的情绪："换句话说，不当寄生虫压力很大。多残酷的世界啊，居然不允许我只拿、只拿、只拿。"

**rvz 提出了一个逆向的、也相当有分量的问题**："认真问一句：如果 Herdr 之前是在求捐赠，你们真的会捐吗？除非另有说明，我认为你们谁都不会。所以这正是开发者不为自己的工具付费、而这些工具的开发者最终去找 VC 的原因之一。这不是作者的错，而是大多数用户（也就是开发者自己）的错，他们总想让自己的工具永远是 0 元。你必须付费并支持你使用的工具，否则 VC 会替你来做，那么当这种情况一再发生时，你就没资格抱怨。"这条评论引发了长串交锋。**bigyabai** 反驳说这是个恶意的两难："用户可以希望它被维护，却未必有钱、有用户基础或有动力去赞助主要开发者。口袋紧不是犯罪，这也正是免费开发工具兴旺而付费的凋零的原因。永远会有一个 FOSS 版本的 Herdr，而且靠着氛围编程，它很可能会保持与付费版的功能对等。"rvz 则举出 Mastodon、ffmpeg、curl、OBS、Blender 作为拥有数十上百个赞助方、且不靠 VC 的反例。**applfanboysbgon** 站在 rvz 一边："开源极端主义者伤害自己事业的程度很好笑。一切都必须'免费'，那么一切就都必须由 VC 或大厂支持，因为免费不能当饭吃，所以最终开发者只是把更多权力交到公司手里、把更少权力留给自己和其他独立开发者与小企业，然后还有脸抱怨一切都被劣化了。"**LikeAnElephant** 提供了一个具体的反证："我转用 Herdr 时特意在他们网站上找捐赠/购买按钮，哪里都找不到（至少不在显眼位置）。我很乐意为我经常用的软件捐款/订阅，但公司有责任把怎么付钱写清楚。"

**关于赛道拥挤程度，ahmadyan 提供了最有信息量的一条**（他本人也在做这个方向的产品 Agentastic.dev，并在评论里坦承）：终端多路复用器/多智能体编码这个赛道已经非常拥挤，光 YC 一家就投了 herdr、Superset、cmux、Emdash、Orca、Bullet、Conductor（Conductor 是从聊天转型到编码之前就进的 YC）等多家互相竞争的创业公司，这还没算 YC 之外的 Superlogical 和他自己的产品。他观察到一个有意思的模式：很多产品都以开源起步（他推测这是获取早期用户和建立社区的战术手段），但在早期增长阶段过去或者拿到融资之后，激励结构似乎就变了；开源本身在这个市场里并不构成产品差异化，而真正用于定位的功能（编排、云、自定义智能体、企业功能、托管基础设施等）最终往往要么闭源，要么只在托管产品中提供。他因此发问：开发者到底有多看重这个品类的开源？**hluska** 直接点破："你是在做客户调研吧？听着就像。如果是的话，为什么不干脆公开说明？我不喜欢你为此做的这个道德跳跃。如果你连自己问题的真实目的都不肯说，我凭什么信任你的产品？"**devin** 给了一句冷酷的预言："它们全都会失败，除非被收购——而那本身也是一种失败。"**miki123211** 则预测整个品类最终会被折叠进 Claude Code 和 Codex（Anthropic 已经在用 Claude Agents 尝试），以 0% 的成本和配置代价完成 80% 的工作。ahmadyan 对此回应说，以他的经验，工具的生命周期通常比模型/实验室更长——终端和 IDE 存在的时间长得多，人们会用自己偏爱的 IDE 好多年甚至几十年；"一个糟糕的周期，下一个 Opus 6 或 GPT 7 就可能扑街（想想 Llama 4 或 Gemini 的遭遇），用户很快就会换到下一个最好的东西。所以把工具做成模型无关的是合理的。"

**关于 Herdr 到底解决了什么，几条评论说得最清楚。** **exitb** 一句话点明了它相对 tmux 的核心差异："你漏掉的是状态更新。Herdr 对运行在其中的智能体应用模式识别来判断状态，所以你能一眼看到所有智能体线程的更新。"**bitmasher9** 补充说，跑便宜快速的模型时状态更新不算什么，一旦你开始提出要 5 分钟以上的请求，它就变得很重要。**SkyArrow** 列出了三条相对于终端分屏的好处：浮现出等待进一步输入的智能体；让你快速跳到这些智能体；SSH 会话持久化（他在公司用一台高配开发机）。**kkapelon** 面对"为什么需要这种工具"的追问给出了完整回答：内置子智能体假设你只用一个 AI 智能体，而有些人用多个，因此按定义就需要独立的终端/进程，即便用同一个智能体，有时也存在不同的安全边界（想想同时服务多个客户的顾问）；当同时打开的终端数超过 5 到 7 个时，他不愿意逐个点开查看哪个需要注意；此外 Herdr 一键创建工作树（worktree）并提供可视化的树/子节点层级，是最初吸引他去看这个项目的杀手级功能。"是的，技术上你用一堆终端加自定义脚本也能做到同样的事。但这就跟'Dropbox 凭什么卖得出去，你用 cvs/ftp 就能做同样的事'是同一个问题。"

**dgunay** 分享了他自己用 tmux 拼出来的方案：他用胶带把一堆功能粘到 tmux 上（会话启动、实时智能体状态等），能用，但确实像胶带；智能体状态列靠的是从终端标题（很多 harness 会把实时状态放在标题里）或 `tmux capture-pane` 得来的启发式规则，其余字段来自 gh CLI 或 beads，从分支名推断。"我不确定 tmux 项目想不想原生支持这些，所以目前 Herdr 看起来是最好的开放且可分叉的选项之一。"

**最后是一条关于文风的吐槽，出人意料地引起了广泛共鸣。** **Taek** 说："这个标题快要了我的命。'运行时保持开源'（The runtime stays open）这句话又重又抓眼球，它是我在首页上唯一能盯着看的东西。这就是那种让我讨厌和 LLM 一起工作的写作——它太擅长垄断我的注意力，让我很难聚焦到页面上其他任何字词上。"**joegibbs** 补充了一个鉴定标准："'这个名词，动词。'（The noun verbs.）这种句式实在太 Claude 了。别的模型不干这事。我认为这是 Claude 写作最大的破绽。"**yoyohello13** 说 Herdr 首页更是"AI 味浓到头疼"。而 **ernsheong** 的观察点出了整场讨论的荒诞之处："讽刺的是这么多人在骂 YC，而我们字面意义上就身处他们的论坛里。"

也有不少纯粹的祝贺：**tyleo** 说"老实讲我一点都不介意。我太爱这个工具了，我愿意付钱。VC 资金能让东西变烂，但也能让东西变好。希望是后者。"**kristjansson** 的祝贺最有分量："作为一个相对新的 Herdr 用户，最吸引我的是这个工具表现出的正交性。它站在一边，以几种界限清晰的方式与下属程序交互，并且只在用户希望的程度上集成它们。关键是，'不要集成，就把我程序的终端输出显示给我'是一个选项，而且是有用的选项。我欣赏当前工具里的这种克制和对用户的尊重，希望能成为你在其上建立的、价值观同样一致的生意的付费客户。"
